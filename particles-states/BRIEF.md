# BRIEF：粒子与物态（particles-states）· 初中化学/物理交叉（开线页）

## 定位
- slug `particles-states`，stage junior。category：本站注册表现无 chemistry 分类——**注册时先在 `pages.config.js` 的 `KNOWLEDGE_CATEGORIES` 新增 `chemistry`（化学 / Chemistry），再给本条目挂该分类**（SPEC 规定新增分类必须先注册、不得在条目里临时发明；注册动作由上线方执行，构建者不要动 pages.config.js）。本页是全站化学线的源头页（接后续原子结构、质量守恒、分子与原子各页），同时与物理线交叉（温度、动能的微观图景）。
- 受众：初中生 + 家长。前置：无站内前置页要求，页面内自足交代（知道冰、水、水蒸气是同一种东西的三种样子即可）。
- 核心直觉一句话：**固、液、气不是三种东西，而是同一群粒子的三种队形——固体时粒子排好队原地抖，液体时贴身滑动、队形散了但还挨着，气体时满屋乱飞、彼此离得远远的；加热，就是让粒子闹得更凶**。
- 已知：一块冰、一杯水、一壶水蒸气长什么样；「热」「冷」的生活经验。唯一新问题：把它们放大到看不见的尺度，里面的粒子到底在干什么，加热又改变了什么？

## 模型假设与失配（本页专节，构建与文案都必须遵守）
本页粒子运动是**真模拟**（不是预录动画、不是示意摆拍）：每个粒子带位置与速度逐帧积分，粒子间做简化碰撞。但模型是教学简化版，以下假设与失配必须在构建报告中复述、并在页面终章「这页的模型边界」一处如实交代（口径照 SPEC 清晰度第 8 条：模型失配必须明说）：
- **二维**：粒子是平面上的等大圆盘，不是三维空间里的分子；队形、间距只在二维成立。
- **碰撞是示意**：粒子间与粒子—器壁用弹性碰撞的简化处理（等质量交换法向速度分量一类），不算真实分子间作用力曲线。固体/液体的「挨着」靠短程约束（近邻弹簧式拉回 / 黏滞范围）近似，不是真实的分子间引力势。
- **温度读数是示意标尺，不是真实标定**：读数由模拟内粒子的**平均速率实算**再映射到一条 0–120 的示意刻度（映射函数构建时定死并写进报告），只保证单调、定性正确（越热读数越高、读数与粒子实际闹腾程度同源），**不冒充**真实摄氏温度下微观速率的精确对应；页面文案只说「温度（示意）」口径，不出现「某 °C 时分子速率恰为多少」的断言。温度与粒子平均动能的严格定量关系（∝T 的统计力学口径）本页不展开，只到定性：**温度越高，粒子平均动得越凶**。
- **粒子数与性能上限**：总粒子数固定一档（建议 90–120，构建时以 390 宽真机口径帧率不掉为准定死并写进报告），全程守恒、不增不减（见判定口径）。帧内只做粒子级 O(N) 近邻简化（网格分桶即可），不做逐像素场计算。
- **物态切换是模型事件**：熔点/沸点在示意刻度上是设定值；「熔化时继续加热、温度读数却停住」是把加热功率按设定分流到「拆队形」呈现的定性规律（真实规律本身成立：熔化吸热、温度不变），不是从模拟里自发涌现的——文案与报告都不许说成涌现。

## 步骤（每步五必填项：已知 / 唯一问题 / 输入与求量 / 控件操作与预期观察 / 结论适用条件）
0. **先看清一群粒子（固体）**：已知冰是硬的、形状固定；唯一问题：放大到粒子尺度，一块「固体」里面的粒子在干什么？输入：粒子群初始态（整齐排队、彼此挨着）；求量：粒子的运动方式（动还是不动、怎么动）。控件：播放/暂停；粒子在各自位置附近**原地抖动**（真模拟，不是静止贴图——暂停时停在当前帧、播放时抖动肉眼可见），可点一个粒子高亮跟踪，看它始终回不到也离不开自己的「座位」。预期观察：固体不是死物，粒子一直在抖，只是被队形困在原地。结论：固体 = 粒子排成队形、原地振动；形状固定是因为队形固定。适用：本页粒子模型口径（见上节）。
1. **加热 = 闹得更凶**：已知第 0 步的原地抖；唯一问题：加热改变了粒子的什么？输入：温度滑杆（唯一的热源控件）；求量：粒子抖动的剧烈程度与温度读数的关系。控件：拖温度滑杆升温——同一批固体粒子抖动幅度/速率肉眼可见地变大（现象可见性：读数之外必须看得见变凶，禁止只变数字）；读数行给「温度（示意）」与由粒子速度实算的「平均闹腾程度」示意值，两者同源（见判定口径）。降温拖回去，抖动随之变弱、可逆。预期观察：温度不是粒子之外的东西，温度高就是粒子平均动得凶。结论（定性、带条件）：**温度越高，粒子的平均动能越大**——本页只到这句定性口径，不给精确公式。适用：同一批粒子、未发生物态变化时。
2. **熔化：队形散了**：已知升温后抖得更凶；唯一问题：再热下去，固体为什么会「化」？输入：继续升温越过熔点（示意刻度设定值）；求量：队形与粒子间距的变化、温度读数的走势。控件：继续拖滑杆越过熔点：粒子抖到挣脱座位、开始贴身滑动、整齐队形散掉、间距略变大——变成液体（仍挤在一起、能流动、贴着容器底）。**关键现象必须可见**：越过熔点后有一段「继续加滑杆、温度读数停住不涨」的平台段（加热的能量先花在拆队形上），滑杆行程走完平台才恢复升温；粒子一个没少（计数读数在位）。预期观察：熔化不是粒子变了，是队形没了。结论：熔化 = 队形瓦解、粒子能互相滑动；熔化过程吸热而温度不变。适用：本页模型设定口径（平台是设定分流，见失配节）；现实中晶体熔化同规律。
3. **液体与蒸发：表面有人逃逸**：已知液体粒子贴身滑动；唯一问题：一杯水不烧也会慢慢变干，粒子去哪了？输入：液体态（温度低于沸点）；求量：逃逸粒子的来源与去向。控件：动画继续——液面处动得最凶的少数粒子偶尔挣脱、飞到液面上方的空间里（蒸发只发生在表面、任何温度下都有，文案点明）；读数给「液里粒子数 / 空中粒子数 / 总数」三数，**总数恒定**；可选小控件「盖上盖子」开关：盖上后逃逸粒子撞盖返回、空中数涨到一定程度就涨停（蒸发与返回达成平衡的定性一瞥即可，不展开「饱和」术语也可一句带过）。预期观察：水变干不是消失，是粒子搬到了空气里。结论：蒸发 = 表面动得最凶的粒子逃逸；逃逸带走能量——蒸发致冷一句点明（湿手吹风更凉的生活回收）。适用：开放表面；盖盖子时净蒸发趋停。
4. **沸腾成气、降温回收（液化）**：已知蒸发是表面事件；唯一问题：烧开时水里到处冒泡、整壶变气，和蒸发差在哪？降温又会怎样？输入：液体继续升温到沸点（示意设定值）；求量：全体粒子的队形与间距。控件：滑杆推过沸点——粒子全员挣脱彼此、满容器乱飞、间距拉大成气体（沸腾是全体事件、发生在液体各处，与第 3 步表面蒸发当场对照一句）；然后**把滑杆拖回降温**：同一批粒子慢下来、先聚回液体（液化，文案点名）、再排回队形成固体——全程同一批粒子、计数守恒，一轮循环走完。预期观察：气体粒子和固体时是同一批，只是队形与间距天差地别。结论：固液气是同批粒子的三种队形，物态变化可逆、粒子本身不变（这是物理变化与化学变化的分界一句埋线，接后续分子与原子页）。适用：本页模型口径。
5. **自测 + 终章**：自测（判定借页面实测/读数，不凭记忆口答）：①熔化平台段里滑杆还在加热，温度读数为什么不涨（能量先花在拆队形上）；②蒸发和沸腾的区别（表面少数逃逸 vs 全体挣脱，点回第 3/4 步对照）；③判断题「水变成水蒸气，是因为粒子变大了」（错：粒子没变，变的是间距与队形——可切到任意态点计数与单粒子跟踪验证）；④气体降温变回液体的过程叫什么（液化）。终章三卡（同一群粒子三种队形 / 加热就是闹得更凶、温度是平均动能的定性读数 / 物态变化粒子不变、可逆循环）+「模型边界」一小段（照失配节如实写：二维、碰撞示意、温度为示意标尺）+ 互链区：温度与热量是下一条线的后续页（未建，**纯文本埋线不挂链**）；站内速度概念页 velocity-vt 讲的是宏观速度-时间图，与本页粒子速率只一句文字提及「快慢的读法在速度页有系统讲法」——落点不贴切则**只作纯文本、不挂链**（构建者查 CONCEPT-MAP 后定，报告里说明取舍）。

## 硬性规范（照 UI-I18N-SPEC.md 与 WORKFLOW.md）
- 双语 #langToggle / knowledge-lang、键集占位符一致；页头/骨架/深色主题照 fractions 与 pythagoras。
- 四件套文件：particles-states/{index.html, app.js, i18n.js, style.css} + BRIEF.md 副本。不要动 pages.config.js 与 CONCEPT-MAP.md，不要动其他页。
- **真模拟硬要求**：粒子位置/速度由模拟逐帧推进（随机热运动 + 简化碰撞），物态形态（队形、间距、逃逸）必须从模拟状态长出来，不许用三张静态示意图切换冒充物态变化；滑杆改变的是模拟的热运动强度（模型参数），不是换图——文案与报告须写明控件改的是模型假设层。
- **判定口径**：
  - 温度同源：温度示意读数只能由模拟内粒子平均速率实算映射得到，不许直接拿滑杆位置当读数；断言自查——固定滑杆待模拟稳定后，读数与粒子平均速率的映射值一致（容差内），且升温/降温两方向单调跟随。
  - 粒子数守恒断言：任意步、任意态、任意滑杆位置，液里 + 空中（ + 盖盖时盖下空间内）粒子数 = 总数 N，构建自查须在固/液/气/蒸发中/液化后五个时点各断言一次。
  - 状态判定与读数模板同源：页面显示的物态名（固/液/气）由模拟量（平均间距/逃逸占比一类纯函数）判定，不许按滑杆区间写死文案；判定纯函数与三数读数在自查里对账。
  - 现象可见性（SPEC 交互硬要求）：升温变凶、熔化散队形、平台段读数停住、蒸发逃逸、液化聚回，每项都要肉眼可见，不许只体现在数字上；平台段必须呈现「滑杆在动、读数不动」的对照。
- 状态一致性：拖滑杆往返跨熔点/沸点多次 × 盖盖开关 × 答题、切语言 × 各步状态；粒子高亮跟踪切换状态后进出干净；重置回到第 0 步固体初态且计数归位。
- 390 性能口径：粒子数取构建定死的一档（见失配节），390 宽下动画流畅（自查以帧率抽测或单帧耗时记录入报告）、零横向溢出；console 零错误。
