## How “mixed” is a group? {#step0 h2=s0t}

::: strings
nav0: 0 Impurity
:::

Step 0 · Impurity {#s0k .step-kicker i18n=text}

This step answers: how can one number measure how mixed up a group is? Imagine 40 points, each belonging to one of two classes (circle or square). **Impurity** is 0 when everything is one class and largest when the classes are split half and half. Two common measures: **entropy** H = −Σp·log₂p (unit: bits, p being each class’s share; the background is in [[entropy#step3|Entropy · binary entropy and twenty questions]]) and **Gini impurity** G = 1 − Σp² (for two classes this is 2p(1−p)). Drag “number of squares”: how does the dot grid change and how do the points on the two curves move? Find where each curve peaks and why both are 0 at the ends. {#s0e .explain}

::: html step0-1

s0kL: Number of squares (out of 40 points)
s0reset: Reset
:::

Both curves peak at p = 0.5 (entropy 1 bit, Gini 0.5) and are 0 at p = 0 or 1 (only one class left). {#s0term .term i18n=text}

## Which cut separates the two classes best? {#step1 h2=s1t}

::: strings
nav1: 1 Where to cut
:::

Step 1 · Where to cut {#s1k .step-kicker i18n=text}

This step answers: if we cut along one feature (x or y below a threshold), what makes a cut good? The data are 80 artificial points (about 8% of the labels are deliberately flipped to mimic noise). After the cut, the disorder (entropy) of each side is averaged, weighted by the number of points; this is the **entropy after the cut**. **Information gain** = entropy before the cut − entropy after it (unit: bits; bigger is better, and 0 means the cut did not help at all). Pick a feature, then drag the threshold: as the white line moves, how does the orange dot on the curve below move? The white dot marks the threshold with the largest gain. The readout lists the class counts on both sides. {#s1e .explain}

cv1: Scatter, cut line and gain curve
s1tL: Threshold
s1reset: Reset
:::

The gain is computed on just these 80 points; with so little data the best threshold wobbles with the sample. {#s1term .term i18n=text}

## How does a tree grow, one cut after another? {#step2 h2=s2t}

::: strings
nav2: 2 Growing a tree
:::

Step 2 · Growing a tree {#s2k .step-kicker i18n=text}

This step answers: if we keep cutting every region that was produced, how does the tree grow step by step? The rule is simple: at each step choose, among all regions, the cut with the largest information gain weighted by the region’s share of the points (**greedy**: look only at what is best right now, never go back). Drag “number of cuts” (or press “Auto grow”): the upper picture is the partition of the points (white line = cut, background = the region’s majority class, red ring = a point this tree gets wrong); the lower picture is the tree, each circle a region with the orange wedge showing the share of squares. Watch: the first few cuts separate the big blocks and the misclassified points drop fast; later cuts just pick off individual points. {#s2e .explain}

::: html step2-1

s2reset: Reset to 0 cuts
:::

Leaf = a region that is not cut any further; its prediction is the majority class inside. Accuracy is measured on the training set only and says nothing about new data. {#s2term .term i18n=text}

## Is a deeper tree always better? {#step3 h2=s3t}

::: strings

Step 3 · How deep {#s3k .step-kicker i18n=text}

This step answers: does growing the tree deeper also help on data it has not seen? The tree size is limited by the **maximum depth** (the most cuts from the root to any leaf), and another 600 points (generated by the true rule with no noise) play the role of “new data”. The orange line is training accuracy, the cyan line is accuracy on new data. Drag “maximum depth” with the noise fixed: as depth grows the orange line approaches 100% while the cyan line rises and then falls; then set “label noise” to 0 and see how the relation between the two lines changes. The same effect with polynomials is in [[overfitting#step1|Overfitting · training error and test error]]. {#s3e .explain}

Accuracy = points classified correctly / all points. “New data” are 600 noise-free points from the same true rule. The conclusion holds only for this fixed data set. {#s3term .term i18n=text}

Step 4 · Using the tree {#s4k .step-kicker i18n=text}

This step answers: how does a trained tree judge a new point? Drag the query point’s x and y (the cross): the tree starts at the root and answers a chain of yes/no questions, and the leaf reached along the white path gives the class; the class shares in the leaf give a rough confidence. ## Wrap-up: separating two classes with the fewest questions {#step5 h2=s5t}

::: strings
nav5: 5 Finale
:::

Step 5 · Finale {#s5k .step-kicker i18n=text}

A decision tree turns “twenty questions” into an algorithm: measure disorder with impurity, pick the best question by information gain, grow greedily one cut at a time, and use depth to keep it from learning the noise. {#s5e .explain i18n=text}

::: html step5-1
c1t: Impurity
c1b: 0 when all one class, largest at a half-and-half split; entropy and Gini both work (step 0).
c2t: Information gain
c2b: Entropy before minus entropy after the cut (weighted by points); bigger is better (step 1).
c3t: Greedy growth
c3b: Each step takes the cut with the largest weighted gain; the first cuts matter most, later ones pick off single points (step 2).
c4t: Depth and new data
c4b: Training accuracy only rises with depth; with noise, new-data accuracy rises then falls (steps 3 and 4).
modelT: Model and limits
modelB: The data are artificial 2-D two-class points (the true rule is two rectangles, the training labels carry noise); every cut must be parallel to an axis; greedy growth does not guarantee the best whole tree; this page uses entropy, and Gini impurity often gives a similar tree; there is no pruning and no cross-validation. Accuracy comparisons hold only for this fixed data set.
:::
