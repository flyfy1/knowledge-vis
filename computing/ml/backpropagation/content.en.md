## How wrong is the network right now? {#step0 h2=s0t}

::: strings
nav0: 0 Forward & loss

Step 0 · Forward pass and loss {#s0k .step-kicker i18n=text}

This step answers: given two weights, how far is this tiny network’s output from the target? The network is one chain: input x = 1, multiplied by weight w1 gives a, passed through σ (the sigmoid, which squeezes any number into 0 to 1) gives h, multiplied by weight w2 gives the output ŷ. The **loss** L = ½(ŷ − 1.2)² measures the gap between the output and the target 1.2; smaller is better. Drag the two weights (or click the loss map below): watch the numbers along the chain change one by one, and whether your position lands on a bright part of the map (small loss) or a dark part (large loss). {#s0e .explain}

## Nudge one weight: how much does the loss change? {#step1 h2=s1t}

::: strings
nav1: 1 Nudge and see
:::

Step 1 · Nudge and see {#s1k .step-kicker i18n=text}

This step answers: without calculus, how can we measure how much blame one weight carries? Add a tiny amount ε to that weight, see how much the loss changes, and divide by ε to get the **slope** (roughly how much the loss changes per unit increase of the weight). The curve is the loss when only the chosen weight moves and the other is fixed; the orange secant joins the original position to the nudged one (red dot), and the dashed white line is the exact tangent (computed by backpropagation in the next step). Pick a weight and drag ε from 1 toward 10^-5: how does the orange line approach the white dashed one? Then drag “position” to try another starting point. {#s1e .explain}

::: html step1-1
s1pL: Position of the nudged weight
s1b1: Nudge w1
s1b2: Nudge w2
cv1: Loss curve, secant and tangent
s1eL: Nudge size ε (log scale)

:::

ε = size of the nudge; secant = the line through two points, slope = (L(w+ε) − L(w))/ε; as ε → 0 the secant becomes the tangent. Every weight needs its own nudge, which gets too expensive with many parameters: exactly the problem backpropagation solves. {#s1term .term i18n=text}

## How can one backward sweep give every weight’s share of blame? {#step2 h2=s2t}

::: strings
nav2: 2 Backward ledger
:::

Step 2 · The backward ledger {#s2k .step-kicker i18n=text}

This step answers: instead of nudging weights one at a time, can we start at the loss and multiply backwards to get every weight’s slope in one pass? The **chain rule**: L depends on ŷ and ŷ depends on w2, so dL/dw2 = (dL/dŷ)·(dŷ/dw2). The ledger below runs back to front: first dL/dŷ, then multiply by each “local slope” (for ŷ = w2·h the slope is h with respect to w2 and w2 with respect to h; for h = σ(a) it is h(1−h); for a = w1·x it is x with respect to w1). Drag “how far backward we have gone” (or press “Auto demo”): each step reveals a new line of the ledger; change w1 or w2 and every number is recomputed. The readout compares the backpropagation result with the “nudge” from step 1. {#s2e .explain}

## Knowing each weight’s share, how do we shrink the loss? {#step3 h2=s3t}

::: strings
nav3: 3 Downhill
:::

Step 3 · Downhill {#s3k .step-kicker i18n=text}

This step answers: given the gradient from backpropagation, how should the weights change? The **gradient** is the vector of the loss’s slopes with respect to each weight and points where the loss grows fastest; **gradient descent** moves the weights a little the opposite way each step: w ← w − η·gradient, where η is the **learning rate** (how far each step goes). Click the loss map to choose a start (or drag the start sliders) and press “Step” or “Auto run”: the white line is the path the weights took and the curve below is the loss against step count. Try η = 0.2 (steady descent), η = 5 (bouncing across the valley without converging) and η = 8 (flying off the map); these behaviours hold only for this tiny network and this start. {#s3e .explain}

## With many layers, can the early layers still hear the error? {#step4 h2=s4t}

::: strings
nav4: 4 Deep gradients
:::

Step 4 · Deep gradients {#s4k .step-kicker i18n=text}

This step answers: when the network gets deeper, what happens to the blame (gradient) that flows back? The model is a chain of n single neurons: each layer computes a = w·(previous output), applies the activation, and the final output is compared with the target 0.5. Bar height is the gradient size of each layer’s weight (log axis; 1e-3 means one thousandth). Going backward, each layer multiplies the signal by “w × the activation’s slope”; if that factor is below 1, more layers mean a smaller gradient (a vanishing gradient). Try it: keep w = 1, switch between sigmoid, tanh and ReLU and raise the depth to 12; then drag w up to 2.0 and see whether the product shrinks or grows. {#s4e .explain}

## Wrap-up: assigning the blame in one backward sweep {#step5 h2=s5t}

::: strings
nav5: 5 Finale
:::

Step 5 · Finale {#s5k .step-kicker i18n=text}

The forward pass computes the loss, the backward pass multiplies local slopes by the chain rule to get every weight’s gradient in one sweep, and gradient descent uses them to change the weights; in a deep network the product of factors decides whether gradients vanish or grow. {#s5e .explain i18n=text}

::: html step5-1
c1t: Forward gives the loss
c1b: Numbers flow from input to output and are compared with the target to give the loss (step 0).
c2t: Nudging is expensive
c2b: Measuring each slope costs one more forward pass per weight, which is infeasible for many parameters (step 1).
c3t: Multiply backwards
c3b: The chain rule multiplies local slopes from the loss backwards and yields all gradients in one sweep (step 2).
c4t: Downhill and depth
c4b: Gradient descent walks downhill with learning rate η; in deep chains the product of factors decides whether gradients vanish or grow (steps 3 and 4).
modelT: Model and limits
modelB: Everything here is a tiny single-path network (1 input, 1 hidden unit, 1 output, no bias, no batch of data). Real networks have thousands of weights and many paths, and backpropagation sums the blame from several paths at each node. The convergence and oscillation in step 3 hold only for this loss and start; step 4 compares a single gradient and is not a training curve.
:::
