## 一颗球，一条步长生死线 {#step0 h2=s0t}

::: strings
nav0: 0 生死线
:::

第 0 步 · 钩子 {#s0k .step-kicker i18n=text}

先把世界简化到只剩一条抛物线：f(x) = x²，谷底在 x = 0。球从 x = 2 出发，规矩只有一条：**x ← x − η·f′(x)**，其中 f′(x) = 2x 是脚下的坡度，η（学习率）是你迈步的胆量。η 太小，球一步步挪蹭；η = 0.5，一步正落谷底；再大一点，球开始在两壁之间横跳着收敛；η = 1，它在 ±2 之间永远弹下去；η 再大——当场飞出去。整个深度学习调来调去的，本质上就是这根滑杆。**先把它玩到飞出去为止。** {#s0e .explain}

xₙ₊₁ = xₙ − η·2xₙ = (1 − 2η)·xₙ {#s0formula .formula i18n=text}

::: html step0-1
s0etaLab: η · 学习率（步长）
s0step: 迈一步
s0play: 连播
s0reset: 回到 x = 2
:::

为什么分区恰好卡在 0.5 和 1？因为每步 x 都被乘上 (1 − 2η)：乘子在 (−1, 1) 里就收敛，正负号决定单调还是横跳，恰好 −1 就原地打转，出了 ±1 就爆炸。一维的全部命运，一个乘子说了算。后面的每一课，都是在跟这个乘子的高维版本打交道。 {#s0hint .hint}

## 梯度永远垂直于等高线 {#step1 h2=s1t}

::: strings
nav1: 1 二维地形
:::

第 1 步 · 二维地形 {#s1k .step-kicker i18n=text}

地形升到二维：一个圆形碗 f(x, y) = ½(x² + y²)，等高线是一圈圈同心圆。**在图上任意点一下放球**，然后一步一步（或连播）看它下山。全场还画了梯度箭头场：每个采样点上的箭头指向 −∇f，也就是「此刻最陡的下坡方向」。盯住箭头和圆的交点看：箭头**处处垂直穿过等高线**，而且越靠近谷底箭头越短——坡度在变小。注意它不指向谷底的「方向情报」有多局限：梯度只告诉你脚下这一小步怎么迈最陡，谷底在哪，它一个字也不说；下山，是把无数次局部判断接成一条全局路径。 {#s1e .explain}

f(x, y) = ½(x² + y²)，∇f = (x, y)，x ← x − η·∇f(x) {#s1formula .formula i18n=text}

::: html step1-1
s1etaLab: η · 学习率
s1step: 迈一步
s1play: 连播
s1reset: 回到 (2.2, 1.6)
:::

为什么箭头必然垂直于等高线？沿等高线走，f 不变，所以梯度（f 增长最快的方向）与等高线方向点积为零——数学上是恒等式，图上是肉眼可见的直角。这个碗是「各向同性」的：哪个方向坡度都一样，球径直滚向谷底。下一站把碗拉长，麻烦就来了。 {#s1hint .hint}

## 条件数决定之字形 {#step2 h2=s2t}

::: strings
nav2: 2 峡谷
:::

第 2 步 · 峡谷 {#s2k .step-kicker i18n=text}

把碗沿一个方向拉长：f(x, y) = ½(x² + κy²)。κ 是**条件数**——地形最陡方向与最缓方向的坡度之比，也就是峡谷的「长宽比」。 <a class="fourier-link" href="../../../math/linear-algebra/eigenvectors/#step4">κ 的真身在特征值页：峡谷长宽比 = λ 之比 →</a> κ = 1 时还是圆碗；κ 拉大，碗变成一道峡谷：横穿峡谷的坡度极大、沿谷底的坡度极小。麻烦随之而来：步长 η 必须迁就最陡的方向（η < 2/λ<sub>max</sub> 才能不爆炸），于是沿谷底只能慢慢蹭；球在两壁之间横跳（之字形），蹭很久才到谷底。下面读数牌上的每个数字——步长上限、最优步长 η\*、收敛率 (κ−1)/(κ+1)——都由地形的特征值 λ 算出，轨迹是当场真迭代的，实测步数和理论步数可以当面对账。 {#s2e .explain}

f = ½xᵀAx，A = diag(1, κ)：λmin = 1，λmax = κ {#s2formula .formula i18n=text}

::: html step2-1
s2kapLab: κ · 条件数（峡谷长宽比）
s2etaLab: η · 学习率
s2etaStar: η 取最优 η\*
s2step: 迈一步
s2play: 连播

理论步数的算式：每步误差最多乘以收敛率 (κ−1)/(κ+1)，所以把误差压到 1/1000 需要约 ln(1000) / ln(1/收敛率) 步。用了 η\* 时两个方向的步乘子绝对值恰好相等，理论值和实测值会非常接近——这不是巧合，是 η\* 的定义决定的。记住特征值这个词：它在这里先以「地形长宽比」的身份露面，下一页它就是主角。 {#s2hint .hint}

## 让球滚起来：动量 {#step3 h2=s3t}

::: strings
nav3: 3 动量
:::

第 3 步 · 动量 {#s3k .step-kicker i18n=text}

还是第 2 步的峡谷、同一起点、同一个 η（两边都用 η\*），唯一的差别：右边的球有了**惯性**。普通梯度下降每步只看脚下的坡；动量法把上一步的速度留住一部分（β）：**v ← βv − η∇f(x)，x ← x + v**。在峡谷里，横跳的方向每步正负翻转、互相抵消，沿谷底的方向每步同向、不断叠加——球冲过谷底摆两下，随后贴着谷底加速滑行。把 β 拉到 0.9 以上再看：惯性过头，球在谷底两边大幅摆动，反而更慢——动量是药，过量也是毒。 {#s3e .explain}

v ← βv − η·∇f(x)，x ← x + v（β = 0 时退化为普通 GD） {#s3formula .formula i18n=text}

## 鞍点与假谷底：梯度为零 ≠ 到底了 {#step5 h2=s5t}

::: strings
nav5: 5 非凸地形
:::

第 5 步 · 非凸地形 {#s5k .step-kicker i18n=text}

真实 AI 的地形不是碗。这张 f(x, y) = (x² − 1)² + y² + 0.3x 有**两个深浅不同的谷**（左谷更深）和一个**鞍点**：鞍点处梯度同样为零，但它只在一个方向上是谷底、另一个方向上是山脊——站在鞍点上，一边是下坡、一边也是下坡（沿山脊），只有横向是上坡。「梯度为零」在非凸世界里什么都不保证。换三个起点放球，看命运如何分岔；再看起点 C：它几乎正落在鞍点上（只偏右一丝），那里 |∇f| ≈ 0.002——没有噪声时，球只能靠这点残余坡度沿山脊磨蹭：默认 η 下要 34 步才滑下山脊、最后落进较浅的右谷；打开「一点噪声」（每步给梯度加 σ = 1.0 的高斯扰动——在别处只是小抖动，在鞍点附近却比梯度本身大几百倍），11 步就被抖下山脊，还落进了更深的左谷。下方读数会把两种模式各自的「离脊步数」按同一判据记下来对账——这正是上一步 SGD 的抖动在真实训练里的另一副面孔。图上的临界点标记都是页面解 ∇f = 0 解出来、再用 Hessian 符号验过类型的，不是手画的。 {#s5e .explain}

f(x, y) = (x² − 1)² + y² + 0.3x，∇f = (4x³ − 4x + 0.3, 2y) {#s5formula .formula i18n=text}

两个谷底的深度差来自 +0.3x 这一项：它把整张地形向左轻轻倾斜。没有它，两谷一样深，鞍点恰在 x = 0；有了它，鞍点位置、两谷深度都挪了位——图上的标记位置是公式解出来的，挪动公式它们就会跟着动。深度学习里没有人能把损失地形画出来，但「初始化决定落进哪个谷、噪声帮忙逃出鞍点」这两件事，每天都在真实训练里发生。 {#s5hint .hint}

c1h: 反向传播 = 梯度的高效算法
c1: 模型有十亿个参数时，逐个试探求梯度是不可能的。**反向传播**用链式法则，一次反向扫过计算图，就把每个参数的梯度全算出来——算的还是这一页的 ∇f，只是算得聪明。
c2h: Adam = 动量 + 自适应步长
c2: 第 3 步的动量攒的是方向，**Adam** 再给每个参数配一个自己的步长：它给每个方向记一笔账——那个方向上梯度大小的滑动平均，迈步前先拿梯度除以这笔账。梯度一直大的方向，实际步幅被压回学习率 η 的量级；梯度一直小的方向，则被相对放大——各方向的步幅就这样被归一化到同一量级，不再由谁的梯度大说了算。它是第 2、3 步两味药的合剂，也是今天大多数训练的默认选择。
c3h: 大模型训练 = 这个循环 × 10⁹
c3: 把参数换成十亿个、数据换成全网文本、地形大到没有任何人画得出来，循环本身一个字没变：**算梯度、迈步、再算梯度**。GPU 集群每秒做万亿次的，就是你在这一页手动做的事。
