第 0 步 · 函数调用自己

一个函数调用自己时，发生了什么？

这一步要回答：递归是怎么「算出来」的？以阶乘 n! = n × (n−1)! 为例（规定 1! = 1，叫基例：不用再往下问就能直接回答）。每调用一次 fact(k)，就多一层调用栈（图中向下叠的方块，表示「还在等下一层的结果」）；走到基例后才开始自底向上返回，把结果一层层乘回来。拖动「执行到第几步」或按「自动播放」：前 n 步方块一层层叠高，后 n 步由内向外变绿并写出值。改 n：栈有多深？

调用栈 = 记录「已经开始、还在等结果」的调用的一摞；基例 = 不再递归、直接给出答案的最小情形。没有基例的递归不会停。

第 1 步 · 汉诺塔

怎样把一座塔搬过去？

这一步要回答：规则是每次只能搬一个盘子、大盘不能压在小盘上，怎样把 n 个盘子从柱 A 搬到柱 C？递归的想法：先把上面的 n−1 个盘子搬到柱 B（借助 C），再把最大的盘子搬到 C，最后把那 n−1 个盘子从 B 搬到 C（借助 A）。搬 n−1 个盘子本身又是同样的问题，所以只要会搬 n−1 个，就会搬 n 个。拖动「第几步」或按「自动播放」：看盘子怎样一步步移动，图下方说明当前处在这三个阶段中的哪一个。步数 T(n) = 2·T(n−1) + 1 = 2ⁿ − 1。

T(n) = 搬 n 个盘子需要的步数；每多一个盘子，步数翻倍再加 1。这里每步都按递归解法走，它已知是最少的步数（本页不证明）。

第 2 步 · 递归树

三种递归，树长得一样吗？

这一步要回答：为什么有的递归飞快，有的慢得吓人？把每次调用画成一个方块、它调用的子问题画在下一层，就得到递归树。三种典型：汉诺塔（规模减 1，分成 2 个子问题，每个调用做 1 步）；二分查找（规模减半，只进入 1 个子问题，每次比较 1 次）；归并排序（规模减半，分成 2 个子问题，每个调用合并 size 个元素）。选一种、拖动规模：看每层的方块个数怎样变（上图），每层的工作量怎样变（下图的横条）。总工作量 = 各层之和。

「工作量」按各自的基本操作计：汉诺塔每次调用搬 1 个盘；二分查找每层比较 1 次；归并排序每个调用合并 size 个元素（叶子不计）。三者口径不同，只比较增长的形态。

第 3 步 · 增长速度

规模变大，代价差多少？

这一步要回答：同样是递归，规模变大时代价差多少？图是总工作量随 n 的变化（纵轴是对数：每上一格是 10 倍）：汉诺塔 2ⁿ−1（红）、归并排序 n·log₂n（绿）、线性 n（灰）、二分查找 log₂n + 1（青）。拖动 n：红线冲向天际，青线几乎躺平。读数里按「每秒 10⁹ 步」换算成时间，只为帮你感受量级。汉诺塔 n = 64 要多久？拖到 64 看看。

指数增长（汉诺塔）与对数、近线性增长的差别是量级的差别，不是常数倍；「每秒 10⁹ 步」只是假设，不是某台机器的实测。

第 4 步 · 分而治之

把大问题劈开，再合起来

这一步要回答：归并排序的递归树在代码里是按什么顺序执行的？它的思路是分而治之：把数组劈成左右两半，各自排好，再把两个有序的半边合并成一个有序的整体（合并只需从两边的头部各取较小的那个，不用重新排序）。拖动「执行到第几步」或按「自动播放」：橙框 = 正在劈开的区间，绿框 = 刚合并好的区间，下方是此刻的递归栈（每条 = 一层调用，长度 = 区间大小）。读数里的比较次数不超过 n·log₂n。「换一组数」会换 8 个新的数并回到第 0 步。

区间 [a, b) 表示从位置 a 到 b−1。合并时每放入一个元素最多比较一次，所以一层合并最多 n 次比较，共 log₂n 层。

第 5 步 · 终章

收束：递归树的形状决定代价

递归 = 基例 + 把问题化成更小的同类问题；调用画成树之后，每层有多少个调用、每个做多少事，就决定了总代价。

基例与调用栈

递归一层层深入，直到基例，再自底向上返回（第 0 步）。

汉诺塔

T(n) = 2T(n−1) + 1 = 2ⁿ − 1，每个盘子让步数翻倍（第 1 步）。

树形决定代价

缩 1 分 2 → 指数；减半进 1 → 对数；减半分 2 且每层做 n → n·log n（第 2、3 步）。

分而治之

劈开、各自解决、合并；合并比重新排序便宜（第 4 步）。

模型与局限

汉诺塔的步数和归并排序的比较次数都是页面里真实执行的精确计数；增长速度的时间换算基于假设的每秒 10⁹ 步。二分查找与汉诺塔都是递归，但递归树的形状不同、代价量级也不同，并不「等价」。本页没有讨论栈溢出、尾递归优化，也没有给出主定理的一般形式。
