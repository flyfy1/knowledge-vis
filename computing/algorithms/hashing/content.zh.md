## 怎样把任意长的文字压成固定长度的指纹？ {#step0 h2=s0t}

::: strings
nav0: 0 指纹
:::

第 0 步 · 指纹 {#s0k .step-kicker i18n=text}

这一步要回答：**哈希函数**怎样把任意长度的输入变成固定长度的「指纹」？本页用的是教学用的 32 位哈希（FNV-1a 再加一步混合，**不是**加密哈希）：输出永远是 32 个二进制位（0 或 1），不管输入是 1 个字符还是 1 万个字符。在文本框里输入文字，或点预设：32 个格子（亮 = 1）怎样变化。预设 abc 与 abd 只差一个字符，指纹却面目全非。滑块「只取最后 k 位」模拟更短的指纹（哈希表常用 h mod 2^k）：变暗的位被丢弃，读数里是保留部分的数值。同样的输入永远得到同样的输出（确定性）。 {#s0e .explain}

::: html step0-1
s0tL: 输入文字
s0p4: 清空（空输入）
cv0: 输入的 32 位哈希指纹
s0kL: 只取最后 k 位
s0reset: 重置
:::

字节 = 8 个二进制位；中文等字符按 UTF-8 编码占多个字节。mod = 取余数。 {#s0term .term i18n=text}

::: strings
s0Cap: {n} 字节 → 32 位指纹（亮 = 1，暗 = 丢弃）
s0Hex: 十六进制：0x{h}
s0Low: 最后 {k} 位的数值：{v}
s0Dir: 同一输入永远得到同一指纹；不同输入也可能撞上同一个（见第 3 步）
s0ro: 输入 <b>{n}</b> 字节 → 指纹 <b>0x{h}</b>（十进制 {d}，其中 {ones} 个 1）；只取最后 {k} 位 = <b>{v}</b>（共 {m} 种可能）。
:::

## 改一个比特，指纹会变多少？ {#step1 h2=s1t}

::: strings
nav1: 1 雪崩效应
:::

第 1 步 · 雪崩效应 {#s1k .step-kicker i18n=text}

这一步要回答：输入只差 1 个二进制位时，输出会差多少？好的哈希函数应该有**雪崩效应**：翻转输入的任意 1 位，输出的 32 位里大约一半会翻转。下图是一条随机的 8 字节消息（共 64 个输入位）：上排是原指纹，下排是翻转第 p 位后的指纹，橙色格子是变了的位。拖动「翻转第几位」；再按「批量统计」：对 20 条新消息各翻转全部 64 位，共 1280 次，把每次变了多少位累积成直方图，应当以 16 为中心。柱子越集中在 16 附近，说明扩散越好。 {#s1e .explain}

::: html step1-1
cv1: 翻转前后的指纹与累计的变化位数直方图
s1pL: 翻转第几位（0–63）
s1run: 批量统计 1280 次翻转
s1new: 换一条消息
s1reset: 清空统计并重置
:::

雪崩效应是好哈希的性质，不等于安全：本页的哈希没有抗攻击设计，不能用于密码或签名。 {#s1term .term i18n=text}

::: strings
s1A: 原消息的指纹 0x{h}
s1B: 翻转第 {p} 位后：0x{h}（橙 = 变了的位）
s1Hist: {n} 次翻转：每次变了几位（虚线 = 当前）
s1Ax: 变了的位数 0 → 32
s1ro: 翻转输入第 {p} 位：输出变了 <b>{cur}</b> 位。累计 {n} 次翻转：平均变 <b>{mean}</b> 位，标准差 {sd}（理想的随机输出：平均 16，标准差约 2.83）。
:::

## 用指纹当地址：钥匙落进哪个格子？ {#step2 h2=s2t}

::: strings
nav2: 2 哈希表
:::

第 2 步 · 哈希表 {#s2k .step-kicker i18n=text}

这一步要回答：怎样用哈希把东西快速放进、找出来？**哈希表**有 m 个格子（桶），一个键放进第 h(键) mod m 号桶。下图把键 key-001、key-002…… 依次放进去：多个键落进同一个桶叫**冲突**，同桶的键排成一列（橙色）。拖动键的个数 n 和桶数 m，保持其中一个不变，看冲突怎样变化。**装载因子** α = n / m：α 越大，冲突越多。读数把「实际占用的桶数」与公式给出的期望值 m·(1 − (1 − 1/m)ⁿ) 对照（公式假设哈希均匀随机；本页是一组确定的键，两者不会完全相等）。 {#s2e .explain}

::: html step2-1
cv2: 哈希表的桶与落入的键
s2nL: 键的个数 n
s2mL: 桶数 m
s2reset: 重置
:::

冲突 = 两个不同的键被分到同一个桶；本页用「同桶排成一列」处理冲突。 {#s2term .term i18n=text}

::: strings
s2Cap: {n} 个键 → {m} 个桶（橙 = 该桶有多个键）
s2Ax: 格子里的数字 = 键的编号（key-编号）
s2ro: n = <b>{n}</b> 个键放进 m = <b>{m}</b> 个桶，装载因子 α = {a}；实际占用 {occ} 个桶，公式期望 {eo}；有 <b>{coll}</b> 个键与更早的键同桶；最长的桶有 {mx} 个键。
:::

## 为什么冲突比想象中来得早？ {#step3 h2=s3t}

::: strings
nav3: 3 生日悖论
:::

第 3 步 · 生日悖论 {#s3k .step-kicker i18n=text}

这一步要回答：往 m 个格子里随机放 n 个东西，n 多大就几乎必然有两个撞在一起？经典例子是生日：m = 365，只要 n = 23 个人，就有约 50% 的概率两人同生日，因为要比较的不是「每人 vs 365 天」，而是 n(n−1)/2 对人。**精确概率**：P(至少一次冲突) = 1 − (1 − 1/m)(1 − 2/m)…(1 − (n−1)/m)。选一个 m，拖动 n，再按「做 1 / 100 / 1000 次实验」：每次实验随机放 n 个，看有没有撞；橙线是已做实验里「撞过」的比例，绿色虚线是精确概率，实验越多越贴近。n 约为 1.18·√m 时概率约 50%。拖动 n 或换 m 会清空已做的实验。 {#s3e .explain}

::: html step3-1
s3nL: 放入的个数 n
s3m0: m = 365（生日）
s3m1: m = 65536 = 2¹⁶
s3m2: m = 2³² ≈ 43 亿
cv3: 生日悖论的实验比例与精确概率
s3r1: 做 1 次实验
s3r100: 做 100 次
s3r1000: 做 1000 次
s3reset: 清空实验并重置
:::

实验用固定随机种子；± 是标准误 √(p(1−p)/次数)。m 很大时曲线在 n ≤ 100 内几乎贴着 0，请看读数里的 50% 位置。 {#s3term .term i18n=text}

::: strings
s3Cap: n = {n} 个放进 m = {m} 个格子
s3Ax: 实验次数 → {n}
s3Leg: 橙 = 撞过的比例，绿虚线 = 精确概率
s3Curve: 精确概率随 n 变化（n：0 → 100）
s3ro: n = <b>{n}</b>，m = {m}：精确概率 <b>{ex}</b>；已做 {trials} 次实验，撞过的比例 <b>{emp}</b>（± {se}）；n 约为 {n50} 时概率达到 50%。
:::

## 要避免撞车，指纹要多少位？ {#step4 h2=s4t}

::: strings
nav4: 4 指纹多长
:::

第 4 步 · 指纹多长 {#s4k .step-kicker i18n=text}

这一步要回答：给大量文件做指纹，要多长才几乎不会撞？假设哈希输出像均匀随机的 k 位数，n 个对象至少有一次冲突的概率约为 1 − e^(−n(n−1)/2^(k+1))（概率很小时约等于 n(n−1)/2^(k+1)）。纵轴是冲突概率的对数（1e-6 = 百万分之一），横轴是指纹位数 k。拖动 n（以 10 的幂计）和 k：n 不变时，k 每多 1 位，概率约减半；读数还给出把概率压到百万分之一以下大约需要几位。32 位指纹到了百万级对象就几乎必撞，要到 128 位左右才能当作「不会撞」。 {#s4e .explain}

::: html step4-1
cv4: 冲突概率随指纹位数的变化
s4xL: 对象个数 n（10 的幂）
s4kL: 指纹位数 k
s4reset: 重置
:::

假设哈希输出均匀随机、相互独立；真实哈希（尤其非加密的）可能有偏差，攻击者还可能故意制造冲突，本页不涉及。 {#s4term .term i18n=text}

::: strings
s4Cap: n = 10^{x} 个对象时的冲突概率
s4Ax: 指纹位数 k：8 → 128
s4Leg: 纵轴 = 冲突概率（对数，下限 1e-30）
s4ro: n = <b>{n}</b>，k = <b>{k}</b> 位：冲突概率约 <b>{p}</b>；要压到百万分之一以下大约需要 {need} 位。
:::
