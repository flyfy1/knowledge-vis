## 被链接得最多的网页，就是最重要的吗？ {#step0 h2=s0t}

::: strings
nav0: 0 谁更重要

第 0 步 · 谁更重要 {#s0k .step-kicker i18n=text}

## 随机点链接，最后停在哪里？ {#step1 h2=s1t}

::: strings
nav1: 1 随机冲浪者
:::

第 1 步 · 随机冲浪者 {#s1k .step-kicker i18n=text}

这一步要回答：怎样把「重要」变成一个可以计算的数？设想一个随机冲浪者：每一步，他以概率 d（**阻尼系数**）沿当前页面的某条出链随机走一条，以概率 1 − d 厌倦了，随机跳到 8 个页面中的任意一个（**瞬移**）。长期来看他在每个页面停留的时间比例，就是该页的 PageRank。按「走 1 步 / 100 步 / 1000 步」或「自动冲浪」：彩柱是他已访问的频率，白线是精确的 PageRank；走得越多，彩柱越贴近白线。拖动 d 会清空已走的步数（页面会提示）。 {#s1e .explain}

::: html step1-1
cv1: 冲浪者的访问频率与精确 PageRank
s1dL: 阻尼系数 d
s1b1: 走 1 步
s1b100: 走 100 步
s1b1000: 走 1000 步
s1reset: 清空并重置
:::

总变差距离 = ½Σ|频率 − PageRank|，0 表示两个分布完全相同；步数越多，随机涨落越小。 {#s1term .term i18n=text}

::: strings
s1Auto: ▶ 自动冲浪
s1Cap: 冲浪者当前所在页面（白圈）
s1Bars: 已访问频率（彩柱）· 共 {n} 步
s1Leg: 白线 = 精确 PageRank；彩柱 = 冲浪者的访问频率
s1Notice: （d 已改变，之前走的步数已清空。）
s1ro: 已走 <b>{n}</b> 步，当前在 {cur}，d = {d}；频率与 PageRank 的总变差距离 <b>{dist}</b>（越小越接近）。{note}
:::

## 不用真去冲浪，怎样直接算出来？ {#step2 h2=s2t}

::: strings
nav2: 2 迭代算出来
:::

第 2 步 · 迭代算出来 {#s2k .step-kicker i18n=text}

这一步要回答：能不能不靠模拟，直接算出每页的 PageRank？思路：开始时每页一样（1/8），然后反复更新——每个页面的新得分 = 瞬移带来的 (1 − d)/8，加上所有指向它的页面把自己得分的 d 倍平均分给各条出链。这就是对矩阵反复做乘法的**幂迭代**（原理见[[eigenvectors#step3|特征向量 · 幂迭代]]）。拖动「迭代次数 k」或按「逐次迭代」：柱子怎样从平均慢慢移向白线（最终值），读数里「相邻两次变化」和「与最终值的距离」怎样缩小。这里 d = 0.85。 {#s2e .explain}

::: html step2-1
cv2: 迭代过程中各页得分的变化
s2kL: 迭代次数 k
s2reset: 重置为 0 次
:::

每次迭代后各页得分之和保持为 1；变化越来越小，说明在收敛。 {#s2term .term i18n=text}

::: strings
s2play: ▶ 逐次迭代
s2pause: ⏸ 暂停
s2Cap: 第 {k} 次迭代时各页的得分
s2Bars: 各页得分（白线 = 最终值）
s2Leg: 每次迭代：新得分 = 瞬移的 (1−d)/8 + 指向它的页面按出链数均分 d 倍得分
s2ro: 迭代 <b>{k}</b> 次：与上一次相比总变化 {ch}，与最终值的距离 <b>{err}</b>；各页得分之和 {sum}；当前名次 {ord}。
:::

## 阻尼系数 d 改变了什么？ {#step3 h2=s3t}

::: strings
nav3: 3 阻尼系数
:::

第 3 步 · 阻尼系数 {#s3k .step-kicker i18n=text}

这一步要回答：d 取不同的值，PageRank 会怎样变？d 越大，冲浪者越认真沿着链接走，结果越取决于链接结构；d 越小，越多的时间花在随机瞬移上，各页越趋于平均。拖动 d，链接不变：看节点大小、柱子（白线 = d = 0.85 时的值）和名次怎样变化；下方曲线是算到误差小于 10⁻⁸ 所需的迭代次数，橙点是当前 d：d 越接近 1 越慢。常用的 d 是 0.85。 {#s3e .explain}

::: html step3-1
cv3: 不同阻尼系数下的 PageRank 与收敛所需次数
s3dL: 阻尼系数 d
s3reset: 重置为 0.85
:::

收敛所需次数取决于这张小图；真实网页图规模巨大，次数和算法细节都不同。 {#s3term .term i18n=text}

::: strings
s3Cap: d = {d} 时的 PageRank
s3Bars: 各页 PageRank（白线 = d=0.85）
s3It: 收敛所需迭代次数（误差 < 10⁻⁸）
s3Ax: d
s3ro: d = <b>{d}</b>：收敛需要 <b>{it}</b> 次迭代；最高得分 {top}；名次 {ord}。
:::

## 收束：重要 = 被重要的页面链接 {#step5 h2=s5t}

::: strings
nav5: 5 终章
:::

第 5 步 · 终章 {#s5k .step-kicker i18n=text}

PageRank 把「重要」定义成随机冲浪者长期停留的概率：它既可以模拟，也可以迭代算出；入链数多不一定重要，来自重要页面的链接分量更重。 {#s5e .explain i18n=text}

::: html step5-1
c1t: 入链数会误导
c1b: X 入链更多，Y 的入链却来自重要页面，名次更高（第 0 步）。
c2t: 随机冲浪者
c2b: 沿链接走加偶尔瞬移，长期访问频率就是 PageRank（第 1 步）。
c3t: 迭代求解
c3b: 反复把得分沿链接分配，几十次后收敛；d 越大越慢（第 2、3 步）。
c4t: 链接的质量
c4b: 来自重要页面的一条链接胜过一群小页面（第 4 步）。
modelT: 模型与局限
modelB: 这是一个 8 个页面的玩具网络，没有出链为零的页面（代码里对它们均分得分，但图里没有）；真实搜索排序用到许多信号，PageRank 只是早期的一种；真实网页图规模巨大，还要处理反作弊。第 1 步用固定随机种子模拟，其余步骤用精确迭代。
:::
