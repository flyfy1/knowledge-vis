## 同样从 A 到 E，哪条路总长最短？ {#step0 h2=s0t pre=1}

::: strings

这一步要回答：带权图里什么叫“最短”？图由**节点**（A–F）和连接它们的**边**组成，每条边有一个**权重**（这里表示路程或时间）；一条路径的代价是它经过的所有边的权重之和，而不是经过的节点个数。**观察：**点击下面的按钮一站一站地从 A 走向 E（只能走到相邻且没走过的节点，可以「撤销」或「重置」），读数显示你的总代价和已知的最短代价。试试 A→B→D→E（7+15+6 = 28）和 A→C→F→E（9+2+9 = 20）：节点更多的路反而更短。 {#s0e .explain}

## 怎样不试遍所有路径就找到最短路？ {#step1 h2=s1t pre=1}

::: strings
nav1: 1 洪水式确认
:::

::: html step1-1
s1step: "第 1 步 · "
s1k: 迪杰斯特拉算法
:::

这一步要回答：怎样系统地求出起点到每个点的最短距离？每个节点维护一个**暂定距离**（当前已知的最短距离，初始为 ∞，起点为 0）。每一轮：在尚未确认的节点中，选暂定距离最小的那个，把它**确认**（红圈）——此时它的距离已经是最终最短距离；然后检查它的每个邻居，若经过它更近，就更新邻居的暂定距离（橙色）。就像水从起点向外漫开，最先漫到的点距离最小。**观察：**点「走一步」或「连续走」（可暂停），盯住每个节点下方的数字。绿色是已确认的点，橙色是候选，确认顺序始终是距离由小到大。 {#s1e .explain}

## 边的权重可以是负数吗？ {#step2 h2=s2t pre=1}

::: strings
nav2: 2 负权会让它出错
:::

::: html step2-1
s2step: "第 2 步 · "
s2k: 它的前提
:::

这一步要回答：为什么迪杰斯特拉算法要求权重不能为负？它的正确性来自：一个点被确认时，不可能再有更短的路——因为其他还没确认的点离起点更远，从它们出发再加上非负的边只会更远。有了负权，这个论证就破了。这里有一张有向小图：S→A 1，S→B 2，B→A（可调），A→C 1。把 B→A 的权重调到小于 −1（如 −2）：算法先确认 A（距离 1），之后才发现经 B 到 A 更近，但 A 已经“关门”，C 的结果就错了；青色是迪杰斯特拉的结果，绿色是不受此限制的贝尔曼–福特算法的结果。**观察：**拖动 B→A 的权重：≥ −1 时两者一致，低于 −1 红圈出现，表示结果不一致。 {#s2e .explain}

这一步要回答：同一套算法放到地图上会怎样？网格里每一格是一个节点，相邻格之间可以移动，进入一格的代价是它自己的权重：路面 1，泥地（棕色，数字是代价）可调。从绿点 S 走到红点 T。蓝色深浅表示算法确认时的距离（越近越亮），橙线是最短路径。**观察：**拖动泥地代价：代价低时路径笔直穿过泥地；代价高到一定程度，路径改成绕到顶行走（多走 12 格但每格代价 1）。读数里给出路径总代价、穿过的泥地格数和“全是路面”时的代价对照。算法本身没变，变的只是权重。 {#s3e .explain}

## 已经知道终点在右边，还要往四面八方都漫吗？ {#step4 h2=s4t pre=1}

::: strings
nav4: 4 A\* 少看一些格
:::

::: html step4-1
s4step: "第 4 步 · "
s4k: 少看一些格
:::

这一步要回答：能否用“终点大概在哪”来少算一些？<strong>A\*</strong> 在迪杰斯特拉的基础上，给每个格再加一个**启发值** h：到终点的估计距离（这里用曼哈顿距离，即横向加纵向的格数，每步代价至少 1，所以不会高估）。它按“已走距离 + 估计剩余距离”的最小者确认，倾向朝终点方向漫，不再向四周均匀漫开。**观察：**切换两种算法，对比被确认的格数：A\* 更少——泥地代价为 1（全是路面）时省得最多，泥地代价高时省得少——而路径总代价相同（读数核对）。泥地代价越高，启发值低估得越多。同一张地图和泥地代价与上一步共用。 {#s4e .explain}
