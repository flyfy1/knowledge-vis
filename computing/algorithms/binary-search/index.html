二分查找 · 每次砍掉一半

在有序数组里找一个数，不必逐个试。每次看中间值，根据一次比较把不可能的半边整段丢掉。

注意因果顺序：比较中间值 → 保留一半 → 下一次中间值改变。算法快，不是因为猜得准，而是每次都能安全丢掉一半。

第 1 步 · 核心动作

左右指针把“还没排除的区间”圈出来

把搜索写成三个数：lo、mid、hi。每一步只更新 lo 或 hi，循环不变量始终是“如果答案存在，它就在 [lo, hi] 里”。

轨迹

    mid = ⌊(lo + hi) / 2⌋

    每次循环只做一次相等/大小比较，再把区间缩短。

    把“排除”写进代码的边界更新里：target < a[mid] 时令 hi = mid − 1，否则令 lo = mid + 1。边界比口诀更重要。

    二分查找的“快”建立在前提上：数组必须有序。若数据还没排序，先排序的成本会改变总账，算法选择永远要连着输入条件一起看。

    第 3 步 · 记账

    n 翻倍，二分只多问一个问题

    用滑杆改变 n，实时比较线性查找最坏需要问多少次、二分最坏需要问多少次。柱高不是秒表，而是比较次数。

    linear: O(n)  ·  binary: O(log₂ n)

    二分最坏比较次数 = ⌊log₂ n⌋ + 1（对本页的闭区间写法）。

    复杂度说的是规模增长：n=32 时差距还像几格柱子，n=1024 时已经是数量级差异。每次砍半，就是对数从哪里来的地方。

    第 4 步 · 收束

    把二分查找写成三个前提

    记住三句话：数组有序；区间边界保持正确；每次比较后排除一半。满足它们，查找就从“逐个试”变成 O(log n)。

    可迁移规则：先问输入有没有顺序，再看一次比较能排除多少候选；算法的复杂度来自你敢删掉的那部分。
