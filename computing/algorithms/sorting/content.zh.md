## 同一副乱牌，两种命运 {#step0 h2=s0t}

::: strings
nav0: 0 双赛道
:::

第 0 步 · 钩子 {#s0k .step-kicker i18n=text}

两条赛道，**同一副牌**（同一个种子生成的同一个数组）：左边冒泡排序，右边归并排序。按下开始，两边**按比较次数推进**——每完成 1 次比较，两边都走相同的时间，所以谁先停下，纯粹由「总共要比多少次」决定，不掺一点手速水分。你会看到归并早早收工，冒泡还在慢慢爬。差距不在谁写得勤快，在**增长形状**。 {#s0e .explain}

::: html step0-1

s0rightLab: 归并排序 Merge Sort
s0race: 开始比赛
reset: 重置
newSeed: 换个种子
:::

诚实交代：这里的「快慢」是比较次数的快慢，不是秒表。真实耗时还取决于语言、机器与实现细节——但比较次数是算法自己的账，谁也赖不掉。动画节奏的单位是「次比较」，图注与正文都会一直守着这个口径。 {#s0hint .hint}

::: html step0-2
start: 开始探索 ↓
:::

s0final: 终局：同一副 {n} 张牌，冒泡比较 <b>{bc}</b> 次，归并只比较 <b>{mc}</b> 次——差了约 <b>{x}</b> 倍。而且 n 越大，这个倍数只会越拉越大：这就是后面六步要拆开看的东西。

## 冒泡与选择：笨办法的账要算清 {#step1 h2=s1t}

::: strings
nav1: 1 O(n²) 家族
:::

第 1 步 · O(n²) 家族 {#s1k .step-kicker i18n=text}

**冒泡**：相邻两个比一比，逆序就交换，大个子一路「冒泡」到队尾；本页的冒泡带**早停**——某一趟全程没交换，说明已经有序，立刻收工。**选择**：每轮从没排的部分里扫出最小的，放到位。单步走一遍盯住计数器：选择的比较数**只认 n、不认数据**；冒泡的交换数则严丝合缝等于原数组的**逆序数**（一对顺序反了的元素）。换个种子、换种数据，自己验。 {#s1e .explain}

选择比较数 ≡ n(n−1)/2 · 冒泡交换数 = 逆序数 · 冒泡（带早停）已排序输入比较数 = n−1 {#s1formula .formula i18n=text}

试试「逆序」数据：冒泡的交换数会冲到 n(n−1)/2（每个元素对都是逆序），选择却连眼皮都不抬——比较数纹丝不动，变的只是交换数。两个算法同属 O(n²)，性情却完全两样：一个对数据敏感，一个对数据无感。 {#s1hint .hint}

:::

## 归并与快排：把大问题切小 {#step2 h2=s2t}

::: strings
nav2: 2 分而治之
:::

第 2 步 · 分而治之 {#s2k .step-kicker i18n=text}

**归并**：数组从中间切开（左半 ⌊n/2⌋），递归排好两半，再像拉拉链一样合并——合并时只比两段的「排头」，小的先出。每一层合并的总工作量约 n，层数约 log₂n，相乘就是 n log₂ n。**快排**在本页的规则写明白：**pivot 取最后一个元素**，用 Lomuto 分区把小的扫到左边、大的留在右边，再递归两边。规则不同，账就不同——所以规则必须印在页上。 {#s2e .explain}

::: html step2-1
algMerge: 归并
algQuick: 快排
:::

两个面板各自独立、计数互不延续——归并这边数的是它自己的比较与移动，切到快排看到的是快排自己的比较与交换，两边的进度互不影响。 {#s2panelNote .hint i18n=text}

::: html step2-2

s2formulaQ: 快排（本页规则）：pivot = 最后一个元素，Lomuto 分区；随机模式从区间内等概率抽一个当 pivot
s2pivotLab: pivot 规则

s2randP: 随机抽

:::

归并的「移动」指合并时把元素写入主数组的次数：每层每个元素都要搬一次，所以移动数约 n·log₂n——它拿额外的内存换稳定的形状。快排则原地分区、几乎不占额外空间，代价是形状要看 pivot 的脸色。两种 n log n，账本的构成完全不同。 {#s2hint .hint}

s2roQ: 快排：比较 <span>{c}</span> 次 · 交换 <span>{s}</span> 次 · pivot 已就位 <span>{p}</span> 个 · {st}
s2noteWorst: 退化属实：已排序输入 + 取末元 pivot，每次分区只排定一个元素，比较数走向 n(n−1)/2 = {f}（本局 {c}）。这不是实现写坏了——是这条规则在这种数据上的真实命运，递推式 T(n) = T(n−1) + (n−1) 说的就是它。
s2noteRand: 同一副已排序牌、换随机 pivot：比较数降到 {c}。注意口径——随机化给的是**期望**意义上的 n log n：运气再差也可能抽到坏 pivot，它保证的是「再没有哪种输入能稳定地坑你」，不是「每次都快」。
:::

## 大 O 是形状，不是速度 {#step4 h2=s4t}

::: strings
nav4: 4 常数对决
:::

第 4 步 · 常数对决 {#s4k .step-kicker i18n=text}

大 O 把系数扔了，但系数不是不存在。设 A 做的是「重操作」：成本 **100·n·log₂n**；B 做的是「轻操作」：成本 **n²**。A 形状好但单价贵 100 倍，B 形状差但单价便宜。n 小的时候 B 反赢——别急着笑它没出息；n 一路涨上去，两条线必然在某个点换位。交叉点不靠猜：下面两侧各取一个整数 n，把两边成本当场算给你看。 {#s4e .explain}

A(n) = 100 · n · log₂n（重操作） vs B(n) = n²（轻操作） {#s4formula .formula i18n=text}

::: html step4-1
s4nLab: n（对数滑杆）
s4termT: 主导项：低阶项会被涨没
s4termE: 看 f(n) = 2n² + 100n：n 不大时 100n 还占大头，n 涨上去之后，占比的天平完全倒向 2n²。大 O 只留最高阶、扔系数与低阶项，不是因为它们不存在，而是因为**在足够大的 n 面前，它们说了不算**。点几个 n 自己看占比怎么变。
:::

诚实区分：这一页从头到尾比的都是**操作次数**，不是真实秒数。真实耗时还受机器、语言、缓存与实现手艺影响——但「n 涨过交叉点之后形状说了算」这件事，在任何机器上都成立。工业实现里「小数据用简单算法」正是活学活用这个交叉点（第 6 步）。 {#s4hint .hint}

::: strings
s4ro: n = <span>{n}</span>：A = <span>{a}</span> · B = <span>{b}</span> → <b>{w}</b> 更便宜（差 <span>{d}</span>）
s4winA: A（形状好）
s4winB: B（常数小）
s4cross: 交叉点自证：n\* = <span>{x}</span> 是第一个 A 更便宜的整数——n = {xm} 时 A = {am} > B = {bm}，B 赢；n = {x} 时 A = {ax} < B = {bx}，A 赢。两侧读数都由成本函数当场算出。
s4termRo: n = <span>{n}</span>：2n² = <span>{q}</span>（占 <span>{qp}</span>%）· 100n = <span>{l}</span>（占 <span>{lp}</span>%）→ f(n) 的大 O 只记 <b>O(n²)</b>

## 计数排序：不靠比较的排法 {#step5 h2=s5t}

::: strings
nav5: 5 计数排序
:::

第 5 步 · 线性时间 {#s5k .step-kicker i18n=text}

数据的值域有界（0 到 k）时，有一招「不讲武德」的排法：**不比较任何一次**——把每个值当成地址，数一遍每个值出现几次（计数桶），再按值从小到大依次把元素倒出来。操作数 = 数一遍（n）+ 扫一遍桶（k+1）+ 倒出来（n），随 n 线性增长。下面全程盯住比较计数器：它从头到尾是 **0**。 {#s5e .explain}

操作数 = n（计数） + (k+1)（扫桶） + n（输出） = 2n + k + 1 · 比较数 = 0 · 内存 = k + 1 格 {#s5formula .formula i18n=text}

::: html step5-1
s5kLab: k · 值域上限（值在 0..k）
s5step: 走一步操作
s5blow: 把值域拉到 100000
:::

口径守则：比较排序有个下界 Ω(n log n)，但它只约束「靠两两比较获取信息」的算法。计数排序压根不比较，所以不是它「打破」了下界，而是它绕开了下界的前提——拿值域当地址用。天下没有白来的线性：值域 k 一旦没边，桶的内存与扫描成本立刻反噬（点上面的按钮试试）。 {#s5hint .hint}

## 真实世界的排序：混血与直觉 {#step6 h2=s6t}

::: strings
nav6: 6 终章 · 真实世界
:::

第 6 步 · 终章 {#s6k .step-kicker i18n=text}

::: html step6-1
c1h: 工业实现都是混血
c1: 你每天用的排序几乎都不是纯种：Python 与 Java 的 **Timsort** 以归并为骨架、掺入插入排序，还会先侦测数据里天然有序的片段顺势利用；C++ 标准库的 **introsort** 以快排为主力，递归太深时切换堆排序兜底防退化、浅层换插入排序收尾。没有哪个纯种算法能通吃所有数据，工程的答案是混血。
c2h: 小 n 时，简单反而赢
c2: 混血算法有个共同细节：片段小到一定程度（几十个元素上下）就切回**插入排序**这种 O(n²) 的简单循环——第 4 步的交叉点说的就是这个理：n 小的时候，常数小、代码直白的算法实际成本更低。O(n²) 在小数据上不是原罪，是性价比。
c3h: 选型直觉：先看 n 与数据
c3: 面对一堆要排的数据，先问四件事：**n 有多大**（决定形状的权重）、**是否近乎有序**（Timsort 与带早停的算法占便宜）、**值域是否有界**（计数排序的机会）、**要不要稳定**（等值元素的相对次序保不保）。形状优先、常数其次——这把尺，就是这一页的全部内容。
s6fin: 回勾一句隔壁的<a class="fourier-link" href="../../ml/gradient-descent/#step2">梯度下降</a>：那边算成本，是「每一步多便宜 × 要走多少步」；这边算成本，是「每次比较多便宜 × 要比多少次」。成本永远是两个因子相乘——一个因子管单价，一个管数量，而数量的**增长形状**，最终说了算。学会看形状，你就有了一把丈量一切算法的尺。
:::
