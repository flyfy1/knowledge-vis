## 一台只会转圈的造波机 {#step0 h2=s0t}

::: strings
nav0: 0 造波机
:::

第 0 步 · 钩子 {#s0k .step-kicker i18n=text}

这一步要回答：**一个只会转圈的点，怎么会描出一条正弦波？**圆上的点匀速转圈，它的身高（纵坐标）被一笔一笔描下来，就是你背了三年的那条**正弦波**。这一页先什么都不解释——让它转起来，盯着看：波的每一个起伏，都是点在圆上的位置。 {#s0e .explain}

::: html step0-1
s0speed: 转速 ω（rad/s）
pause: ⏸ 暂停
stepOnce: 单步 ▸（+6°）
:::

弧度（rad）先交代一句：它是量角的另一种单位——一整圈是 2π rad，1 rad ≈ 57.3°；转速 ω 用 rad/s，就是每秒扫过多少弧度。波不是预先画好的：每一帧都取点**此刻的真实身高**记下来、连成线。把转速拉快或拉慢，看波被压紧还是拉长——记住这个手感，第 5 步它会变成声音的高低。 {#s0hint .hint}

::: html step0-2
start: 开始探索 ↓
:::

::: strings

s0ro: θ = {deg}°（{rad} rad）· sin θ（此刻身高）= {sin} · 波最前面的那个点，就是此刻的身高

:::

## cos 是站位，sin 是身高 {#step1 h2=s1t}

::: strings
nav1: 1 点的坐标
:::

第 1 步 · 点的坐标 {#s1k .step-kicker i18n=text}

这一步要回答：**点的横、纵两个坐标，凭什么就是 cos 和 sin？**停下自动转，改用手拖。把圆上的点拖到任何地方：它横着离原点多远，就是 **cos θ**（站位）；竖着离原点多高，就是 **sin θ**（身高）。所谓三角函数，不过是给这个点的两个坐标起了名字。两条投影线和中间的直角三角形会一直跟着它。 {#s1e .explain}

::: html step1-1

s1rad: 弧度 rad
s1snap: 特殊角一键到位：

:::

看符号怎么变：点走过 y 轴，站位（cos）变负、身高还是正的；掉到 x 轴下方，身高（sin）变负。四个象限的正负号不是口诀，是坐标自己带的——点在哪儿，查哪儿。 {#s1hint .hint}

## 把身高摊开，就是正弦波 {#step2 h2=s2t}

::: strings
nav2: 2 sin 是身高
:::

第 2 步 · sin 登场 {#s2k .step-kicker i18n=text}

这一步要回答：**把身高按时间排开，为什么就是正弦波？**这次把造波机讲透：点爬到最高处，波就到峰顶；点穿过水平直径，波就过零。波不是「像」圆——波就是圆的**侧影**：把点每一刻的身高按时间排开，仅此而已。在几个关键角度停下来打点，看波上对应的位置长什么样。 {#s2e .explain}

::: html step2-1
s2amp: 振幅 = 半径 R
s2mark: 在关键角度暂停打点：
s2pause: ⏸ 暂停
:::

拖振幅滑杆：圆变大的同时，波**同步**变高——量它们的是同一把尺子、同一个半径。振幅不是波身上另一个参数，它就是圆的半径本身。 {#s2hint .hint}

## 换个方向看：站位也能成波 {#step3 h2=s3t}

::: strings
nav3: 3 cos 是站位
:::

第 3 步 · cos 登场 {#s3k .step-kicker i18n=text}

这一步要回答：**cos 描出的波，和 sin 是什么关系？**同一台机器，把要描的量换成站位（横坐标）：描出来的波和 sin 一模一样，只是**早出发了四分之一个周期**。cos 不是第二个要背的函数——它就是提前 90° 的 sin。「相位差」这个词，从这里开始有画面了。 {#s3e .explain}

::: html step3-1
s3watchSin: 看身高 sin
s3watchCos: 看站位 cos
s3watchBoth: 两条叠加
:::

在圆上看得最清楚：身高到峰顶时，站位刚好过零；站位到最右时，身高刚好过零。一个到峰，另一个必过零——永远错开四分之一圈。傅里叶和采样里到处都是的「相位」，说的就是这个错开的量。 {#s3hint .hint}

::: strings
s3ro: θ = {deg}° · sin θ = {sin} · cos θ = {cos} · 相位差恒为 90°（π/2）：cos θ = sin(θ + 90°) = {shift}，与 cos 本人分毫不差
cSinWave: sin 波（身高）
cCosWave: cos 波（站位）
:::

## tan 是斜率，站上 x = 1 的墙 {#step4 h2=s4t}

::: strings
nav4: 4 tan 是斜率
:::

第 4 步 · tan 登场 {#s4k .step-kicker i18n=text}

这一步要回答：**tan 是什么，点逼近 90° 时它会怎样？**还剩最后一个。把原点和点的连线**延长**，让它撞上 x = 1 这面竖墙：撞点离地面的高度，就是 **tan θ**——它其实就是这条线的斜率，也就是 sin 除以 cos。拖动点（或拖滑杆）逼近 90°，看撞点怎么冲上天；再拖过 90°，看它从哪里回来。 {#s4e .explain}

先点 89.9°、90°、90.1° 依次比较：有限值、未定义、有限负值是三种不同状态。 {#s4bridge .hint i18n=text}

::: html step4-1
s4th: 角度 θ（°）
s4near: 逼近 90°：
tangentSource: 数学依据：OpenStax · tan的定义域与周期 ↗
:::

定义域排除90°+180°k，k为整数；tan的周期180°（π rad）。90°左侧趋+∞、右侧趋−∞是单侧极限，90°本身没有数值。有限大值不会因画面越界变成无穷；≈标示数值舍入。全周0–360°，360°与0°同向并显示0°。滑杆/本图方向键循环调0.1°，Shift为1°；Home/End回0°。内部用弧度，180°=π rad。 {#s4hint .hint}

## 世界在转圈与波之间翻译 {#step5 h2=s5t}

::: strings
nav5: 5 旋转⇄往复
:::

第 5 步 · 旋转 ⇄ 往复 {#s5k .step-kicker i18n=text}

这一步要回答：**转圈和波，在真实世界里是怎么互相翻译的？**圆和波不是数学课的摆设：**旋转的东西，身高就是波；波，就是被摊开的旋转。**下面三联小景共用同一个转速——摩天轮的座舱高度、发动机的活塞行程、声音的音高，都是同一个点在转。 {#s5e .explain}

::: html step5-1
s5speed: 转速（圈/秒）
s5wheelT: ① 摩天轮：座舱高度
s5pistonT: ② 曲柄活塞：往复行程
s5soundT: ③ 转速变声音
s5play: ▶ 听一听
:::

转盘经连杆推活塞。连杆长度只有曲柄半径的 2.5 倍——有限长的连杆会让活塞在冲程顶端附近多磨蹭一会儿，所以活塞的曲线**接近正弦，但不是正弦**。连杆越长差越小；只有无穷长的连杆，才给出严格的正弦。 {#s5pistonE .explain}

拖转速：画面里的波被挤紧的同时，声音真的变高——波的疏密和音高的低，是被转速锁死的同一件事。默认静默，点了才出声，音量已压低。 {#s5soundHint .hint}

## 总览台：一个圆，三个投影 {#step6 h2=s6t}

::: strings
nav6: 6 终章总览
:::

第 6 步 · 终章 {#s6k .step-kicker i18n=text}

这一步要回答：**同一个点，怎样同时描出 sin、cos、tan 三条波？**最后把全家叫到同一张桌子上：拖动这个点（或让它自己转），圆上的点、三个读数、三条波的**当前位置**同时亮起。三条波没有一条是预先画好的——点被拖过哪儿，哪儿的波就被它的投影当场描出来；没去过的地方，就是空的。 {#s6e .explain}

::: html step6-1

s6clear: 清空轨迹
s6autoNote: 轨迹只记录点实际扫过的位置；tan带仅显示±3.4，画外留空断线，90°/270°无定义。当前点可用方向键调1°（Shift10°），Home/End回0°；手动操作暂停播放。刷新仅恢复当前角度/链开关，不恢复轨迹或自动播放。 ≈表示舍入，不能只凭显示角度判定义域。
s6fin: 试试把第二个小圆挂到大圆的点上：小圆绕着大圆的点转，笔尖的轨迹立刻不再是圆，而是花瓣。再往后一步，就是**傅里叶变换**——把很多这样的圆首尾相连，各有各的半径、转速和相位，让它们替你画出任何波形、任何图形。这一页的单个圆，就是那一整页的全部家当。
