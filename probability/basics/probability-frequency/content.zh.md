## 转盘停在红色的可能性有多大？ {#step0 h2=s0t pre=1}

::: strings
nav0: 0 转一次
:::

::: html step0-1
s0step: "第 0 步 · "
s0k: 转一次
:::

这一步要回答：概率是怎么算的？转盘每次转停，指针落在哪里是随机的。**概率**是这个结果出现的可能性大小，这里等于红色扇形占整个圆的比例。拖动红色的占比，再按“转一次”：每次的结果是随机的，不能预测，只能说它的概率。 {#s0e .explain}

spin0: 转一次
:::

s0roIdle: 红色概率 = {p}%（占 {a}° ÷ 360°）。按“转一次”试试。
:::

## 转几十次、几百次，红色的频率怎么变？ {#step1 h2=s1t pre=1}

::: strings
nav1: 1 转很多次
:::

::: html step1-1
s1step: "第 1 步 · "
s1k: 转很多次
:::

这一步要回答：频率和概率是什么关系？**频率** = 红色出现的次数 ÷ 转的总次数。每次按钮转 1、10、100、500 次：折线记录“转到现在，红色的频率”。开始摆动很大，转得越多，折线越靠近虚线（红色的概率 30%）。 {#s1e .explain}

:::

## 每次实验转的次数越多，结果的波动会越小吗？ {#step2 h2=s2t pre=1}

::: strings
nav2: 2 越多越稳
:::

::: html step2-1
s2step: "第 2 步 · "
s2k: 越多越稳
:::

这一步要回答：为什么“转得多”更可靠？选每次实验转 n 次，按“做 20 次实验”：每次实验得到一个红色频率，画成一个点，每行是一个 n。同一个 n 的 20 个点散开多宽，就是这个 n 下频率的波动。n 越大，这一行的点越集中在概率 30% 附近。 {#s2e .explain}

## 所有可能结果的概率加起来是多少？ {#step3 h2=s3t pre=1}

::: strings
nav3: 3 概率之和
:::

::: html step3-1
s3step: "第 3 步 · "
s3k: 概率之和
:::

这一步要回答：概率有什么限制？转盘一次必定停在某种颜色上，所以所有颜色的概率加起来 = 1（100%）。拖动红色和蓝色的占比，绿色得到剩下的部分：每个概率都在 0 到 1 之间；“不是红色”的概率 = 1 − 红色的概率。 {#s3e .explain}

::: html step3-2
s3cv: 三色转盘
rr: 红色占比（%）
bb: 蓝色占比（%）
:::

::: strings
s3ro: 红 {r}%、蓝 {b}%、绿 {g}%，加起来 {s}%；“不是红色”的概率 = 100% − {r}% = {nr}%（蓝 + 绿 = {nr2}%）。
:::

## 转 n 次，红色的频率大约落在哪个范围？ {#step5 h2=s5t pre=1}

::: strings
nav5: 5 终章
:::

::: html step5-1
s5step: "第 5 步 · "
s5k: 终章
:::

这一步要回答：怎样预测频率的范围？概率 p、每次转 n 次时，频率大约有 95% 的可能落在 p ± 1.96 × √(p(1 − p) ÷ n) 之内（这是常用的近似，n 较大时好用）。选 p 和 n，按“做一次实验”：每个点是一次实验的频率，橙色带是预测范围。多做几次，看落在带内的比例是否接近 95%。 {#s5e .explain}

::: html step5-2
s5cv: 预测范围与实验结果
pp: 概率 p（%）
nn: 每次转的次数 n
run1: 做一次实验
run50: 做 50 次实验
reset5: 重置
recapTitle: 回顾
recap1: 概率是一次结果的可能性大小；频率是实际做了很多次之后的比例。
recap2: 次数越多，频率越稳定地靠近概率，但每一次结果仍然是随机的。
recap3: 过去的结果不会让下一次“补偿”：连红之后，下一次红色的概率不变。
modelTitle: 模型范围与局限
modelText: 这里的随机数由计算机的伪随机数生成器（固定种子，序列可复现）产生，用来模拟理想转盘和硬币，不是真实实验。95% 范围用的是正态近似，次数很少或概率很接近 0、1 时不准。
