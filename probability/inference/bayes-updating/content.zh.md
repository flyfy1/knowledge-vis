## 检测说你阳性——先别慌，先押个注 {#step0 h2=s0t}

::: strings
nav0: 0 钩子
:::

第 0 步 · 钩子 {#s0k .step-kicker i18n=text}

一种病，**患病率 1%**：一万人里大约 100 人真得。你去做了检测：真病人有 **90%** 会被检出（灵敏度），但健康人也有 **9%** 会被误报（假阳性率）。现在，你的结果是**阳性**。问题来了：你真得病的概率，大约是多少？先押一注，再揭晓。 {#s0e .explain}

先押一注：你觉得「真得病」的概率约是？ {#s0betQ .seq-label i18n=text}

## 亮灯的卡片里，有多少真的带星标？ {#step1 h2=s1t pre=1}

::: strings
nav1: 1 先验是起点
:::

::: html step1-1
s1k: 第1步 · 从测量方向到后验
:::

这一节把同一概率更新换成**假想读卡器**：H表示“卡片有星标”，E表示“读卡器亮灯”。随机从一批卡片抽一张，抽取前星标比例p就是先验P(H)。设有星标时亮灯P(E|H)=90%，无星标时也会亮灯P(E|¬H)=9%。现在只知道它亮灯了，问的是反向的P(H|E)，并不是刚才的90%。 {#s1e .explain}

::: html step1-2
s1priorLab: 抽卡前的星标比例 p=P(H)（原对数滑轨）
s1p1: 先验1%（默认）
s1p10: 先验10%
s1poolTitle: 只看亮灯结果：它们来自哪两组？
s1poolIntro: 整条表示所有亮灯结果E，归一化为100%。A是“有星标且亮灯”，B是“无星标却亮灯”；两类的池内比例随上方同一先验滑轨改变。
s1proof: 为什么要把两类亮灯结果加作分母？
s1jointA: 在全部卡片中，A=P(H∩E)=0.90p
s1jointB: 在全部卡片中，B=P(¬H∩E)=0.09(1−p)
s1evidence: 任一卡片亮灯的概率 P(E)=A+B
s1direction: P(E|H)先限定“有星标”再问亮灯；P(H|E)先限定“亮灯”再问星标，分母不同。90%与9%分别来自两种假设，不是互补概率，不要求加成100%。这里展示模型概率，不是实际抽到的卡片数，也不是设备实测。
s1source: 条件概率与分母 · 教材依据
s1chain: 下一步：第3步比较新测量与复制记录（固定1%先验，不继承此滑轨）
s1map: 回到知识地图中的贝叶斯更新 →

90%和9%是本假想模型的两条条件概率，不是读卡器的“总准确率”。这一节只改先验，识别器参数不变；其他章节仍沿用原检测示例，不自动同步本步滑轨。 {#s1hint .hint}

s1formula: P(H|E)=A/(A+B)≈{post}。A、B先用未舍入值求和与归一化，再显示近似读数。
docTitle: 贝叶斯 · 先查底子，再看证据 · 一步一交互
s1ro: 先验P(H)≈<span>{prior}</span> ＋ 亮灯E → 后验P(H|E)≈<span>{post}</span>。本例似然比LR=10固定，后验概率不是简单把先验乘10。

## 换上赔率眼镜：后验 = 先验 × 似然比 {#step2 h2=s2t}

::: strings
nav2: 2 证据是乘法
:::

第 2 步 · 证据是一次乘法 {#s2k .step-kicker i18n=text}

概率挤在 0 和 1 之间，乘法在里面施展不开。换成**赔率**（概率 ÷ 不中概率）：先验 1% 就是赔率 1 : 99。证据的强度叫**似然比** LR = P(证据|得病) / P(证据|没病)——竖线读作「在……的前提下」：P(证据|得病) 就是「在真得病的前提下，出现这份证据的概率」，没病那边同理。本页检测阳性 LR+ = 0.90 / 0.09 = **10**，阴性 LR− = 0.10 / 0.91 ≈ **0.11**。后验赔率 = 先验赔率 × LR，一次乘法完事。在 log₁₀ 赔率轴上，乘法变成一段**位移**：证据有多重，就把你往右（或往左）推多远。 {#s2e .explain}

::: html step2-1
s2priorLab: 先验概率（对数刻度）
s2lrLab: 似然比 LR（对数刻度）
s2lrPos: 预置：阳性 LR+ = 10
s2lrNeg: 预置：阴性 LR− ≈ 0.11
:::

log 赔率还有个名字叫**证据权重**（weight of evidence）：LR = 10 值 +1，LR = 100 值 +2，LR = 0.1 值 −1。证据在这里第一次可以「称重」、可以相加——第 3 步就靠它连乘。 {#s2hint .hint}

::: strings
s2ro: 先验 {p0} → 赔率 <span>{o0}</span>（log₁₀ 赔率 {l0}）· × LR {lr} → 后验赔率 <span>{o1}</span>（log₁₀ 赔率 {l1}）→ 后验概率 <span>{p1}</span>
cAxisLab: log₁₀ 赔率轴（刻度下为对应概率）
cPriorPt: 先验
cPostPt: 后验
:::

## 同一条读数，不能算两次新证据 {#step3 h2=s3t}

::: strings
nav3: 3 证据连乘
:::

第 3 步 · 新测量，还是旧记录？ {#s3k .step-kicker i18n=text}

沿用第1步的假想读卡器：H 表示卡片有星标，E 表示亮灯。这里固定先验为 1%（不继承第1步滑轨）；有星标时亮灯概率为 90%，无星标时为 9%。**新增测量**按钮选择一个模型假设：在有星标、无星标两种情况下，各次读数都条件独立，即知道之前的读数不会改变下一次的亮灯概率。记录编号只是演示来源，不是独立性的证明。 {#s3e .explain}

::: html step3-1
:::

先预测再试：清空 → 新增亮灯 R1 → 复制 R1。概率会再升吗？撤销复制件，再新增亮灯 R2，比较同一曲线：约 9.17% → 9.17%，与 9.17% → 50.25%。 {#s3task .hint i18n=text}

::: html step3-2
addPos: ＋ 新测量：亮灯（×10）
addNeg: ＋ 新测量：不亮（×0.11）
s3copy: 复制最后一条记录（×1）
undo: 撤销上一条
clear: 清空重来
s3warn: **复制的是同一条已知读数，不是再次测量。**它没有新增信息，赔率只乘 1，曲线出现平段。真正的新测量即使有关联，也可能提供新信息，但需知道给定此前结果及 H／¬H 后的条件概率；不能照搬固定的 ×10。条件独立也不等于不区分 H 的总体独立。**独立连乘不是一般的上限或下限。**
:::

亮灯的似然比为 0.90 / 0.09 = 10；不亮为 0.10 / 0.91 ≈ 0.11。赔率乘似然比，不是概率直接乘它。图横轴计显示条目，复制件也占一格。 {#s3hint .hint}

## 一枚不知道偏不偏的硬币 {#step4 h2=s4t}

::: strings
nav4: 4 连续版 · 硬币
:::

第 4 步 · 连续版 {#s4k .step-kicker i18n=text}

把问题连续化：硬币掷出正面的概率 θ 未知，先验不再是一个数，而是一条**分布曲线**。每抛一次，曲线按贝叶斯规则收紧一点：先验 Beta(α, β) ＋ 数据（H 次正面、T 次反面）→ 后验 Beta(α+H, β+T)，闭式更新，不靠模拟。先偷偷告诉你：这枚硬币其实是偏的，<strong>θ\* = 0.65</strong>——方便你看后验往哪儿收。随机抛币走带种子的发生器（mulberry32），种子写在读数里，同种子序列可复现；手动记账与随机序列分开计数——「换一颗种子」只重启随机序列，手动记账不清零。 {#s4e .explain}

::: html step4-1
priFlat: 平坦 Beta(1, 1) · 没成见
priWeak: 弱倾向 Beta(8, 8) · 觉得大概公平
priStrong: 强成见 Beta(40, 10) · 笃定偏正面
flip1: 抛 +1
flip10: 抛 +10
flip100: 抛 +100
manH: 手动记正面
manT: 手动记反面
newSeed: 换一颗种子

:::

本页不给可信区间（可信区间＝「真 θ 多半落在哪一段范围」），只给均值与最可能值——区间要对后验分布做数值积分求分位，是另一台机器；这里先把「曲线随数据收紧」看清楚。抛得越多，曲线越窄：**后验的宽度，就是你还剩多少不知道**。 {#s4hint .hint}

## 数据够多时，成见会被冲淡 {#step5 h2=s5t}

::: strings
nav5: 5 洗刷 + 频率树
:::

第 5 步 · 先验洗刷 + 频率回访 {#s5k .step-kicker i18n=text}

两个先验——平坦 Beta(1, 1) 与强成见 Beta(40, 10)——喂**同一条**抛币序列（同一种子、θ\* = 0.65）。看两条后验曲线和均值之差：n 小的时候，成见还说了算；n 拉到几百，数据把两条曲线冲到一起。**洗刷是真的，但要付数据的钱**——样本越小，先验越贵。 {#s5e .explain}

::: html step5-1
w10: 再抛 +10
w100: 再抛 +100
w600: 一口气到 600
:::

换回人话：自然频率树 {#s5treeT .sub-t tag=h3 i18n=text}

同一笔账，换一种讲法：不谈概率，只数人数。拖患病率滑杆，树上的人数与「阳性后真得病」同步重算——公式算出来的 PPV（阳性预测值——报阳性的人里，真得病的占多少），和树上数出来的人头比，一字不差。**自然频率就是贝叶斯穿上人话的衣服**：医生跟病人解释筛查结果时，应该用这棵树，不用百分比。 {#s5treeE .explain}

第 6 步 · 终章 {#s6k .step-kicker i18n=text}

贝叶斯不是一条公式，是一种记账习惯：任何新证据，先问它落在多厚的底子上，再按似然比入账。它在真实世界里到处值班： {#s6e .explain}
