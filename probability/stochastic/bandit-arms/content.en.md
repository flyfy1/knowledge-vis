Step 0 · Five machines, blind {#s0k .step-kicker i18n=text}

This step answers: five identical-looking slot machines each have a different, hidden win probability; how do you win the most in a limited number of pulls? Each press of “Pull X” pulls that machine once and a win scores 1 point. The bars are your **current estimate** of the win rate = wins ÷ pulls, and the white vertical lines are a rough error range (about 95%, very wide for few pulls). Pull each machine a few times, then decide where to spend the rest. ## Why does always pulling the current best lose out? {#step1 h2=s1t}

::: strings
nav1: 1 Explore vs exploit
:::

Step 1 · Explore versus exploit {#s1k .step-kicker i18n=text}

This step answers: is it enough to keep pulling whichever machine looks best? **Greedy** always pulls the highest estimate; with a bad start it can lock onto a second-best machine forever (it never “explores” the others). **ε-greedy** pulls a random machine with probability ε (exploring) and otherwise the highest estimate (exploiting). The chart shows average cumulative regret over 500 steps (average of 80 independent simulations; the machines’ true probabilities are 0.25 / 0.40 / 0.50 / 0.62 / 0.45). Drag ε with everything else fixed: how does the orange line change? The grey dashed line is ε = 0 (pure greedy) and the cyan dashed line ε = 0.10. Too small an ε explores too little; too large keeps wasting pulls on poor machines. {#s1e .explain}

s1eL: Exploration probability ε
s1reset: Reset
:::

Average cumulative regret = the regret curves of many simulations averaged; a flatter curve means the best machine was found sooner. {#s1term .term i18n=text}

## How can a rarely pulled machine get a chance? {#step2 h2=s2t}

::: strings
nav2: 2 UCB
:::

Step 2 · Optimism under uncertainty {#s2k .step-kicker i18n=text}

This step answers: instead of coin flips, can we decide systematically whom to explore? **UCB** (upper confidence bound) adds an “optimism bonus” to every machine’s estimate: score = estimate + c·√(2·ln t / n), where t is the total number of pulls so far and n the number of pulls of this machine. A rarely pulled machine gets a large bonus and is tried; a often-pulled one gets a small bonus because its estimate is more trustworthy. c is the exploration weight (c = 1 is textbook UCB1). Drag “pulls so far t” or press “Auto play”: the short white bar is estimate + bonus, the white frame marks the machine chosen next; the bars are estimates and the red lines are the true probabilities. Then drag c: a larger c explores more, a small c is closer to greedy. (One simulation with a fixed random seed.) {#s2e .explain}

::: html step2-1

s2tL: Pulls so far t
s2cL: Exploration weight c
s2reset: Reset
:::

Bonus c·√(2 ln t / n): larger for small n and slowly growing with t, so every machine eventually gets retried. {#s2term .term i18n=text}

## Use a distribution to express “how unsure am I” {#step3 h2=s3t}

::: strings
nav3: 3 Thompson sampling
:::

Step 3 · Thompson sampling {#s3k .step-kicker i18n=text}

This step answers: can we choose directly from “beliefs”? **Thompson sampling** keeps a **Beta distribution** curve for every machine, expressing the belief about its win probability: at first it is flat (knowing nothing, Beta(1,1)); each win adds 1 to α and each loss adds 1 to β. To choose, draw one number from every curve and pull the machine with the largest draw. Drag “pulls so far t” (or auto play): how do the curves narrow and move toward the true probabilities (short ticks at the bottom)? A machine pulled more has a narrower curve. (One simulation with a fixed random seed.) {#s3e .explain}

::: html step3-1
cv3: Beta distributions of each machine’s win probability
s3tL: Pulls so far t
s3reset: Reset
:::

Beta(α, β) = the belief about the win probability after seeing α−1 wins and β−1 losses; its mean is α/(α+β). {#s3term .term i18n=text}

Step 4 · Comparing strategies {#s4k .step-kicker i18n=text}

This step answers: which strategy is cheapest? The chart shows average cumulative regret (lower is better). One of the five machines wins with probability 0.5 + Δ and the other four with 0.5: Δ is the best machine’s advantage. Drag Δ: the smaller the advantage the harder it is to tell, so how do the curves change? Drag “total steps” and see whether the curves’ growth slows: a flattening regret curve means the best machine has been locked in. Note: UCB with c = 1 is the textbook value and over-explores over this shorter time; c = 0.3 is cheaper in this setup, but that is only what happens with this set of machines and is no guarantee. {#s4e .explain}

## Wrap-up: the trade-off between exploring and exploiting {#step5 h2=s5t}

::: strings
nav5: 5 Finale
:::

Step 5 · Finale {#s5k .step-kicker i18n=text}

The bandit problem quantifies the conflict between “try more” and “pull the best” as regret; the strategies just shrink uncertainty in different ways as pulls accumulate. {#s5e .explain i18n=text}

::: html step5-1
c1t: True probabilities are hidden
c1b: Only estimates are available, wide for few pulls; regret measures the price paid for that (step 0).
c2t: Pure greedy can lock in
c2b: A bad start may mean never trying the good machine again; ε adds random exploration (step 1).
c3t: Let uncertainty point the way
c3b: UCB boosts rarely pulled machines; Thompson sampling draws from beliefs (steps 2 and 3).
c4t: No universal winner
c4b: The constant c, the advantage Δ and the horizon all change the ranking (step 4).
modelT: Model and limits
modelB: Each machine is an independent Bernoulli event with a fixed probability; real settings (advertising, clinical trials) often have probabilities that drift, context information and delayed feedback. Regret needs the true probabilities and can only be computed in simulation. All simulations use fixed random seeds, and rankings hold only for the machine settings on this page.
:::
