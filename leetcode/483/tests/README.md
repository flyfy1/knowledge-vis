# Reproduce author self-checks

From the repository root:

```sh
OUT_DIR=/tmp/lesson-483-check python3 -B leetcode/483/tests/test_solution.py
OUT_DIR=/tmp/lesson-483-check node leetcode/483/tests/test_core.cjs
OUT_DIR=/tmp/lesson-483-check node leetcode/483/tests/test_browser.cjs
OUT_DIR=/tmp/lesson-483-check node leetcode/483/tests/test_focus.cjs
python3 -B scripts/register_leetcode_lesson.py 483 --validate-only
```

`test_core.cjs` reads the independent oracle fixtures generated by the Python test from the same output directory. Without OUT_DIR, evidence goes to this lesson's tests/evidence directory. Set NODE_PATH to the installed browser packages if needed. The browser honors PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH and PREVIEW_ROOT (default http://127.0.0.1:18770); it starts no server. The tests execute the actual Python callable and separately check the BigInt simulation. Acorn parses the dictionary to reject duplicate object keys before evaluation.

Browser checks use real headless Chromium, synthetic viewports and CSS layout zoom at 200%. They do not establish physical-device testing, browser toolbar zoom behavior, LeetCode acceptance, production deployment, independent review, or actual learner comprehension. Official public GraphQL evidence is retained in official.json; this is a dated capture, not a runtime dependency. Screenshot visual inspection is recorded in ../SELF-CHECK.md.
