## First-use terms and dependencies
Step 0: itinerary = airport sequence; lexical order = first unequal fixed-width airport code decides. Step 1: graph = airports with directed ticket edges; Euler trail = uses each edge once; baseline backtracking = try one unused ticket and undo on failure. Step 2: stack = active exploration trail with last entry on top; postorder/finished = append airport only after outgoing tickets exhausted; invariant = property retained after every action. Terms redefined locally at steps 3/4. Ticket IDs distinguish duplicates. No chart axes: rows are original ticket identities; badges name remaining/used state. Lists show bottom→top and first→last append order.

Simulation is JavaScript state snapshots, not Python execution. E push actions plus E+1 pop actions; all states retained for teaching, potentially quadratic storage. Canonical Python only keeps adjacency, stack, finished O(E). Preset change resets trace only; language preserves all state; prediction change clears feedback. Reset restores complete initial trace; no timers. Copy failure exposes selected source; storage failures use common locale memory fallback. Empty/loading/reconnect states inapplicable: local synchronous data only. Start/end disable truthful controls. Both locales cover push/pop/start/completion, all guesses, copy success/failure, hidden/revealed hand answer. Tests validate snapshot conservation and final route against independent permutation/backtracking oracle.
