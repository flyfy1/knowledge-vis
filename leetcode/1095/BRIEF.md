## Correctness, costs, simulation
Peak loop lo<hi ensures m+1<=hi<n. A rising edge cannot be at/right of peak, so p>m; a falling edge implies p<=m. Both retain p and strictly shorten interval; singleton is peak. Ascending [0,p] and descending [p+1,n-1] are strictly ordered; equality unique within each side; smaller-than-target keeps right on rising side, left on falling side. Every discarded index is unequal; empty range means absent. Search left first, so any found left index is globally minimal. No plateau allowed, though values can repeat across sides. Each loop halves its range; n<=10000: peak <=14 comparisons at2 calls, each side <=14 at1: at most56 get calls. Canonical time O(log n), auxiliary space O(1), no input mutation/caching. Baseline scan O(n) calls, O(1) space; correct but n may exceed100.
