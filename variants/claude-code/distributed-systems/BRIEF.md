## 定位

- category `computing`，subtopic `systems`，stage `university`（与原版一致）。
- 受众：大学低年级；知道概率的乘法和「从 n 个里选 k 个」，不要求学过分布式系统。
- 一句话直觉：**副本靠「数数」才能像一个值：写等 W 个、读问 R 个，W + R > N 就一定读到最新；代价是宕机时的可用性，而网络分区时一致和可用只能选一个。**
- 与原版的差异（设计选择）：同样以版本化寄存器为模型，但本版把「为什么 W + R > N」落到可数的组合（热力图上每格的陈旧读概率），再用 200 次模拟让实测比例收敛到公式；可用性一步用二项和精确计算并画成对数刻度的不可用概率；分区一步用固定脚本对照 CP 与 AP 的后果（拒绝 vs 丢写）。

## 模型、模拟设定与失配

- `model.js`（浏览器与 node 共用）：`write0`、`staleProb`、`simulate`（mulberry32 定种子）、`atLeast` / `availability`（二项和）与 `availabilityBrute`（2ᴺ 枚举，测试用）、`partition`（固定脚本）。
- 失配（页面 s5 明说）：单协调者编号，不处理并发写者；无读修复与反熵，陈旧率是上限；W + R > N 只保证读到最近一次成功写入，不是线性一致性，不涉及 Raft / Paxos；宕机独立假设。

## 数值结论与测试（`tests/core.cjs`）

- 第 0 步：32 种送达组合下只有送到的副本改变、陈旧比例 = 未送达 / 5；默认 3/5。
- 第 1 步：N = 3..9 全部 (W, R) 上公式 = 枚举全部读集合的结果；为 0 当且仅当 W + R > N；最小重叠 = W + R − N；默认 30%，热力图最大 89%。
- 第 2 步：全部 (N, W, R) 上每次读的陈旧判定 = 读集合是否错过写集合；最新版本恰在 W 个副本；W + R > N 永不陈旧；2 万次长跑在 4 个标准误内贴近公式；默认 200 次落在 30% ± 7%。
- 第 3 步：N = 3..9、p = 1..30% 全部格点上二项和 = 2ᴺ 枚举；W 增大写可用降、读可用升；让较差者最好的 W 恰为多数派（N 偶数时两个并列）；默认 99.144%、约 75 小时 / 年。
- 第 4 步：k = 1..4 两种模式：CP 恰一侧接受、无丢失、读数一致、少数派拒读；AP 两侧都接受、读数 200 / 50 不同、修复后留 50 丢 200；修复后副本一致。
- 双语：键集与占位符一致、中英不同、无「左图/右图」；HTML/app 的键与动态键存在；深链目标与锚点存在；对照链接存在；有 provenance 占位、未引入 canvas-label-guard。
