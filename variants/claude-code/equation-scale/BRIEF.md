## 定位

- category `math`，subtopic `algebra`，stage `primary`（与原版一致）。
- 受众：小学高年级到初一预备；会整数加减乘除，知道「平分」「几倍」。不要求见过字母表示数。
- 一句话直觉：**天平平着 = 两盘一样重 = 等号；对两盘做完全相同的事，天平不倒；用这一招把一个袋子单独留在一边，另一边的颗数就是 x。**
- 与原版的差异（设计选择）：
  - 未知量是「封好的袋子里有几颗弹珠」：袋子不计重量，重量单位就是「1 颗」。这样 x 是一个**计数**，和散弹珠同单位，「两边各拿走 1 个袋子」也成立（第 5 步）。
  - 第 0 步加了一条「试过的颗数」数轴，记录每次试称是哪边重，平衡点被左右两色点夹出来（交互规则 1：呈现历史）。
  - 第 4 步特意选了 3x + 2 = 14（不能先平分），让「先减后除」的理由在按钮可用性上直接看见，而不是背顺序；另两题两种顺序都通。
  - 增加第 5 步「两边都有袋子」（3x + 1 = x + 9），把同一招推广到原版没覆盖的情形。

## 模型与判定口径（`model.js`）

- 唯一状态 `{a, b, c, d}`：左盘 a 个袋子 + b 颗，右盘 c 个袋子 + d 颗；方程 a·x + b = c·x + d。
- `weigh` / `isBalanced`（严格相等，容差 0）/ `heavier` / `tiltDeg`（每差 1 颗 4°，钳在 ±14°，**只用于画图**，文案在第 0 步图下和第 1 步读数旁两次说明是示意）。
- `applyOp`：两边同加同减（颗或袋）、同乘、同除（只允许 `divisors` 给出的整除数），以及两个故意的错误操作（只动左盘）。拒绝时返回原因键：`needMarbles`、`needBags`、`notEven`、`tooMany`（每盘最多 6 袋、24 颗）、`emptyPan`，页面照原因说明「这一步没有做」。
- `isolated`（袋子单独在左盘或右盘）、`isolatedValue`、`solve`、`exprString`、`substitute`（代回验算的逐项算式）。
- 未知数的值在揭晓前不进 DOM：第 0 步只说哪边重；第 3–5 步读数只给盘面组成，结论节点在袋子单独留下之前不存在；终章三式用的是另外三道方程，不剧透第 3–5 步（测试钉住）。
- 模型失配（终章 boundary 明说）：理想天平，差 1 颗就算不平；只有正整数；不处理负数、分数答案和两边袋子一样多的情况。

## 数值结论与测试（`tests/core.cjs`）

- 精确平衡、倾斜方向与钳幅；第 0 步三个袋子在 0–15 颗内都能称出，哪边重的翻转点恰在 x。
- 不变性：400 组随机平衡状态 × 10 种两边操作，合法时平衡保持；不平衡的状态做两边操作仍不平衡（s1hint 的说法）；只动一边必倒。
- 拒绝原因五种各有一例；第 2 步文案里的 x + 2 = 5 → 2x + 4 = 10 → x + 2 = 5、3x + 6 = 15 与「×3 盘满」由模型推出。
- `divisors`、`isolated` 的典型值；六道题答案为正整数且起始平衡；用页面按钮集合做广度优先搜索，最少步数为 1、2、2、2、3、3（标题「一步/两步」与此一致）；第 4 题 1 不能先平分、第 2 题两种顺序都得 5；第 5 步第一步得 2x + 1 = 9。
- 自测两题答案 = `solve`，选项四个不同；解析里的算式与模型一致；终章三式正确且不含第 3–5 步的题。
- 双语：键集与占位符一致、非符号键中英不同、页脚含模型 id、全文无「移项」；HTML/app 引用的键都存在；深链目标页与 `#stepN` 锚点存在；占位注释与 page-provenance.css 在。
