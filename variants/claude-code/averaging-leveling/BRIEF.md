## 定位

- category `math`，subtopic `data`，stage `primary`（与原版一致）。
- 受众：小学中高年级；会整数加减乘除，见过简单分数、小数。
- 一句话直觉：**平均数是“倒匀以后每份多少”**：倒来倒去总量不变，所以平均数 = 总量 ÷ 个数；高出平均数的总和 = 低于平均数的不足总和。
- 与原版的差异（设计选择）：原版按“倒水守恒 → 移多补少 → 总数÷杯数 → 除不尽 → 极端值”展开。本版保留“倒”的主线，但把“除不尽”并入第 2 步（结果可为小数/分数），新增两个“用处”步骤：第 4 步人数不同的两队比平均数而不比总数；第 5 步已知平均数倒推缺的那一杯（平均数 × 个数 = 总量）。每一份都按原杯着色，看得出它去了哪里。

## 模型、设定与失配

- `model.js`（浏览器与 node 共用）：`pour`、`levelPlan`（最多→最少逐份倒）、`excess` / `shortfall`、`meanFrac`（精确分数）、`step3` / `step4` / `step5`。
- 全部数据都是为讲道理编的示意数，不是调查（终章明说）。
- 失配：第 0、1、5 步只能整份倒；第 2 步把果汁当成可无限细分；平均数不反映离散程度（终章举 4,4,4 与 0,4,8）。

## 数值结论与测试（`tests/core.cjs`）

- 第 0 步：2000 次随机倒水总量恒为 16；同杯/空杯/满杯给出对应原因；份数始终在 0..10。
- 第 1 步：三组预设平均数 4、5、6（整数），逐份倒到全部相等；所需份数 = 起始高出份数（4、5、5）；每个中间状态高出 = 不足，且每次恰好减 1。另用 300 组随机数据验证“只有在平均数处高出 = 不足”。
- 第 2 步：n = 2..6 的总量 8、15、18、27、31 与平均数 4、5、4.5、5.4、31/6，以及分数表示。
- 第 3 步：x = 0..20 平均 = (20+x)/5，变化 = (x−5)/5，始终在最小与最大之间；x=20 时 4 杯低于平均。
- 第 4 步：x = 0..10 时乙总数 > 甲总数且乙平均 < 甲平均；乙平均上升 ⇔ x > 6。
- 第 5 步：需要份数 = 4t − 16；可行 ⇔ t ∈ 4..7；正好时平均 = 目标；s5e 的“少 3 格、多 1 份”。
