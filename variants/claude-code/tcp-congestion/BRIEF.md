## 定位

- category `computing`，subtopic `systems`，stage `university`（与原版一致）。
- 受众：大学低年级；知道比特 / 字节、毫秒，不要求学过计算机网络。
- 一句话直觉：**一次传输拆成几件各管一事的问题：切包付头部、时间 = RTT + 大小 ÷ 带宽、确认与重发保证不丢、窗口 ≥ BDP 才填满链路，而发送方只靠丢包信号用 AIMD 摸索窗口，并因此和别的流趋于平分。**
- 与原版的差异（设计选择）：原版的路由一节在这里改成终章链接；本版把重点放在拥塞控制的因果链上：窗口 → 带宽时延积 → 排队与丢包的「拐点和悬崖」→ AIMD 锯齿 → 两条流的公平性（相平面）。

## 模型、模拟设定与失配

- `model.js`（浏览器与 node 共用）：`packetize`、`fetchTime`、`conversation`（握手 + 3 段停等，可丢第 2 段）、`schedule` / `windowRate`、`bottleneck`、`aimd` / `aimdStats`、`twoFlows`。全部是确定性的教学模型，没有随机数。
- 失配（页面 s7 明说）：不计选项、TLS、链路层帧头；停等只为看清消息；真实 TCP 有累积确认、快速重传、按字节计窗口；拥塞控制按轮计算且丢包规则固定；CUBIC、BBR 等不在范围内。

## 数值结论与测试（`tests/core.cjs`）

- 分包：全部滑杆格点上包数公式、末包、线上字节；MTU 增大占比不升；默认 45 包 / 末包 1296 / 头部 1800 / 2.67%；文件翻倍包数翻倍（±1）、占比变化 < 0.4 个百分点（≥ 16 KB）。
- 时间：全部格点 T = RTT + 大小 ÷ 带宽、T ≥ RTT、翻倍省 tx/2；网页 100 Mbit/s 等待 > 95%；视频 RTT 占比 < 0.2%；带宽滑杆 1/10/100/1000。
- 握手：消息数 8 / 9；ack = x+1、y+1；数据段连续、ack = 下一个想要的字节；状态顺序；完成于 4 RTT、首个数据 1 RTT；丢包完成于 6 RTT、多 2 RTT、重发恰在 RTO 之后；图高 6 RTT。
- 窗口：全部格点 BDP、吞吐 = min(C, W·L/RTT)、满载当且仅当 W ≥ BDP；绘制的发送时间线长期速率与公式一致（±2%）；默认 2 Mbit/s、20%、每包 1.2 ms。
- 排队：全部格点包数守恒、三段行为、RTT = RTT₀(1 + 排队/BDP)；坐标范围（75%、180 ms）。
- AIMD：每轮规则（翻倍 / +1 / 减半）、丢包当且仅当 cwnd > BDP + B；B ≥ 50 利用率 100%、B < 50 不足 100%；B = 0 锯齿 25–51、利用率 76.7%；B = 50 RTT ×1.52；慢启动 1→64。
- 两流：AIMD 7 次丢包、差距逐次 56/2ᵏ；AIAD 差距恒 56。
- 双语：键集与占位符一致、中英不同（协议字段除外）、无「左图/右图」；HTML/app 的键、消息与状态键存在；深链目标与锚点存在；对照链接存在；有 provenance 占位、未引入 canvas-label-guard。
