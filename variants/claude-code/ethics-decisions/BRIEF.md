## 模型、模拟设定与失配

- `model.js`（浏览器与 node 共用）：`summary`（每组负担、合计、平均、最重一组）、`score`、`ranking`、`winner`、`sweep`（沿一个假设扫描 + 二分求翻转点）、`margins`、`meanLine`/`crossP`。
- 设定（全部虚构）：三片住区 500/100/400 户；市区每年被淹概率 p，河岸 2p（滑杆 1–4 倍），山坡 0.3p；被淹损失 100 千元；方案费用 2000/2500/5000 千元/年，全城平摊；A 减市区损失 90%（滑杆 50–100%），B 每户减 40%，C 让河岸搬走、蓄洪公园减市区损失 30% × 搬走比例；搬迁损失 8 千元/户/年（滑杆 0–20）。
- 模型失配（页面 s6 明说）：负担只算能折成钱的部分；搬迁损失是规划者的猜测；得分只是最简单的分配规则；自愿搬迁者的搬迁损失仍按规划者估计计入；不提供道德、法律或政策建议。

## 数值结论与测试（`tests/core.cjs`）

- s0e 里的每个设定数字与模型常量一致；滑杆范围与文案一致。
- 负担 = 三项之和；全城合计 = Σ 户数 × 负担；平均 = 合计 / 1000；不作为时 10/20/3。
- 第 1 步：平均负担是 p 的直线、截距 = 费用分摊（C 另加搬迁）；不作为/A 交点 = 2/45 ≈ 4.44%，两侧大小关系；任意 p、规则、q 下 C 都不是平均最低。
- 第 2 步：A 下河岸负担恰比不作为多 2（任意 p、eA、mR）；凡 λ = 0 时 A 第一，λ < 0.4 前就让位；默认 p 下顺序 A → B → C。
- 第 3 步：只看账本时平均与最重负担与 q 无关、被迫户数 = 100(1 − q)；规则开时 p ≥ 5% 下留下户是最重一组且随 q 单调上升；q = 1 两版数字相同。
- 第 4 步：甲乙同 p、甲丙同 λ；两种规则、所有 q 下甲第一 A、乙第一 B（小测）；规则开且 q < 1 时 C 在整张地图上都不第一；翻转点两侧的第一名与报告一致，未报告翻转的方向全程不换。
- 第 5 步：条带分段首尾覆盖范围、每段中点的第一名与颜色一致；改河岸倍数会移动 p、λ 行的交界。
- 双语：键集与占位符一致、非符号键中英不同、无「左图/右图」；HTML/app 用到的键都存在；深链目标与锚点存在；对照链接存在；未引入 canvas-label-guard。
