## 定位

- category `probability`，subtopic `inference`，stage `senior`（与原版一致）。
- 受众：高中生；会百分数和分数，学过（或正在学）条件概率的记号最好，但页面当场解释「|」。
- 一句话直觉：**拿到结果 = 换分母。** 阳性报告把你放进「全部阳性的人」这一列；后验就是在这一列里数病人。罕见病时健康人基数大，小误报率也能造出比病人还多的阳性。
- 与原版的差异（设计选择）：开头先让读者凭直觉猜（第 0 步），再用 1000 个圆点（颜色 = 真实状况，实心/空心 = 检测结果，双重编码不靠颜色单独区分）逐步拆解；第 3 步把人群「按结果重排」并框出分母；第 4 步专门对比两句话的分母（行 vs 列）；第 5 步加「再测一次」，用赔率 × 似然比解释为什么第二次阳性推高得那么快，并点明独立性假设。

## 模型、设定与失配

- `model.js`（浏览器与 node 共用）：`counts`（期望人数与 PPV/NPV）、`ppvFormula`/`npvFormula`（只用概率的贝叶斯式，对照 counts）、`roundedCells`（圆点图取整，每行保持合计）、`lrPos`、`odds`、`repeatRounds`。
- 人数是 1000 人中的**期望人数**，不是一次随机抽样；圆点按每格四舍五入（误差 ≤ 0.5 人）。
- 第 5 步假设各次检测条件独立；页面明说同一种检测重复时误报原因可能重复，真实证据更弱。
- 本页不是临床计算器（boundary 明说）。

## 数值结论与测试（`tests/core.cjs`）

- 全部滑杆格点（患病率 60 档 × 灵敏度 51 档 × 特异度 51 档）：四格和 = 1000；counts 的 PPV/NPV = 贝叶斯式；阳性抬高、阴性降低（检测有信息时）；赔率式成立；圆点取整误差 ≤ 0.5 人且合计 1000。
- 默认场景：20/18/2/49/931、阳性 67、PPV 26.9%、误报多于病人、默认猜测 80% 判为「偏高」、抬高倍数在 10–20 倍之间（「十几倍」）。
- 提示里的数：0.5% → 5 个病人；特异度 99% → 约 10 个误报；灵敏度不动健康人行；30% 时 P(病 \| 阴性) 为几个百分点；PPV 随患病率单调上升。
- 第 4 步：行比例恒为灵敏度；两数相等当且仅当分母相等；判断题 9.0%、约 90 倍、0.99/9.99/10.98。
- 第 5 步：26.9% → 86.9% → 99.2%；似然比 18，特异度 80% 时 4.5；赔率 = 先验赔率 × LR^k；后验 = 下一轮先验。
- 格式化：`fmt(90, 0)` 仍是 `90`（只在有小数点时去尾零）。
- 双语：键集与占位符一致、非符号键中英不同；无「左图/右图」；HTML/app 用到的键都存在；深链目标与锚点存在；对照链接目标存在。
