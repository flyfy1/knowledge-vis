## 定位

- category `computing`，subtopic `algorithms`，stage `university`（与原版一致）。
- 受众：大学低年级，会写函数、知道 log₂；不要求学过算法分析或主定理。
- 一句话直觉：**递归的成本就是递归树的形状**——每层缩小多少决定层数，每层花多少决定总账；子问题重叠或切得太偏会让树变大。
- 与原版的差异（设计选择）：原版用阶乘、汉诺塔、递归树三种形状和归并排序执行顺序。本版不用汉诺塔：
  - 用同一个 3ⁿ 的两种写法对比「减 1」与「减半」的深度；
  - 用参数化递推式 T(n) = a·T(n/2) + n^d 在递归树上逐层记账，看哪一层主导；
  - 补上两个常见坑：重叠子问题（斐波那契、记忆化）和切得不均（快速排序式的固定比例切分）。

## 模型、设定与失配

- `model.js`（浏览器与 node 共用）：`linearTrace`（逐事件栈快照）、`halvingCost`/`linearCost`、`mergeTrace`（结点、事件、每事件状态）、`mergeWorst`、`treeLevels`/`predicted`、`fibCalls`（真跑递归计数）/`fibCountsFast`（同计数的线性算法，n 到 40）、`splitCost`/`splitTable`/`splitRows`。
- 第 2 步数组用 mulberry32 种子 1–50 生成，值 1–99。
- 失配（页面 boundary 明说）：不计真实时间、缓存与调用开销、尾递归优化；第 3 步规律只适用于 a 份 n/2 且 n 为 2 的幂；第 5 步 p 人为固定；栈容量有限。

## 数值结论与测试（`tests/core.cjs`）

- 第 0 步：n=0..10 事件数 2(n+1)、最深 n+1、乘法 n、值 3ⁿ、深度曲线是单峰、峰顶为 pow(0)。
- 第 1 步：n=1..1024 减半帧数 = 二进制位数 + 1，乘法 = 位数 + 1 的个数；n 翻倍帧数 +1；BigInt 验证减半递归算出 3ⁿ 与位数；1023 → 11 帧 20 次（全滑杆最大），1024 → 12 帧 12 次（文案引用值由测试钉住）。
- 第 2 步：8! 种排列穷举，最坏 17（= 公式）、最好 12；种子 1–50 排序正确、22 个事件、4 行、调用栈最多 4 层、左半边归并完成才进入右半边、每次归并比较次数介于短的一半与 len−1。
- 第 3 步：a×d×m 全网格每层合计之和 = 直接递推；相邻层比 = a/2^d；主导层判断；m=9→10 比值变化 < 6%、比值 ∈ [1, 4]；归并每层 = n、Karatsuba r=1.5、四块 r=2、a=1/d=2 顶层占一半以上。
- 第 4 步：n ≤ 22 快速计数 = 真跑递归；n=2..40 调用 = 2·fib(n+1)−1、fib(1) 被调用 fib(n) 次、记忆化 2n−1 且每柱 ≤ 2、增长比 ≈ 1.618（±0.005，n ≥ 20）。
- 第 5 步：表 = 记忆递归；冰柱行数 = 深度；p=0 时 n(n−1)/2、深度 256、翻倍 ×4；p>0 时翻倍 ×2.2–2.3、深度 ≤ 64、C(256)/2048 < 2.6；p 越小曲线越高。
- 双语：键集与占位符一致、中英不同、无「左图/右图」；HTML/app 用到的键都存在；深链与对照链接目标存在；不引入 canvas-label-guard。
