# #982 — original contract and provisional teaching risks

[Official problem](https://leetcode.com/problems/triples-with-bitwise-and-equal-to-zero/).
[Access evidence](982-official-access.json); original response bytes are saved separately.

## Verified original contract

`nums` has 1–1000 integers, each in `[0, 65535]`. Count ordered index triples
`(i,j,k)` whose three selected numbers have bitwise AND zero. Every index ranges
independently over the entire array: repeated indices and duplicate input values
are allowed. This is not a distinct-index combination count.
Official examples are `[2,1,3] -> 12` and `[0,0,0] -> 27`.

Python3: `Solution.countTriplets(self, nums: list[int]) -> int`.
TypeScript: `countTriplets(nums: number[]): number`.
Both are supported; Python needs no language exception. Keep the input array and
index identities visible rather than substituting a set of distinct numbers.

## Concrete examples and invariants to derive

These are dispatcher analysis, not an authored lesson or acceptance evidence.

- Begin with `[1,2]`: the eight ordered triples include six with both values,
  which yield zero; the all-1 and all-2 triples do not. A two-bit display explains
  AND without requiring readers to understand masks beforehand.
- `[0,1] -> 7` shows that any selected zero makes the conjunction zero, while
  three selections of 1 fail. `[0] -> 1` makes repeated indices unavoidable.
- Values `3,5,6` demonstrate a useful wrong-turn counterexample: all three pairwise
  ANDs are nonzero, yet `3 & 5 & 6` is zero. Requiring a zero pair loses valid
  triples. A logical truthiness test likewise differs from bitwise AND.
- If grouping ordered index pairs by their AND result, the proposed invariant
  is that each histogram bucket counts actual ordered pairs, including equal
  indices; bucket counts must sum to `n²`. Then combining a bucket with a third
  index must retain that bucket's multiplicity. Counting distinct masks alone
  loses information. Associativity motivates grouping but is not a speed claim.
- All-zero input has `n³` valid triples; all equal nonzero values have none.
  Include 65535 and bit 15, so a tiny teaching display cannot silently redefine
  the original 16-bit domain. At maximum length the count can be 1,000,000,000.

## Correctness is separate from Python cost

Pair counting followed by scanning every distinct pair mask for every third
element has a bound `O(n² + n·min(n²,2^16))`; the second stage can approach
65,536,000 checks. A 65,536-bucket dense scan has the same worst-case scale.
Do not call either automatically fast enough or accepted without measuring the
actual Python submission and representative high-mask-diversity inputs.

Enumerating submasks of the third value's 16-bit complement can also perform
65,536 iterations when that value is zero. Repeating that query for many zeros
repeats the work. Frequencies/caching help repeated values but do not by themselves
prove an attractive bound for every input. Submask loops must include zero exactly
once and terminate; Python's unbounded negative `~x` requires an explicit finite
mask before any complement-based enumeration.

**Provisional explainable optimization to assess:** a subset-sum table (often
called SOS DP) over the pair histogram. For a third value `x`, a pair mask is
compatible precisely when its set bits lie in the bounded complement of `x`.
Precomputing the sum of pair counts over all submasks therefore answers that
query directly. The author would need to derive the table's processed-bit
invariant and show a tiny two/three-bit hand table before generalizing to 16 bits.
The proposed bound is `O(n² + 16·2^16 + n)` time and `O(2^16)` extra space;
the transform has 16×65,536 mask visits, with updates only where that bit is set.
Value-frequency aggregation can weight queries by occurrence count and optionally
weight pair generation by `freq[a]·freq[b]`, including the `a == b` case.
This is a candidate design direction, not a supplied implementation, performance
measurement, required algorithm, or proof that an online judge accepted it.

## Focused future review checks

Use a direct triple enumeration on tiny arrays as an independently structured
numerical check. Check pair-histogram totals, zero-mask multiplicity, equal-index
triples, repeated values, high bits and bounded complements separately. If a
transform is chosen, compare its entire tiny-domain table against direct submask
sums before comparing final answers. Exercise maximum-length Python behavior with
the actual chosen structures; small-oracle agreement is not resource evidence.
Keep masks, counts and original indices distinct in the trace and code mapping.
Any reduced-size visual display must explain its presentation limit while the
canonical input contract remains unchanged. No code or oracle is implemented here.
