# #987 — original contract and provisional teaching risks

[Official problem](https://leetcode.com/problems/vertical-order-traversal-of-a-binary-tree/).
[Access evidence](987-official-access.json); original response bytes are saved separately.

## Verified original contract

The input is a nonempty binary tree with 1–1000 nodes and values in `[0,1000]`.
Assign the root `(row,col)=(0,0)`. A left child adds `(1,-1)`; a right child adds
`(1,+1)`. Return columns from left to right, each ordered by row and then by value
when row and column coincide. Preserve every node, including duplicate values.

Python3: `Solution.verticalTraversal(self, root: TreeNode | None) -> list[list[int]]`.
TypeScript: `verticalTraversal(root: TreeNode | null): number[][]`.
The optional root annotation does not broaden the statement's nonempty constraint.
The UI may expose the original level-order serialization with `null` gaps, but the
submission receives a `TreeNode`, not an array of coordinates.

Official examples:

- `[3,9,20,null,null,15,7] -> [[9],[3,15],[20],[7]]`.
- `[1,2,3,4,5,6,7] -> [[4],[2],[1,5,6],[3],[7]]`.
- `[1,2,3,4,6,5,7]` has the same output as the preceding example.

## Concrete examples and invariants to derive

These are dispatcher analysis, not an authored lesson or acceptance evidence.

- Start with `[3,9,20]`: explicitly assign coordinates and group the three columns
  before introducing a collision. “Vertical” means these derived columns, not
  horizontal screen position or binary-search-tree ordering.
- The two full-tree official examples differ in the encounter order of values
  5 and 6 at coordinate `(2,0)`. Their shared output exposes why left-first BFS,
  DFS or stable insertion order cannot settle this tie. Value decides the order.
- A fresh row-priority example is `[9,2,3,null,1,4,null]`: column zero must be
  `[9,1,4]`, because the root precedes deeper values even though 9 is larger.
  Sorting a whole column by value would be wrong; sorting by `(col,row,value)`
  is a candidate strategy the author must relate to the original contract.
- `[0,0,0,null,0,0,null]` yields `[[0],[0,0,0],[0]]`. The two deeper zero nodes
  share a coordinate and a value, yet both remain. Their relative identity order
  is unobservable in the required output; inventing an identity tie-break is
  unnecessary. A set or one-cell-per-coordinate map would drop valid occurrences.
- A proposed traversal invariant is that every discovered node has its correct
  path-derived coordinate and occurs exactly once in the collected records.
  A separate output invariant must explain column order, row priority and local
  value ties. Traversal discovery order and output order serve different purposes.

## Code-level and review risks

Do not confuse this contract with variants that preserve BFS encounter order for
ties. Compare rows numerically before values, retain negative column indices,
and keep duplicate node identities in intermediate displays. Values are labels,
not unique keys. Avoid lexicographic string sorting of coordinates or values.

The original tree serializer needs correct `null` handling: array index arithmetic
for a dense heap is not a substitute for ordinary queue-based sparse level-order
construction. Invalid interactive inputs should not silently be repaired into a
different tree. A skewed 1000-node tree is within scope; assess the actual Python
recursion limit and chosen traversal rather than assuming recursive DFS always
survives. An iterative traversal can avoid that particular stack dependency.

If collecting all coordinate records then sorting is selected, derive `O(n log n)`
time and `O(n)` auxiliary/output scale from the actual structures, including any
traversal stack/queue. Do not claim linear behavior merely because traversal is
linear. An independent tiny-tree coordinate table can check intermediate records
and tie groups; distinct traversal mechanisms should agree on final output.

Future review should cover a singleton, skewed chains, sparse `null` input,
same-row/column unequal values in reversed encounter order, equal-value collisions,
and a shallow large value above a deeper smaller value. UI progress should show
why a node enters a column before revealing sorting; locale changes and backwards
steps must preserve node identity and tie groups. No renderer, canonical solution,
proof, serialization code or oracle is implemented here.
