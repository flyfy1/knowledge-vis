## Original contract

Given a binary array, one operation toggles every bit in a contiguous length-`k`
window. Return the minimum operations needed to reach all ones, or `-1` if
impossible. The statement specifies binary values; length is 1–100,000 and
`1 <= k <= len(nums)`. Python3:
`Solution.minKBitFlips(self, nums: list[int], k: int) -> int`.
Public metadata agrees; TypeScript is also returned. There is no extra limit on
the allowed number of operations. An operation toggles bits; it does not set them
to one. Official outputs: `[0,1,0], k=1 -> 2`; `[1,1,0], k=2 -> -1`;
`[0,0,0,1,0,1,1,0], k=3 -> 3` (starts 0, 4, 5).

## Distinguishing examples and review questions

`check-examples.py` uses breadth-first search over literal binary states. Every
edge directly toggles one legal window; shortest distance gives the small-case
minimum independently of a greedy/lazy implementation. It checks all official
examples and these original cases, without making a full-input performance claim.

| Input | Answer | What it distinguishes |
| --- | --- | --- |
| `[0,1,0], k=2` | 2, starts 0 then 1 | `[0,1,0] -> [1,0,0] -> [1,1,1]`; overlapping flips can restore an original one |
| `[0,0,0], k=2` | -1 | Greedy progress does not itself establish feasibility of the remaining suffix |
| `[0,0], k=2` | 1 | A window ending exactly at `n` is legal |
| `[1,1], k=2` | 0 | Already complete; no unnecessary operation |
| `[0,1], k=2` | -1 | With `k=n`, a mixed array cannot become all ones |
| `[0], k=1` | 1 | Smallest input; for `k=1` the answer is the number of zeros |

A provisional direction is left-to-right forced decisions with active flip
parity. A proof needs the ordering step: toggles commute and repeating one start
twice cancels, so a minimum solution needs each start at most once. Once earlier
starts are decided, the decision at index `i` is forced: later starts cannot
affect `i`, and the only undecided start that can affect it is `i`. A zero effective
bit requires starting a flip there; a one requires no flip. If the required window
does not fit, no later decision can repair that position. Authors must connect
this reasoning to their actual implementation; these notes do not select one.

For lazy parity, inspect expiration before evaluating the current bit. A flip
starting at `j` covers `j` through `j+k-1` and expires at `j+k`; equality `i+k==n`
is allowed, whereas `i+k>n` is impossible only when a flip is needed. The effective
bit is the original bit XOR active parity. Cumulative operation count, number of
active windows and parity are different quantities, including when two active
flips cancel at a position.

Literal writes to all `k` cells per operation can cost `O(n*k)` at the original
limit. Lazy expiration can make a linear scan, but workspace depends on the
actual structure: an expiration array costs `O(n)`, while a bounded queue/ring
may use `O(k)`. Do not label a length-n marker array constant space. An in-place
marker variant must explain mutation and preserve original binary input for the
visual trace. No variant is implemented or benchmarked by this preparation.

Later review should compare original versus effective bits, display each exact
window and expiration, and demonstrate the impossible suffix honestly. Check
reset/rewind restores parity and expiration state, and that the visual step cost
is not presented as the canonical algorithm's runtime. No UI, lesson, submission
or fresh reviewer acceptance is produced here.
