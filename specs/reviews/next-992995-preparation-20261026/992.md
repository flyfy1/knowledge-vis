## Original contract

Return the number of contiguous index intervals containing exactly `k` distinct
integer values. Equal value sequences at different positions count separately.
Input length is 1–20,000; both each value and `k` are between 1 and the input length.
Python3: `Solution.subarraysWithKDistinct(self, nums: list[int], k: int) -> int`.
Public metadata agrees; TypeScript is also returned. Neither an empty array nor
external `k=0` is an original input. `k` can exceed the array's actual distinct count.
Official examples return 7 for `[1,2,1,2,3], k=2`, and 3 for `[1,2,1,3,4], k=3`.

## Distinguishing examples and review questions

Direct enumeration in `check-examples.py` independently checks the official
examples and these original cases; zero-based interval endpoints are inclusive.

| Input | Answer | What it distinguishes |
| --- | --- | --- |
| `[1,2,1], k=2` | 3: `[0,1]`, `[0,2]`, `[1,2]` | Contiguous intervals, including both overlapping windows |
| `[1,1], k=1` | 3 | Count occurrences by position, not unique value sequences |
| `[1,1,2], k=2` | 2: `[0,2]`, `[1,2]` | A valid exact-k window does not imply every suffix is exact-k |
| `[1,1], k=2` | 0 | Legal `k` can exceed the actual number of distinct values |
| `[1], k=1` | 1 | Smallest legal input; internal zero-threshold boundary |

A provisional explainable direction is `atMost(k) - atMost(k-1)`: the difference
isolates exactly-k intervals. This is a review direction, not an author choice.
If used, derive why a window with at most `t` types has all `right-left+1` suffixes
valid after shrinking, and why earlier starts are invalid. That suffix-count rule
cannot be applied directly to an exactly-k window. For `[1,1,2], k=2`, the length-3
window has only two exact-k suffixes; `[2]` is not one of them.

Frequency counts must track repeated values. Removing one occurrence does not
remove a type until its count reaches zero; zero-count keys must not inflate the
distinct count. Separate helper passes need fresh state. Internal `atMost(0)=0`
is needed for original `k=1`, even though zero is not an allowed external input.
Any two-window alternative must state each window's invariant independently.

For two-pointer implementations, justify amortized movement of each boundary,
rather than inferring complexity from nested syntax. Expected constant-time map
updates can support linear scans; this is not a measured runtime result. The
maximum answer is `20000*20001/2 = 200010000`, attained by a constant-valued array
with `k=1`. Explain algorithm workspace separately from retained visual trace.

Later review should bind every displayed count to concrete interval positions,
show the original input and current inclusive boundaries, and distinguish the
current frequency table, number of types, per-end contribution and cumulative
answer. Locale/reset/rewind must not reuse stale window state. No lesson, UI,
submission, performance benchmark or fresh reviewer acceptance is produced here.
