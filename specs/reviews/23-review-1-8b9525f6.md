- Runtime line tracing of the canonical Python on the default input gives: first assignment `dummy.next: None → 0:0`; second assignment `0:0.next: 0:1 → 1:0`. This is the missing local teaching example, **not** an explanation credited to the lesson. At event 1 the emitted ledger is [0:0], but the physical chain starting there still includes its unprocessed original suffix. “Output prefix” is a logical emitted prefix, not yet a detached terminated linked list. Source preservation matters: assigning the previous tail's next does not destroy the newly selected node's successor, which is subsequently pushed.
- Actual algorithm cost is O(k + N log(k+1)): scan all k entries; linear heapify of m≤k heads; N pops and at most N successor insertions on at most m candidates. Auxiliary heap O(k), plus constant dummy/tail. No output-node allocation beyond the dummy; existing next fields are mutated. Final `tail.next=None` terminates the chain; on empty input dummy.next remains None. These claims agree with code. The baseline's O(N log N) description omits the additive scan over k empty entries; minor precision issue, since the final algorithm explicitly includes k.
