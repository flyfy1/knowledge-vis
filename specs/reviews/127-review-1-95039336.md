Correctness reconstruction from canonical source: reject absent target before queue initialization; remove the known start from the remaining dictionary; queue starts at word count 1. On removal at d, only a one-position replacement still in remaining can be inserted, at d+1. It is removed from remaining immediately, so no second predecessor can queue it. FIFO keeps all smaller-distance predecessors ahead of later layers. Hence first discovery is minimal, target removal returns that minimum, and exhausting the finite queue proves unreachable. Unchanged letters and previously discovered or unlisted candidates never add state. Distinct endpoints and nonempty dictionaries are explicit official preconditions, not untested promised extensions.

Inspected actual before/after semantics in the official browser trace: after hot, queue is `(dot,3), (lot,3)`; removing dot produces `(lot,3), (dog,4)`. Frame 3/7 shows dot removed/current, lot queued at distance 3, dog queued at 4 with parent dot, 75 checks, and three accumulated removal records. This maps directly to `popleft`, the three positions × 25 letters, `remaining.remove('dog')`, and `append(('dog',4))`. Orange border means the current removal; explicit parent/state text gives the data meaning independently of color. See `independent-390-frame3.png`.

Python cost claim is sound as an expected upper bound: at most N+1 removals, 25L replacements each, O(L) allocation/copy and first hash per candidate. Thus O(26NL²) time; live dictionary/set/queue strings and metadata use O(NL) auxiliary space. Set probe behavior is qualified as expected. The baseline really compares each unordered pair with L comparisons and stores edges, consistent with O(N²L) time/O(N²) edge-space upper bounds. Snapshot/history retention belongs to the browser simulation, not the canonical submission's cost.
