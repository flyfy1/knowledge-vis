## Executable checks, invariants and code mapping

Executed **the actual canonical Python** with `runpy.run_path`, using a separately written memoized first-burst oracle: try every surviving balloon as the next burst, multiply its current neighbors and value, remove it, recurse. This oracle uses changing lists rather than the candidate's last-burst interval recurrence.

Fresh code checks confirmed the recorded predictions: `[2,3]`→9, `[2,1,3]`→15. For the counterexample, all orders are bounded by oracle result 15; burst values 1,2,3 earns 6+6+3=15. Clarification to the preserved cold wording: **7 is the best achievable continuation after choosing 3 first**, not the score of repeatedly selecting the current largest value (that policy earns 3+2+1=6). Both disprove largest-first; this precision does not affect the optimum or cold prediction/reveal separation.

Additional actual-source checks: `[0]`→0, `[9]`→9, `[0,0]`→0, `[1,1]`→2, `[0,4,2]`→12, `[3,1,5]`→35 and `[3,1,5,8]`→167. Another 150 independently seeded cases (seed 31204, length 1..7, values 0..6) agreed with the first-burst oracle. All input lists remained unchanged. Official maximum-length closed forms passed: 300 zeros→0; 300 ones→300; 300 hundreds→298010100 = 298×100³+100²+100. Empty input is outside the official constraints, although the supplied test also checks that defensive case.

Independently reconstructed the key rendered transition on default preset `[3,1,5,8]`: at frame 4, dp[0][3] is still 0 and dp[1][3]=15 is already saved. Frame 5 completes (0,3):

- last=1: dp[0][1]+dp[1][3]+1×3×5 = 0+15+15 = 30.
- last=2: dp[0][2]+dp[2][3]+1×1×5 = 3+0+5 = 8.

Thus the cell becomes 30 and the displayed candidate identity must be 1, even though 2 is enumerated last. This maps directly to the Python `best = max(...)` followed by `dp[left][right] = best`. Width 2 has empty children initialized to zero. Every child has smaller width; increasing width therefore prepares dependencies, considers every possible last, and ends at dp[0][len(values)-1]. Padding allocates a new list, and the nested comprehension creates distinct DP rows. There are n(n+1)/2 nonempty intervals and n(n+1)(n+2)/6 candidate evaluations, giving O(n³) time; the (n+2)² table and padded list give O(n²) auxiliary space. Browser trace snapshots are separate teaching overhead, not submission storage.

An independent JS audit checked **41 completed frames** across all four presets, both fresh inputs and `[0]`, `[0,0]`, `[1,1]`: exactly one interval is completed per frame, other cells are unchanged, candidate terms use the prior snapshot's child cells, bestK attains best (ties consistently choose the last maximizer), completed counts and total interval counts agree, and final answers match the first-burst oracle. Completed zero-valued cells need not change color; the instruction explicitly directs attention to nonzero cells. `core.js`'s helper called `brute` is memoized interval DP, so it was not treated as an independent oracle.
