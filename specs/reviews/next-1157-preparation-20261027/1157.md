# #1157 Online Majority Element In Subarray

Official source: https://leetcode.com/problems/online-majority-element-in-subarray/
The archived ordinary public response is HTTP 200, Hard, free, with full content,
metadata and all returned language templates.

## Original stateful interface and constraints

Python3 class `MajorityChecker` has `__init__(self, arr: list[int])` and
`query(self, left: int, right: int, threshold: int) -> int`.
TypeScript class `MajorityChecker` has `constructor(arr: number[])` and
`query(left: number, right: number, threshold: number): number`.
Preserve construction followed by queries on that array; there is no update API.
The constructor's `null` in the official operation example is not a query result.

Array length and values are each 1..20,000. Indices satisfy
`0 <= left <= right < arr.length`; both endpoints are included. Writing
`n = right - left + 1`, valid integer thresholds satisfy `threshold <= n` and
`2 * threshold > n`. Consequently threshold is positive and exceeds half of
this particular query interval, not half of the full array. At most 10,000 query
calls are made. Return a value occurring **at least** threshold times, otherwise
-1. Array values are positive, so -1 is an unambiguous absence sentinel.

There cannot be two qualifying values: their frequencies would sum to at least
`2 * threshold > n`. Thus there is no valid-input multiple-answer ambiguity or
lexicographic tie rule. A strict majority need not reach a larger requested
threshold: frequency two in a three-element interval fails threshold three.
The threshold guarantee does not promise that an answer exists.

The oracle directly applies `Counter` to `arr[left:right + 1]`. It does not use
cancellation, a tree or occurrence lists to choose the expected answer.

For each fixture, a separate experiment records a cancellation candidate, its
unmatched balance, its actual Counter frequency, and original occurrence indices.
`bisect_right(positions, right) - bisect_left(positions, left)` equals the direct
count, including both boundaries. None of these three quantities should be
conflated: a candidate names a possible value, balance counts uncancelled copies,
and frequency counts every actual occurrence in the query interval.

## Required candidate-merge semantics, not assumed associativity

The tested merge cancels unequal residual values in pairs; equal candidates add
their balances; zero balance is a canonical empty summary. On leaves 1, 2, 3,
`merge(merge(1,2),3)` yields candidate 3/balance 1, but
`merge(1,merge(2,3))` yields candidate 1/balance 1. Therefore this summary operation
is **not associative as an exact candidate/balance pair**. On [1,1,1,2,3], valid
parenthesizations yield (1,1) or (1,3), although the actual frequency is always 3.
These are reproduced semantic examples, not findings against a live lesson.

A future implementation using such summaries must discharge these obligations:

1. Every interval summary represents a possible deletion of unequal-value pairs
   from exactly that interval, leaving its stated copies of one candidate or no
   residue. Child intervals must be disjoint and cover their parent; query pieces
   must cover the requested interval without omissions or double counting.
2. Merging valid residuals preserves that deletion interpretation: prior deleted
   pairs stay deleted, and new cancellations remove unequal pairs across the
   residuals. This invariant supplies the needed tree-composition argument;
   equality of summaries under all parenthesizations is not required or true.
3. A strict majority survives any such pair deletion. If its frequency is f in
   n values, deleting one copy and one other leaves the positive margin 2f-n
   unchanged; deleting two other values increases that margin. Hence a complete
   single-value residue must retain that majority with positive balance.
4. A qualifying value must be a strict majority under the official threshold
   constraint. The candidate, if any, must still be verified by exact occurrences
   in the original inclusive interval. Only frequency >= threshold may be
   returned. A surviving non-majority candidate must be rejected.

The small script considers all binary parenthesizations for 363 ternary arrays
of lengths 1..5, deduplicating equal summaries. Across 519 distinct summary checks
and 957 valid-threshold queries, every actual strict majority survived and exact
Counter verification produced the oracle answer. These finite checks support
those inputs; they do not replace the general deletion argument or verify an
actual segment-tree traversal. No randomized method, optimized data structure,
full-size performance, learner-facing UI or implementation acceptance is claimed.
