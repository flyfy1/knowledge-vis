Here ranks are −2→1, 0→2, 4→3. At i=0, prefix(2) reads bit[2]=2, excluding the equal 4 at rank 3. Adding rank 3 then changes bit[3] from 1 to 2. This independently explains the transition that the visible suffix diagram represents: query the old suffix, write the final original-index count, then register the current element. The maintained Fenwick invariant is `bit[k] = sum(frequency[k-lowbit(k)+1:k+1])`. An independent check verified every cell of each JS bitTrace frame on the fresh input against that interval over the post-insertion suffix. Actual complexity is O(n log n) time and O(n) auxiliary space: sorting unique values costs O(n log n) in the worst case, n query/update pairs take O(log m) each for m distinct values, and ranks/tree/output take O(m+n) storage. Sorting a new set does not mutate nums. These reasons are reviewer reconstruction; the lesson itself does not supply them.
