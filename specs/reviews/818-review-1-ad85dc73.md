Correctness reconstruction: `seen` initially contains (0,1), and every subsequently enqueued pair is recorded immediately. The queue holds complete position, speed and arrival length, with FIFO order, so no later discovery can improve that length. For example, dequeuing (3,4,2) generates A=(7,8,3), R=(3,-1,3); R's changed speed prevents it being confused with its parent. RR returns to the already seen start and is excluded; AARA and ARRA both arrive at position 2 with different speeds and both survive. This accounts for included and excluded cases and agrees with the browser's complete rows. The target condition is intentionally position-only. Integer target is not mutated; queue/set are local to each call. Repeating ARR gives a finite route with unit positive speed restored; finite BFS layers therefore eventually reach every valid target. No clipping bound is silently assumed.

Cost reconstruction: the raw baseline replays each of up to 2^d strings of length d, totaling O(D·2^D) command operations, with one O(D)-length generated tuple at a time. BFS visits each pair once, performs two candidate transitions per dequeue, and through its stopping depth has no more states than the binary command tree, giving conservative O(2^D) unit-cost time and stored-state bounds. Generating some depth D+1 successors before finding a depth D target only changes a constant factor. The lesson explicitly identifies D and qualifies growing Python integers (O(D) bits); it does not promise polynomial complexity or confuse the teaching snapshot storage with the canonical queue. No input-side mutation or hidden pruning was found.
