### Step 01 — Start with a hand-sized example
- **Question:** “how does one replacement change the neighbour constraint?”
- **Action:** Read the displayed `arr1=[1,5,3]`, `arr2=[2,4]` example and the two replacement alternatives.
- **Observable result:** It shows replacing 5 with 2 gives `[1,2,3]` in one operation, while replacing with 4 leaves `4<3` false; it defines “last value” as the rightmost processed value and states constraints.
- **Causal paraphrase:** A replacement must satisfy both neighboring inequalities; the current rightmost value is the threshold for the next value.

### Step 02 — Baseline and state
- **Question:** “why can’t we keep only one current minimum?”
- **Action:** Read the baseline and counterexample after `[1,5]`.
- **Observable result:** It contrasts cost 0 ending at 5 with cost 1 ending at 2, and says 5 cannot connect to 3 but 2 can. It states `dp[last]` is the fewest replacements for a prefix ending at `last`.
- **Causal paraphrase:** Cost alone is insufficient; preserving multiple possible last values is necessary because future feasibility depends on the last value.

### Step 03 — Sort, then try one candidate
- **Question:** “why is the replacement the smallest arr2 value that is just larger?”
- **Action:** Read the sorted/deduplicated explanation and transition equations.
- **Observable result:** It says `bisect_right` finds the first `arr2` value greater than `last`; keep `x` when `x>last`, otherwise replace with that smallest feasible `y`, merging equal outcomes with `min`.
- **Causal paraphrase:** The smallest feasible replacement leaves maximum room for later values, so larger feasible replacements are dominated for the same predecessor state.
