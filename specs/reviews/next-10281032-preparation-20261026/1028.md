# #1028 Recover a Tree From Preorder Traversal

Dispatcher-only contract reference. [Official statement](https://leetcode.com/problems/recover-a-tree-from-preorder-traversal/).
One ordinary public GraphQL response returned HTTP200, Hard, free, matching the
frozen catalog. Full original content, metadata and language templates are in
`1028-official-response.json`; exact request/hash in `1028-official-access.json`.

## Original input and interface

Input is one `traversal` string: preorder nodes are encoded by depth-many dashes
followed by a positive decimal node value. Root depth is zero. A node with one
child has that child on the left. Return the reconstructed **TreeNode root**;
the displayed level-order list is serialization, not the callable return type.
There are 1–1000 nodes and values range from 1 through 10^9. No uniqueness of
values is specified. Empty input and a sole-right-child tree are outside this
contract; negative signs and zero values are not valid token meanings.

Python3: `Solution.recoverFromPreorder(self, traversal: str) -> TreeNode | None`.
TypeScript: `recoverFromPreorder(traversal: string): TreeNode | null`.
Both templates supply the commented TreeNode definition. The nullable template
annotation does not make an empty legal input: the statement requires a node.
Preserve the original string input in a lesson; a tree editor is not its substitute.

## Small distinguishing checks

| Input string | Level-order display | Point |
| --- | --- | --- |
| `1-2` | `[1,2]` | One child is left, not right. |
| `12-34--56-78` | `[12,34,78,56]` | Read whole numbers; depth can decrease. |
| `7-7--7-7` | `[7,7,7,7]` | Values do not identify node instances. |
| `1-2--3---4-5` | `[1,2,5,3,null,null,null,4]` | Returning to depth1 selects the root as parent. |
| `1000000000` | `[1000000000]` | A ten-digit singleton is one token. |

All three official examples and these boundaries are independently forward-encoded
from explicitly written tree structures, then displayed through breadth-first
serialization. This checks the contract without supplying a recovery algorithm.

## Provisional teaching and review risks

Show the distinction between character cursor, parsed depth/value and tree node.
Dashes describe absolute depth, not a count of edges from the previous visited
node. Siblings and return across several ancestors require different parent
context; previously attached children must not be overwritten. Explain why the
sole-left guarantee resolves orientation rather than treating it as a cosmetic
layout choice. A chosen state representation must identify the ancestor at depth
D−1; repeated values cannot serve as that identity.

Preorder text and level-order output need separate labels. Rewind/reset must
restore both parsing position and the partially built tree. Invalid demo syntax
must be identified as validation behavior, not an invented official requirement.
A legal 1000-node chain can be deep enough to challenge naive recursive runtimes;
no runtime-limit measurement was performed. Also distinguish node count from
input-character count: dashes contribute to input size. No optimized algorithm,
complexity proof, maximum-input pass or candidate acceptance is claimed.
