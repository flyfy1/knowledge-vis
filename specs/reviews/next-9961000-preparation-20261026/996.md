## Original contract and interfaces

Count distinct permutations whose every adjacent pair sums to a perfect square.
Permutation identity is the resulting **value sequence**, not the identities of
equal-valued input positions. The input has 1–12 values, each from 0 through 10^9.
Official examples: `[1,17,8] -> 2` and `[2,2,2] -> 1`.

- Python3: `Solution.numSquarefulPerms(self, nums: list[int]) -> int`.
- TypeScript: `numSquarefulPerms(nums: number[]): number`.

Both templates and callable metadata are preserved in the access wrapper. No
additional graph, starting node, modulus or adjacency matrix is an original input.

## Independent tiny examples

`check-examples.py` enumerates all permutations for small inputs, deduplicates
complete tuples, then checks adjacent sums using integer square roots. It does
not reuse a proposed optimized solver or duplicate-skipping recurrence.

| Input | Count / distinct valid sequences | Distinguishing point |
| --- | --- | --- |
| `[1,1,8]` | 1: `[1,8,1]` | Equal occurrences are available twice but exchanging their labels adds no new permutation |
| `[2,2,7]` | 3: `[2,2,7]`, `[2,7,2]`, `[7,2,2]` | Repeated values are usable; compatible self-adjacency is allowed |
| `[0,0,1]` | 3 | Zero is permitted, and 0+0=0 is a perfect square |
| `[1]`, `[0]` | 1 each | No adjacent pair exists to violate the condition |
| `[1,1]` | 0 | Duplicate handling cannot manufacture an edge: 1+1 is not square |
| `[1000000000,999967841]` | 2 | Sum 1,999,967,841 = 44,721² lies near the upper sum limit |
| `[1000000000,999967842]` | 0 | The neighboring nonsquare must not be rounded into a match |

All official examples are checked too. The oracle is deliberately factorial and
only used on these tiny cases; it is not a proposed full-constraint implementation.

## Teaching and code-review risks

Keep two ideas separate: adjacent-value compatibility and remaining occurrence
counts. A compatibility graph alone does not know whether a value has already
been exhausted. Removing duplicates from the input loses required occurrences;
counting labeled index permutations without deduplication overcounts them. This
is a different output identity from ordered-index counting problems such as #982.

A provisional direction is a search over last value and remaining multiplicities,
or an index-mask DP with an explicitly justified duplicate rule. Neither is
mandated here. If sorting and skipping equal choices, explain why the skip is
local to a choice depth and must not prohibit a second equal value later in the
same path. If memoizing, last value alone is insufficient: the remaining multiset
or used-position mask affects future choices. If using labeled counts followed
by factorial division, justify the equal-label multiplicity for every value
sequence rather than presenting division as an unexplained correction.

Use an exact square test, for example checking `isqrt(sum)**2 == sum` in Python.
Do not merely test an approximate square-root display. This note does not claim
floating-point checks necessarily fail within these limits; the integer check
provides a direct auditable condition. Include zero, identical values, absent
edges, and singleton termination. A completed path contributes once, not once
per compatible outgoing edge. Backtracking must restore counts/path on every
return, and a cached count must not suppress distinct prefix multiplicities.

The naive labeled enumeration can visit 12! permutations; do not call it efficient
because the input is short. An index-mask state space has at most n·2^n states,
with transition and deduplication costs needing their own accounting. A frequency
state representation has a different bound. Any chosen optimization still needs
actual constraint checks and honest workspace accounting, separate from saved
animation history. No performance measurement is supplied here.

Preserve the original `nums` in the UI. Show remaining counts and the latest
adjacent sum/square decision, including a rejected branch and a duplicate choice
that is skipped without losing occurrences. Avoid displaying labeled copies as
different final arrays. Trace restoration and locale changes must keep path,
counts and accumulated solution count consistent. These are review questions,
not a design or source implementation injected into future author prompts.
