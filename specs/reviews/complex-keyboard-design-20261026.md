# Round9 minimal keyboard equivalent for complex coordinates

Red evidence: evidence/red-gap.json — S1/S2/S4 have no numeric editor or focusable arbitrary keyboard canvas route; native presets work but cannot set arbitrary operands.

Use one native form below each existing draggable canvas, before its presets/readouts. S1 has real/imag fields; S2/S4 add two existing-style native z1/z2 target buttons. Tab/typing/Enter or Apply updates the same S1/S2/S4 arrays and corresponding existing renderer only. ArrowUp/Down prevent native default and change only the draft by0.1; blank/nonfinite drafts give a translated error rather than silently becoming zero. No new controller, clock, persistence, tracking or learner status.

Input finite raw coordinates; existing normalizers snap each coordinate to0.1, then box-clip S1±5 and S2±4.2 or radially project S4 to |z|≤2.6. Raw inputs are not incorrectly limited to S4's output component range. A projected component need not remain on the grid. These are drawing bounds, not limits on complex numbers. Reject only invalid/nonfinite/uncomputably large input before it can enter state. Display applied actual coordinates and bilingual adjustment status.

Presets retain exact old sin/cos assignments; never normalize a preset. Applying unchanged coordinates preserves their exact values. Fields use step=any to avoid treating exact preset/projected values as native step errors. A dirty draft is presentation in the existing DOM, preserved across locale change; explicit preset/drag/a different target selection discards that draft and syncs actual state. Field aria-invalid and live status explain a rejected edit. Native forms use novalidate so custom bilingual errors are not intercepted by HTML min/max validation. Native labels,48px controls,3px focus/forced colors and stable focus; no canvas-only aria-label substitute.

Independent design approved with these numeric-domain/precision/submit/arrow/state constraints. Tests: pure complex and edit-normalizer invariants, origin/principal angle/wrap, component vs polar product, grid/projection/raw overflow, unchanged exact preset; actual all-target keyboard edits, mouse/touch parity, locale/draft/error/quiz/rotation preservation, atlas Back context, both locales/narrow/doubled text/forced colors/denied storage. Root and reviewer browser lanes run serially. Geometry→optics remains source inventory only this round.

Implementation review refinement: preserve dirty drafts when pressing the already-selected target. Use native type=button/aria-pressed groups, not a custom radiogroup or direction-key framework.
