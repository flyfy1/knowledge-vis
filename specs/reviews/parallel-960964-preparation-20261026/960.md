# #960: statement and teaching preflight

[Official problem](https://leetcode.com/problems/delete-columns-to-make-sorted-iii/).
See [official response](960-official-access.json) and [dispatch prerequisites](README.md).
This is read-only preparation, not an implementation brief, candidate or acceptance.

**Verified contract.** There are 1–100 equal-length strings, each 1–100 lowercase
English letters. A chosen set of column indices is deleted from every row. Minimize
the number deleted so characters within each remaining row are nondecreasing.
The official Python3 method is `Solution.minDeletionSize(self, strs: list[str]) -> int`.
The returned TypeScript method is `minDeletionSize(strs: string[]): number`.

Official examples return 3 for `["babca","bbazb"]`, 4 for `["edcba"]`, and 0 for
`["ghi","def","abc"]`. Preserve these exact expected results in later checks.

**Teaching pitfalls inferred from that contract:**

- Do not confuse this problem with its earlier numbered variants: rows need not
  be sorted relative to one another. The third example is the clean counterexample.
- A deletion removes the same column from every row; independent per-row edits
  are invalid. Visualize shared column selection before introducing a recurrence.
- Equality is allowed. Do not teach a strictly increasing character subsequence.
- A potential kept-column transition must satisfy every row, and kept columns
  retain original order. Inspecting only the first row or sorting columns changes
  the problem. A tiny exhaustive deletion-mask baseline can expose either error.
- Distinguish maximum columns retained from the requested deletions; one column
  is always retainable. Explain the complement instead of reporting chain length.
- If deriving a column-chain DP, make its endpoint state and all-row transition
  visible before presenting code. Separate row count from column count in costs.
