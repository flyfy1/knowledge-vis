On official example 1, frame 8: dequeued (4,4,2), child winner 2; predecessor (3,4,1) r 3→2 remains unproved. This is cat-winning evidence against one mouse exit, not a proved loss. Frame 12: current (5,3,1), winner 1; updates (5,1,2) and (5,4,2) each r 1→0, finalize 1 because every cat exit loses. Compared both table turns, before/after readouts and history. The current cell is a proved winner like other cyan cells but additionally has an orange outline and literal →; it retains its value, and rewind/replay restores the complete state. `?`, `×`, final draw 0, current processing and keyboard focus have separate meanings.

Terminal states are initialized for both turns, cat columns/parents exclude 0, and reversal uses undirected edges. Each winner is assigned/enqueued once and has a finite forcing proof; after queue exhaustion, residual reachable states have neither an own-proved winning child nor all opponent-winning children. Thus each mover can stay residual, forcing eventual repetition without either forcing a win. Reachability restriction in the browser is explicitly distinguished from full-product canonical Python, and is closed under legal nonterminal moves. Hypothetical unreachable no-move triples do not undermine the reachable start guarantee.

Verified cost from loops: initialization includes O(n²) cells and O(nE) cat-degree counting; each state's reversed edges processed once gives O(nE), dense O(n³). Valid graphs have no isolated nodes, so E≥n/2 absorbs initialization. Two arrays and the queue require O(n²) auxiliary space; parents are generated without copying the graph. Baseline rechecks O(nE) edges per round with at most O(n²) productive rounds plus the stopping round, so O(n³E) time / O(n²) space is a valid upper bound. Browser O(n⁴) whole-table snapshot storage is correctly disclosed separately. No input mutation or arbitrary move cutoff.
