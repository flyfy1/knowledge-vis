The invariant is about the instant **after expiry, before testing**: the earlier prefix is fixed at 1 and parity counts earlier windows still covering i modulo two. Selecting i never changes that prefix; skipping is safe only for an effective 1. Failure preserves the earlier prefix but leaves the current 0 pending. Browser preset C shows this: final −1, flips so far 0, index 2 current/pending, not fixed. Finite scanning ends after n tests or the first impossible required window. Cancellation permits each start to be considered once; uniquely forced starts yield minimum count, not merely a feasible count.

Actual Python allocates n+1 expiry cells, scans n positions, and performs constant work per iteration. It does not reconstruct snapshots or mutate nums. Time and auxiliary space are O(n), including initialization, even for immediate failure or all ones. The displayed baseline copies n elements and can toggle k cells at each of O(n) starts: O(nk) time/O(n) extra space; k≥1 prevents a lost scan term at a zero parameter. Legal endpoint n is stored and not scanned; the strict `i+k>n` rejection is correct.
