## Findings

### 1172-R1-F1 (required, high): invariant prose contradicts the canonical implementation

- **Location/state:** Step 1 at the reviewed revision, English and Chinese, initial page and after applying `push(9)`.
- **Reproduction:** Read the heading “Two directions, two heaps” and prose “A min-heap ...; a max-heap (stored as negative indices) ...”. Then read Step 4 code and execute `pop()`.
- **Expected:** The explanation and code should describe the same maintained state and causal mechanism.
- **Actual:** The canonical Python has `free` (a min-heap) and uses `self.stacks[-1]` plus cleanup for the rightmost non-empty stack; there is no `maxNonEmpty` heap or negative-index heap. The rendered invariant nevertheless names `maxNonEmpty` and says a max-heap is maintained. The UI’s Step 1 readouts are recomputed scans, not heaps.
- **Violated requirement:** Frozen rubric causal derivation/maintained state and visual-to-code mapping; a correct result with an unexplained or contradictory transition is a required fix.
- **Severity/owner:** High; lesson owner should rewrite both locales to explain list-tail cleanup and align labels/readouts with code, then provide a fresh candidate and review.
- **Status:** open.
