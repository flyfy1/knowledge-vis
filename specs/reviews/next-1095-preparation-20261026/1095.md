# #1095 Find in Mountain Array: source and semantic preparation

Official public statement: https://leetcode.com/problems/find-in-mountain-array/
The retained GraphQL response returned HTTP 200, Hard, `isPaidOnly: false`.
Full original templates and metadata are retained alongside the source hash.

## Original interactive contract

Python3 provides `Solution.findInMountainArray(self, target: int, mountainArr:
'MountainArray') -> int`. TypeScript provides
`findInMountainArray(target: number, mountainArr: MountainArray)` (the official
snippet does not annotate the return type). Both expose only `get(index)` and
`length()` as the MountainArray API. The submission returns the smallest matching
index or -1. The input has 3..10,000 elements; values and target are 0..1,000,000,000.
Its peak is strictly interior, and each slope is strict. Equal values may occur
on opposite slopes; plateaus, endpoint peaks and wholly monotonic inputs are not
valid mountains.

More than 100 `get` calls is Wrong Answer. This is a count of calls, including
repeated indices, not distinct queried positions. The statement does not impose
that limit on `length()`. Access must remain through the API; replacing the
callable with `(values, target)`, indexing hidden storage or assuming extra judge
methods would change the task. Retained manual metadata describes array-shaped
test input and TypeScript harness internals, including `getGuesses`; these are
not additions to the stated submission API. Templates explicitly warn against
implementing or speculating about the MountainArray internals.

## Independent observations and teaching risks

The harness alone inspects fixture arrays to compute a linear minimum-index
oracle and verify their mountain constraints. The illustrative consumer receives
an object and calls only `get`/`length`; its target parameter remains first.
It locates a peak by comparing adjacent queried values, searches the ascending
part first, and searches the descending part only if needed. This is a bounded
query-count experiment requested for preparation, not an adopted author solution.
There is no cache in this experiment.

- Official `[1,2,3,4,5,3,1]`, target 3 returns 2, not 5. A right-slope hit alone
  does not establish the minimum index.
- `[0,1,0]` covers the smallest mountain, shared endpoints, its peak, and a target
  above the peak. Peak index 1 and index n-2 are legal boundary cases.
- `[2,5,4,3,1]`, target 1 returns the right endpoint; target 0 is absent below both
  endpoints. `[0,2,4,6,1]`, target 0 exercises the left endpoint and latest peak.
- The descending search reverses its comparison direction. The peak is included
  once in the ascending interval; no valid index n is queried during adjacent
  comparisons. Strictness makes each slope's match unique.
- Visible source arrays in a future teaching simulation must not silently grant
  the submission free direct access. Any displayed query count must correspond
  to actual API calls, including repeated comparisons; local cache hits would
  require a separate distinction. This is a review risk, not a UI design proposal.

## Query limits and evidence limits

The exact experiment uses at most 14 peak iterations with two calls each, then
at most 14 iterations per inclusive binary search with one call each: a
conservative total of 56 for n <= 10,000. This bound depends on these exact
interval updates and one-read search iterations; it does not certify arbitrary
variants. No extra equality read follows the search loop.

The 21 maximum-length samples use three peak locations (1, 4999, 9998) and seven
specified targets each; the highest measured count is 51. These samples do not
exhaust all arrays or prove the bound on their own. Ten explicit tiny cases and
1,634 small-family target checks compare results with the independent oracle.
The family exhausts nonempty left/right subsets below peak values 1..4 only.

A valid length-102 mountain and absent target illustrate a linear scan reaching
its 101st call before finishing. The local double accepts 100 calls and raises
on call 101; a repeated same-index experiment crosses the same boundary. The
exception models the statement's rejection condition, not the actual private
judge implementation. Repeated `length()` calls do not increment the local get
counter. No official submission, maximum-runtime benchmark, lesson rendering,
independent learner review or publication acceptance is claimed.
