Correctness reconstructed independently:

- Every reachable speed has nonzero power-of-two magnitude ≥1. In k commands from magnitude v, the magnitude before command i is at most v·2^i; A contributes at most that displacement and R contributes zero. Thus net displacement ≤v(2^k−1). This is an upper bound on possible motion, giving a lower bound on required commands, without assuming an all-A route actually arrives.
- Facing toward the target, d>0 and q=ceil(d/v); k must satisfy 2^k−1≥q. For positive integer q the least such k is q.bit_length(). E.g. q=3 permits k=2, whereas q=4 needs k=3. At (3,4), target 6, h=1 while A reaches 7: the bound is explicitly not a route.
- Facing away, every arriving route must reverse; any A before its first R increases distance. After that R speed magnitude is one and distance is at least d. At least 1+d.bit_length() total commands are therefore necessary. Target arrival has h=0 at any speed. These arguments justify every bound branch used by Python and the small teaching simulation.
- `best[(p,s)]` is the smallest **discovered** g, not necessarily finalized distance. Both A and R edges remain. Strictly better arrivals can reopen a pair; stale heap entries are skipped before goal testing. Equal/larger g to the same pair cannot improve a suffix because the future actions are identical. This avoids any reliance on heuristic consistency.
- A complete tiny search for 3 has initial (0,1), g=0,h=2,f=2; pop it and enqueue A (1,2), g=1,h=1,f=2 and R (0,-1), g=1,h=3,f=4. Pop (1,2), enqueue A (3,4), g=2,h=0,f=2 and R (1,-1), g=2,h=3,f=5. Pop goal (3,4) and return 2 without children. Both language displays and actual Python stream reproduce this ordering.
- In target 5 event 17, the visible parent (2,2), g=4,h=2,f=6 generates R (2,-1), g=5,h=3,f=8, improving old g=6. The old g=6 entry remains and is labeled stale. This concrete update maps to `next_g=g+1`, strict comparison with `best.get`, assignment and `heappush((next_g+h,-next_g,p,s))`. The numeric state, status and previous g agree, including after rewind/replay and locale roundtrip. The supplied stream-parity check covers every actual Python pop and enqueue for 3,5,6; larger executions also encounter stale pops.
- A nonstale minimum-f goal has f=g. A hypothetical cheaper route would leave a frontier prefix with g+h no greater than that cheaper total, which must pop first. Cheaper replacement prefixes only strengthen the inequality. Therefore goal **pop**, not merely enqueue, certifies optimality. ARR repeated target times supplies a finite route. Before return an optimal frontier prefix bounds minimum f≤D, and h≥0 bounds g≤D; only finitely many binary prefixes exist up to that depth, including improved arrivals, so termination follows.

Cost and mutation: only local heap/dictionary change; the integer input is not mutated and repeated calls have independent local state. The enumerating baseline replays 2^d length-d words, totaling O(D·2^D) time and O(D) working storage when generated one at a time. For A*, Q includes every generated entry, including stale ones. Heap operations are O(Q log Q), storage O(Q); g≤D for expansions and children at depth ≤D+1 give Q=O(2^D), hence conservative O(D·2^D) unit-cost time and O(2^D) space. This remains valid with reopening because every strictly better arrival has a command-prefix witness. The explanation explicitly separates growing O(D)-bit integers/hashing and extra browser snapshots. No state/geometry/time cutoff, distance-greedy pruning or claimed polynomial bound was found.
