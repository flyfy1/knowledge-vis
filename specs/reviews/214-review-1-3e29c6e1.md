For i=3 of abac, canonical `j=pi[i-1]` initializes 1, `while` changes it to pi[0]=0 without storing pi[3], `if` fails c=a, and only then `pi[i]=j` commits zero. The UI's fallback snapshot therefore corresponds to a real intermediate Python state, and its following zero snapshot corresponds to completion. For abab at i=4, candidate ab has no proper nonempty border: length one would compare a to b, so the jump 2→0 excludes a genuinely invalid state. Match frames include the new character in the suffix; fallback frames use the old prefix ending at i−1. Source confirms that rendering implements this difference. History records old/new j, actual compared characters and pending/commit status.

Correctness depends on the unique separator and longest-border invariant. At every iteration, previously completed pi cells are valid; candidate j is a border of the processed old prefix. Any shorter extendable border must be a border of that candidate, so the fallback chain excludes no possible solution. A match extends the largest viable candidate; a mismatch at zero leaves no nonempty border. Increasing i finishes the finite string, and each fallback strictly decreases j. Final pi[-1] is the maximal palindromic-prefix length. The lower-bound proof covers m<n, m≥n and empty input. Python input is immutable and the implementation only constructs new strings/list state.

Actual cost is O(n) time and O(n) auxiliary plus output space: t has 2n+1 characters, j gains at most one per i and total decreases cannot exceed total gains. Slicing/reversal/concatenation also take linear time/space. Replay snapshots deliberately have additional storage and are explicitly excluded from the submission cost. Metadata complexity is exactly the nonempty string `O(n) time; O(n) auxiliary space and output space`.
