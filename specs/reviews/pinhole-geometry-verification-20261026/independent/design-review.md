# Round 10: straight-line slope → pinhole image ratio

## Design verdict

Adopt the bounded lesson extension, with the conditions below resolved before final acceptance. It offers a real learning task beyond a pair of links: use one straight ray's constant slope to predict where its object point lands, distinguish image size from inversion, then verify a distance-ratio prediction in the existing diagram. Reuse pinhole-camera S.s2/set2/render2, native controls and quiz state; no new simulator, model controller, animation clock or atlas inline bridge is needed. Two concepts (slope and pinhole-ratio), one application edge and a two-stop ordinary route are sufficient. Reuse the current three equal/half/double presets rather than duplicating them without a distinct question.

This is an actual-source/BRIEF-first design and science review, not a cold UI study. No Chrome or repository edits were performed. Files read: pinhole-camera and linear-functions app/i18n/index/BRIEF, pinhole style, atlas data/app/README; primary references below. ## Must hold in the implementation

1. **Use the actual coordinate convention.** Current S2 has A=(56,252−H), B=(56,252), O=(56+u,252−H/2). Pixel y points down. With the hole as origin, X right and Y up, A=(−u,+H/2), B=(−u,−H/2), and the physical screen is X=v. The top ray has slope k=−H/(2u), so Y′A=kv=−Hv/(2u). The other endpoint is +Hv/(2u). Hence the signed endpoint difference h_s=Y′A−Y′B=−Hv/u and M=h_s/H=−v/u, while the existing positive image size remains h=|h_s|=Hv/u. Do not label the top point's ordinate H, conflate k with M, negate the existing positive h readout, or confuse physical Y with canvas y. Define the symbols/axis next to the explanation; H is total object height, not a point's height above this optical axis. Display M as dimensionless, all lengths in cm; local sign is a geometric inversion convention, not negative distance u or v.

2. **Fix the existing S2 rendering boundary before promoting it.** The formula is correct, but for H=60,u=80,v=160 the image extends to logical y=282 below the drawn screen's bottom252. At H=90,u=60,v=180, endpoints72 and342 also exceed the scene height330. The latter is statically provable clipping. Keep the allowed parameter ranges and numerical mapping; extend/reframe the screen and logical scene or choose a fixed scale/translation that shows the entire permitted ray/image extent, with margins and readable controls. Do not silently clip/normalize h or change parameter ranges merely to make the image fit. Recheck drag-coordinate inverse mapping after any view change. UI verification should decide the final rendering details, not these source calculations alone.

3. **Bound the aperture claims where they are actually read.** Current s3hint/fc3b say without qualification that smaller holes always sharpen images; s2hint also says size is unrelated to aperture. Define h as the ideal point-aperture/central-ray image extent (or center-to-center endpoint separation), not the outer envelope of a finite-aperture blur. In this geometric model a finite aperture gives blur width d(1+v/u), whose centers still obey the ideal ratio. Add a short nearby qualifier to the current aperture conclusion and closing card: geometric blur decreases as the hole narrows, but real sufficiently small apertures show diffraction and cannot sharpen without limit; no diffraction/optimal aperture/real brightness prediction is computed here. A distant source link alone cannot undo an unconditional local conclusion. Do not label the physical pinhole screen distance v a thin-lens focal length, and do not apply 1/f=1/u+1/v: this experiment has no lens. Stanford's computer-vision notes sometimes call its image-plane distance f, so retain this lesson's v convention rather than importing that terminology.

4. **Make navigation state promises testable.** Both current lesson controllers hold state only in JS memory and have no pagehide/pageshow/history/session restoration code. Ordinary browser Back may retain the entire page via bfcache; it is not an application-level restoration guarantee. Verify a real same-tab round trip with a nondefault linear k/b/selected point and prior quiz state, and reciprocal pinhole H/u/v/help/quiz state. If the product explicitly promises restoration when a new document is loaded, add only the minimal validated course-local snapshot necessary, preserve unrelated history fields, and restore without starting animation. Do not claim reload or storage-denied resilience based only on bfcache, nor mirror one lesson's controls into the other's independent state. Language/resize/help opening must not reset numerical or quiz state.

5. **Keep rounding honest.** Compute from unrounded state/endpoints; symbolic identities may use =, displayed rounded k/M/h/Y values need ≈ when not exact. The old s2 readout already selects =/≈ for its displayed ratio; any new strings must not reintroduce exact arithmetic between rounded factors. For negative operands use parentheses or symbolic formulas. No independent new cached numerical state should drive the explanation.

## Smallest learning task

A native details after existing S2 readout/hint can connect the two similar right triangles and the constant-slope ray; the same S state drives accessible DOM equivalents and the canvas. A prompt can ask: H=60 cm,u=120 cm,v=90 cm: image size45 cm, M=−0.75; if only v doubles to180, predict size90 cm while the image stays inverted. Two explicit local preset buttons may set the named complete task states; they must not change other steps, quiz answers or language. Alternatively reuse sliders and existing presets with instructions if equivalent checks are unambiguous. No score, mastery, tracking, new global state or artificial learner profile is needed. Opening or returning from the explanation must retain focus/context; controls need normal keyboard equivalents.

The linear-functions#step2 cross-link should explicitly say the pinhole page uses a straight light ray and similar triangles to predict an inverted image, not that all functions describe light. Its reciprocal link should name constant slope and lead to the actual equation/probe step. An atlas edge can explain that equal slopes along the same ray yield corresponding-side ratios; type application is suitable, not an enforced prerequisite. New canonical pinhole text must include the model boundary rather than inherit lens terminology. Keep the existing foundation-cycle policy.

## Primary sources checked

- [Stanford CS231A Camera Models, pp.1–3](https://web.stanford.edu/class/cs231a/course_notes/01-camera-models.pdf): point-aperture projection and similar triangles; distinguishes later lens construction. Our sign/height convention above is derived directly from this project's actual geometry, not copied from that document's different axes.
- [OpenStax: Introduction to Geometric Optics](https://openstax.org/books/college-physics-2e/pages/25-introduction-to-geometric-optics): ray versus wave-model scope.
- [OpenStax: Limits of Resolution](https://openstax.org/books/college-physics-2e/pages/27-6-limits-of-resolution-the-rayleigh-criterion): circular apertures spread light through diffraction, limiting image detail. No quantitative diffraction model is proposed here.
- [OpenStax: Image Formation by Lenses](https://openstax.org/books/college-physics-2e/pages/25-6-image-formation-by-lenses): focal point/focal length belong to a refracting lens construction; distinguish from this freely chosen pinhole screen distance.
