Correctness reconstruction: before a text row, `previous[j]` is truth for the preceding text prefix and pattern prefix j. During the row, every current cell to the left has already been computed, while `current[0]` is false. A star either consumes no final text character (left) or consumes the final character and remains available (above); these exhaust its possibilities. A literal/question mark requires one-character compatibility and the shorter-prefix diagonal. Row zero permits only all-star prefixes. Nested bounded loops terminate and the final `previous[n]` covers both entire strings. Fresh rows prevent stale truth. Strings are immutable; the algorithm allocates only local Boolean lists and does not mutate inputs.

At final event 29, b/b and diagonal T cause T. The table preserves complete history; Python intentionally keeps two rows. Initialization timing differs: the model fills every first-column boundary before row zero, while Python creates current-row zero as each row is allocated. This does not change values; the view's declared full-table model explains that it is not a literal Python execution timeline.

Actual work is O((m+1)(n+1)) time including initialization/empty-pattern rows, O(n+1) auxiliary cells (usually O(n) for positive n). Only two live rows are needed; no recursion in canonical code.
