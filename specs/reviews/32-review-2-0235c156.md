The maintained invariant is a nonempty stack with the last unmatched close (or −1) at its bottom and unmatched openings in increasing order above it. On an opening, appending preserves that order. On a close, removing the last opening matches the nearest one; if only the bottom was removed, the current close is unmatched and becomes the new boundary. Otherwise the remaining top is excluded: every character strictly after it through i belongs to a matched suffix, and that suffix cannot extend through the unmatched top. Each valid substring ends at some processed endpoint, so maximizing over those suffixes gives the global answer. Empty input terminates with 0 without popping. The `(()` preset also checks the unmatched-opening obstruction, not only invalid-close boundaries.

Visible event 5 maps to actual Python `stack.pop()` followed by `best = max(best, i - stack[-1])`: [0,3] → [0], i=4, prior best=2 → max(2,4−0)=4. The focused excerpt intentionally shows the max statement, while Previous state supplies the pre-pop stack. At final unmatched close, current length becomes 0 while historical best remains 4. Boundary indices are data; cyan/underline mark the current operation and orange outlines mark the valid suffix. No spurious secondary stack-storage indices are displayed.

Baseline worst case is O(n²) time (e.g. all opens makes each inner loop scan to the end), O(1) extra space. Canonical optimized Python is O(n) time/O(n) auxiliary space: each input position is visited once, with at most one stack push/pop and amortized constant list-end operations; all opens can retain n indices.
