The key invariant is not that one fixed anchored rectangle retains its coordinate identity after swaps. Rather, all rectangles are relabeled by row/column permutations, so an XOR-1 rectangle cannot disappear. When all anchored rectangles pass, `board[i][j] = board[0][0] ^ board[i][0] ^ board[0][j]`; alternating both label sequences therefore yields a chessboard. Counts provide legal target starts, and opposite mismatch pairs attain each axis lower bound. Complementing all opposite-axis labels leaves that minimum unchanged, so the costs remain additive even if an operation moves row/column zero.

Visible-to-code mapping checked concretely: default frame 6 reads row target 0101 with mismatches at positions 1 and 2 of 0011, so the Python `mismatches // 2` is 1 for start 0. Frame 7 performs that row swap in the simulation; Python records only the computed row cost. First-row 0110 costs 1 independently. `return rows + cols` therefore returns 2. XOR-failure frame (1,1) on 01/00 corresponds directly to the nested-loop early return; count-failure preset has first-row 0001, whose one 1 cannot match either 4-position alternating target's two ones.
