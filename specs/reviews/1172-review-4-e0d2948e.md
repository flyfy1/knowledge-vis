### Canonical statement and implementation

The official statement was read at the supplied LeetCode URL. It defines `DinnerPlates(capacity)`, `push(val)` to the leftmost stack with room, `pop()` from the rightmost non-empty stack or `-1`, and `popAtStack(index)` or `-1`. The rendered interface and `solution.py` use the same callable names and return semantics. The official example's return sequence is consistent with the independently executed Python class.

`leetcode/1172/solution.py` is the canonical Python source. `provenance/official-source.py` is byte-identical, and the displayed `window.PYTHON_SOURCE` decoded from `python-code.js` is byte-identical (1,376 bytes). The page explicitly says the animation is a simulation and the source is the official interface. This is a Python-canonical lesson, so no non-Python language contract is required; the registration language table resolves this problem to Python when no contract file exists.

The implementation maintains a min-heap plus set of non-full indices. `push` removes stale/full heap entries, chooses the smallest available index or appends, then re-adds the index if it remains non-full. `pop` trims empty tails before taking the tail value; `popAtStack` validates bounds/emptiness, pops the requested top, and re-adds its hole. The independent fresh run used capacity 2, pushes 1–5, `popAtStack(0)`, `push(6)`, then mixed `pop`/`popAtStack`; observed outputs were `2, 5, 4, 3, 6, 1, -1`, matching the state transitions.
