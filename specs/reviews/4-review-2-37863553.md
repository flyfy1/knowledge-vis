### Correctness, intermediate state and actual cost

Independently reconstructed proof: sorting each row supplies within-row order; the cross comparisons supply the other two possible left/right pairings. Together with left size half, that establishes median rank. With shorter length m≤n, m≤half≤n, so j=half−i is legal for every i from 0 through m. Increasing i cannot decrease aL or increase bR: if aL>bR, every larger cut fails too. Decreasing i cannot increase aR or decrease bL: if bL>aR, every smaller cut fails too. A valid split exists by considering the first half of a hypothetical merged order. Each rejected midpoint strictly shrinks a finite interval while retaining a valid split; termination follows.

The odd UI transition maps directly to canonical lines 21–22: bl=3, ar=2 makes `lo = i + 1`, from 0 to 1. The new decrease preset maps to lines 19–20: al=10, br=3 makes `hi = i - 1`, from 2 to 0. The view retains tested i=1,j=2 while showing post-update bounds; before state and retained history display earlier snapshots. Values stay constant; highlights and cut markers identify positions, not mutations. Empty sides use comparison sentinels, not inserted values. Equal values are allowed because only strict violations trigger movement.

Canonical Python swaps references and reads lists without copying or mutation. Its work is logarithmic in the m+1 candidate cuts of the shorter array, with a constant-time empty-array case, and constant auxiliary storage. The UI's JavaScript model copies arrays and retains frames for presentation; its storage is not the submission's auxiliary-space claim. Odd returns max(left); even averages max(left) and min(right). The baseline's generic O(N log N) sorting upper bound is conservative for Python's adaptive sort on two sorted runs; the relevant avoided work remains at least linear combined input processing.
