### Correctness and visual-to-code correspondence

The source scans all incoming edges before DSU scanning, so `later` is fixed before any connectivity operation. `incoming` stores original input positions, not parents or DSU leaders. Filtering reduces all indegrees to at most one; any undirected cycle then must have one incoming edge per cycle vertex and hence also be directed (including opposite-arrow length-two cycles). Retained edges stay a forest, and DSU partitions are exactly its components. Equal representatives detect closure without merging. A conflict forces the answer to be earlier or later; failure after excluding later forces earlier. Otherwise n−1 forest edges imply connectivity and one root. Without a conflict the unique cycle's last input edge is the closure edge. All branches return under the input guarantee.

Concrete mapping after default frame 4: row1 is code index0, `find(1)=1`, `find(2)=2`, equal sizes keep leader1, `leader[2]=1`, `size[1]=2`; visible groups change from `{1} · {2} · {3}` to `{1,2} · {3}`. The diagram's 1→2 becomes solid. Frame5 sets `leader[3]=1`, `size[1]=3`. Frame6 skips index2 because `later=2`; groups stay unchanged. Counterexample row4 is rejected while answer row1 remains marked retained in the **detection** graph; the explicit before-removal caption prevents conflating this with an already repaired tree. Final answer identity and input row are correct even when the answer is not the last tested edge.

Path halving changes DSU links only within an existing component; union by size changes one representative link and updates its size. No input edge is mutated. Returning `[:]` gives an independent two-element list. Three length-n arrays dominate auxiliary space, and two scans plus size-weighted/path-halved DSU yield O(n α(n)) amortized time. Baseline independently costs O(n²) time/O(n) space; teaching snapshot storage is separately described as O(n²). No recursive stack is used. The complexity claims match the actual implementation.
