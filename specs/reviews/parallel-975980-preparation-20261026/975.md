# #975: original contract and teaching preflight

[Official problem](https://leetcode.com/problems/odd-even-jump/).
[Saved payload](975-official-access.json); [future dispatch gate](README.md).

**Verified input/output.** `arr` is an integer array of length 1–20000, with each
value in `[0,100000)`. Jumps move strictly forward in index. On an odd-numbered jump,
choose the smallest eligible destination value at least the current value; on an
even-numbered jump, choose the largest eligible value at most the current value.
In either case, ties use the smallest destination index. With no eligible index,
the sequence stops. Count starting indices that can reach the final index,
including the final index itself with zero jumps.

Python3: `Solution.oddEvenJumps(self, arr: list[int]) -> int`.
TypeScript: `oddEvenJumps(arr: number[]): number`.
Official examples: `[10,13,12,14,15] -> 2`, `[2,3,1,1,4] -> 3`,
`[5,1,3,4,2] -> 3`. Keep original indices/values visible, including duplicate ones.

**Pitfalls to address in later teaching:**

- Odd/even labels refer to jump number, not source index or value parity. Every
  new starting index begins with an odd jump, even if that array index is even.
- Selection has two priorities: destination value first, then index among ties.
  It is not simply the nearest qualifying element. In the first example, index 0
  jumps to value 12 at index 2 rather than value 13 at index 1.
- Equality is eligible for both jump types. The repeated 1s in example two make
  the smallest-index tie rule visible; show both candidates before resolving it.
- Distinguish “no legal jump” from reaching the end. The one-element case succeeds
  without a jump. If representing two reachability states, define the *next* jump
  type and explain terminal behavior before backward transitions.
- Each state has a prescribed destination, not a menu of paths to optimize over.
  Count good starts, not jump sequences, successful edges or only odd-index starts.
- If sorted indices and a stack are chosen later, show why they preserve the
  value/index priorities; do not reorder the displayed input or reverse equal-value
  index order accidentally. A sorted picture alone is not that proof.
- A direct small-input destination scan can check both destination maps before
  reachability. Derive the optimized costs from the chosen actual structures,
  keeping original array, preprocessing order and simulation history distinct.

No successor map, stack proof, recurrence, UI or test oracle is implemented here.
Those choices require the author's own derivation and independent review.
