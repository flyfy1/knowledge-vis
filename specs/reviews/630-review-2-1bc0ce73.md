### Executable algorithm, boundaries, and teaching mechanism

Read actual solution.py, core.js, app.js, copy.js, index.html, local/shared CSS and common locale consumer after the cold report was saved. The Python implementation sorts a new list by deadline, inserts each negative duration and updates total, pops one longest on a strict overload, and returns heap length. It does not modify the caller's outer list or inner pairs. The simulation instead uses a linear search for a longest retained course and deep-copied frames: its extra history and simulation cost are correctly distinguished from the submission's heap and O(n) working space.

The proof is valid: any feasible subset can be deadline-ordered by adjacent exchanges. At the first overloaded prefix of the current list, some course must be omitted. If an optimal solution includes a longest course L, exchange L for an omitted J from that prefix. Earlier prefixes remain subsets of previously feasible full prefixes, and totals from the end of that prefix onward do not increase. Thus an optimal solution omitting L exists. Repeated permanent safe deletions give the scan; already-repaired prefixes never become overloaded when later courses are added. One pop suffices because longest duration is at least the new duration: repaired total ≤ previous total ≤ current deadline. This proof, including the earlier-deadline caveat, is visible in both locales. Termination is the finite scan; tied removals are interchangeable, equality succeeds, and a too-long course is removed. The negative-duration heap realizes that deletion without exploring subsets again.
