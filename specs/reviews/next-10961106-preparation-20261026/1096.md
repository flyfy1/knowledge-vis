# #1096 Brace Expansion II

Dispatcher-only reference to the [official contract](https://leetcode.com/problems/brace-expansion-ii/).
The saved ordinary public GraphQL response is HTTP 200, Hard/free, and matches the
fixed catalog. Original statement, examples, metadata and templates are retained
in `1096-official-response.json`; the access wrapper records exact request/hash.

## Original interface and grammar

Python3: `Solution.braceExpansionII(self, expression: str) -> list[str]`.
TypeScript: `braceExpansionII(expression: string): string[]`.
Input is the original expression string; output is a sorted list of distinct
lowercase words, not a derivation list or count. Length is 1–60; characters are
lowercase letters, `{`, `}`, and `,`; the input is guaranteed valid.

A letter denotes one word. A braced comma-separated group of at least two
expressions denotes union. Adjacent expressions denote every ordered
concatenation from their two word sets. The formal grammar has no empty-word
literal or empty alternative. A multi-letter token such as `ab` is concatenation
of letters. Do not silently add singleton braces, top-level commas, whitespace or
range syntax as official grammar features.

## Small semantic witnesses

| Expression | Required result | Distinction |
| --- | --- | --- |
| `{a,a}` | `["a"]` | Union is idempotent. |
| `{a,b}{c,d}` | `["ac","ad","bc","bd"]` | Cartesian product, not zip or union. |
| `{ab,c}d` | `["abd","cd"]` | Each whole alternative is extended by `d`. |
| `a{b,c}d` | `["abd","acd"]` | Prefix and suffix both survive grouping. |
| `{a,ab}{bc,c}` | `["abbc","abc","ac"]` | Two derivations produce `abc`; output it once. |
| `{z,aa,a}` | `["a","aa","z"]` | Lexicographic order differs from length order. |

All 11 checked cases include both official examples. Each input is independently
serialized from a manually authored valid grammar tree. A tiny bag/product oracle
retains duplicate derivation words before deriving the final distinct sorted set.
It supplies semantic witnesses, not an expression parser or an optimized solver.

## Provisional teaching and review risks

Keep grammar nesting, unfinished concatenation and accumulated alternatives
visibly distinct. A comma separates complete alternatives within its own braces;
it does not discard a preceding concatenation or split nested commas at the outer
level. Explain product versus union before introducing any parser state. Repeated
derivations are different from repeated output words. In a chosen implementation,
a temporary concatenation identity such as `{ "" }` is an internal state, not
permission for empty official inputs or empty output words.

Sorting and deduplication must match the returned callable result. Reset/rewind
must restore all active group contexts rather than just the visible output list.
Short expression length does not make materialized products or string copies
free; any complexity explanation needs intermediate/output sizes. These notes
choose no parsing technique, data structure or performance claim. The direct
oracle does not validate cursor handling, a candidate implementation, rendering
or the largest legal expansion.
