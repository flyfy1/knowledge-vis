# #1106 Parsing A Boolean Expression

Dispatcher-only reference to the [official contract](https://leetcode.com/problems/parsing-a-boolean-expression/).
The saved ordinary public GraphQL response is HTTP 200, Hard/free, and matches the
fixed catalog. Original statement, examples, metadata and templates are retained

## Original interface and grammar

Python3: `Solution.parseBoolExpr(self, expression: str) -> bool`.
TypeScript: `parseBoolExpr(expression: string): boolean`.
Input is one valid expression string of length 1–20,000. Its characters come from
`t`, `f`, `!`, `&`, `|`, `(`, `)`, and `,`; return a Boolean value, not the strings
`"t"`/`"f"`, a count, or a numeric bitwise result.

`t` and `f` are complete literal expressions. `!(subExpr)` has exactly one
operand. `&(subExpr1,...)` and `|(subExpr1,...)` each have at least one operand;
unary AND/OR is valid. These are prefix operators with explicit grouping, not
infix precedence rules. Empty operator calls, multiple NOT operands and implicit
whitespace are not specified extensions. Invalid-input recovery is separate from
the guaranteed-valid official problem.

## Small semantic witnesses

| Expression | Result | Distinction |
| --- | --- | --- |
| `t` / `f` | true / false | A literal is a full input. |
| `&(t)` / `|(f)` | true / false | One-operand AND/OR is legal. |
| `!(!(t))` | true | Nested NOT has separate groups. |
| `&(|(f,t),!(f))` | true | Reduce inner groups before the outer meaning. |
| `|(&(f,!(f)),&(t,t))` | true | A false inner AND still has syntax before a later sibling. |
| `&(|(t,!(t)),f)` | false | A true inner OR does not decide the outer AND. |

Thirteen checked cases include all three official examples. Explicit grammar
trees serialize to the original inputs; an eager tiny truth oracle records each
group's operand values and result. Thirty additional truth-table checks cover
AND/OR arities 1–3 and both NOT inputs. No parser or cursor implementation is
supplied or tested by this oracle.

## Provisional teaching and review risks

Separate knowing a group's truth value from consuming its complete syntax. If a
chosen parser short-circuits a Boolean calculation, it must still correctly pass
that group's remaining nested tokens and closing delimiter before interpreting
outer siblings. The two sibling examples make this distinction concrete without
prescribing recursion, stacks or another parsing technique.

A nonempty string `"f"` is truthy in Python and JavaScript; its literal meaning
must be decoded explicitly. TypeScript bitwise operators produce numbers, so a
chosen implementation must still honor the Boolean return contract. Preserve
operator arity and group boundaries; commas do not add operands by themselves.
A legal expression can be deeply nested within 20,000 characters, so recursive
runtime limits require actual validation if that technique is chosen. No such
maximum-depth/performance test is claimed here. Visualization state should
separate cursor, current operator, completed child values and returned value;
there is no UI proposal or implementation in these notes.
