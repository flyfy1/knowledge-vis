### Executable correctness, invariant, and cost

Executed actual `leetcode/827/solution.py` through importlib with Python bytecode disabled. Independently wrote an oracle that tries no flip and every actual zero flip, constructs a land-coordinate set, and removes each reachable component using a growing queue. This oracle does not use component IDs or the optimized sum formula. It agreed with the canonical solution on all 530 binary grids of sizes 1..3 and 300 independently seeded random grids of sizes 4..5 (seed 20261026827); input equality was checked after every call.

Both fresh predictions saved above were confirmed before consulting any preset result: the first returns 4, the counterexample returns 6, and neither input changes. These are **code checks**; there is no arbitrary-input UI. In the second case, the center's three neighbors all belong to one size5 component, so the tempting 16 is impossible even though there are three contacts.

The canonical loops justify the invariant rather than merely agreeing with an oracle:

- A seed is labeled before entering the stack. Only unlabelled original land is pushed; marking before pushing prevents a second path from scheduling it again. Every pop counts one unique cell. When the stack empties, all reachable original land has been counted, and area[component] is final.
- All component fills finish before zero testing. For each zero, `seen` collects at most four IDs; `area[0]=0` makes water irrelevant. Distinct original components are disjoint, so one new cell plus their areas is exactly its connected island. Other islands are untouched. The initial best already includes them and the no-flip choice.
- `best=max(best,candidate)` retains earlier candidates; all zeros are enumerated, so the final maximum covers all permitted operations. Both scans and each loop terminate over finite cells; every land cell enters the stack once.

Concrete visual-to-code mapping: on the repeated-island preset, before the zero test `labels=[[2,2],[2,0]]`, `area={0:0,2:3}`, best=3. For (1,1), the Python neighbor loop adds ID2 twice to `seen`, which remains `{2}`. `candidate = 1 + sum(area[k] for k in seen)` yields 4, and best becomes 4. The browser displays raw [2,2], distinct [2], `1 + 3 = 4`, and leaves the candidate cell's value at 0. The simulation omits water IDs from its displayed raw list; Python may also add ID0. This has no numerical effect because area[0]=0, and the mapping paragraph explicitly explains it.

Cost audit: n is the side length, hence n² cells. Baseline copies and rescans O(n²) cells per possible zero and retains only one trial, giving O(n⁴) worst-case time/O(n²) space. The submission labels each land cell once and checks four neighbors per zero, yielding O(n²) time. labels, area and worst-case stack require O(n²) auxiliary space; the bounded seen set is O(1). No grid assignment mutates the argument. History snapshots belong to the teaching simulation and are explicitly excluded from the submission claim. No recursive-call explanation is required for this iterative solution.
