### Independent calculations, transition mapping, and cost

Executed the actual canonical Python with `runpy.run_path`, not its browser imitation. The pre-recorded fresh predictions were confirmed: `[2,5,7] → True`, `[2,5,6] → False`, `[2,5] → True`. On the losing triple `[2,5,6]`, X=1; removing 2, 5 or 6 produces respectively X′=3,4,7 with two numbers. Each child is winning for the next player. On `[2,5,7]`, zero is detected before any move, disproving parity-only classification. Additional singleton `[0] → True`, `[65535] → False`, 1000 entries with 999 zeroes and one 65535 → True, and 1000 copies of 65535 → True matched predictions; input lists were unchanged.

A separate recursive game-tree oracle recomputed each of 16 bit columns, ignored zero-producing erasures, and recursively tested opponent loss. It matched canonical Python on 923 multisets of lengths 1..6 over independently chosen values `{0,1,2,5,7,65535}`. This checks actual optimal play independently of the parity shortcut. The checked-in tests supplied additional exhaustive sequence, random, maximum-size and displayed-baseline coverage, described below.

Concrete visual/code mapping: browser [1,1,2] at X=2 erases original index 0/value 1, leaving original indices 1 and 2 with values [1,2], X=3. The displayed baseline constructs `nums[:i] + nums[i + 1:]`; its child retains [1,2] while the parent remains [1,1,2]. In canonical Python the same child board is classified by accumulator values 0→1→3 and even length. The submission intentionally computes the classification, rather than simulating that UI move. Both the distinction and prefix accumulator invariant are visible in both locales.

Source confirms core snapshots are copied, retained original IDs identify duplicates, `loser` distinguishes a just-created zero from a zero-at-entry win, and history slicing discards future branches after an alternative move. Each erasure decreases remaining count, so automatic Finish terminates in at most initial n steps. Even nonzero positions have a safe move by the cancellation contradiction; odd safe moves give even nonzero positions. The singleton establishes the induction base. Initial zero and post-erasure zero are handled separately in both renderer and proof.

Canonical cost is O(n) time/O(1) auxiliary space: one bounded-width XOR per element, two scalar locals, no list copies or input writes. The displayed baseline's O(n·n!) is a valid loose upper bound for a factorial branching tree with O(n) local work, including XOR scans and slices. O(n²) active sliced-list space follows from lengths decreasing by one down a branch; short-circuiting may save work but cannot invalidate these upper bounds. At n=1 the bounds remain meaningful. UI snapshots are explicitly excluded from submission space.
