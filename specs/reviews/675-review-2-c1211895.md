Canonical correctness reconstruction: sorted unique heights determine the endpoints. Each call creates fresh `seen` and a FIFO deque containing start at distance zero. Only in-bounds positive unseen neighbors enter, marked seen before enqueue. FIFO processing makes their assigned distance minimal. Dequeuing the target returns that distance; exhausting the queue returns -1, propagated immediately. The outer loop accumulates successful legs and moves the start. Blocked start is checked explicitly. A start tree returns distance zero. No assignment writes to `forest`; maintaining original positive heights preserves the same connectivity as actual cuts.

Visual-to-code mapping: on [1,3,2], (0,0) starts at d0; the in-bounds/positive/unseen checks admit (0,1), then `seen.add` and `queue.append((nr,nc,steps+1))` produce d1. The trace deliberately groups a complete discovery layer and later a cut; canonical Python returns when dequeuing the target. This difference is explicitly taught in both languages. For the detour, frame 6 has target d6 and completed total 0; frame 7 adds 6; frame 8 resets distances but retains total 6. The target value is never paired with another leg's distance.

Cost is correct for the actual code: initial scan O(mn), sorting O(T log T), up to T searches of O(mn) each, and O(mn+T) auxiliary storage. Since officially T≥1, the scan is absorbed by O(Tmn + T log T). Queue and seen are per-leg; sorted targets add T storage. At maximum grid/tree count the stated dequeue/direction-check bounds are upper bounds, not timings. The cubic all-pairs baseline is executable and correct for legal inputs, but solves many unneeded distance queries. Snapshot storage is explicitly separate from submission space.
