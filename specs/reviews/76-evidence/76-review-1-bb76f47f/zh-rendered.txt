#76 · 最小覆盖子串

用一段连续文字，凑齐每一个需要的字符；再把多余的边缘去掉。

01

先手算：两个 A 都要有

这一步要回答：s = ABAAC 中，哪一段连续字符能提供 t = AAC 要求的两个 A 和一个 C，而且最短？子串就是连续的一段；窗口是正在考虑的子串。覆盖表示每种字符的数量至少达到 t 的要求，字符顺序不必相同。

官方范围：1 ≤ m,n ≤ 100000，m、n 分别是 s、t 的长度；仅大小写英文字母，A 与 a 不同。无解返回空串。官方测试保证答案唯一。

把位置写出来：0:A，1:B，2:A，3:A，4:C

从右端 4 开始检查：[0,4] = ABAAC，A:3、C:1，长 5；去掉位置 0 的 A 得到 BAAC，A:2、C:1，长 4；再去掉 B 得到 AAC，长 3，仍覆盖。再去掉一个 A 得到 AC，A:1，不够了。少于 3 个字符不可能提供 3 份需求，所以 AAC 最短。这里 [left,right] 包含两端，位置从 0 开始。

一个诱人的错法：只检查字符集合。AC 和 AAC 都含 A、C，但 s = AC、t = AAC 无解。另一个错法：找到第一个覆盖就停；ABAAC 虽然覆盖，却比 AAC 长。

官方例子：ADOBECODEBANC / ABC → BANC；a / a → a；a / aa → 空串。

可靠起点：枚举每个起点和终点

怎样保证不错过答案？固定起点 left，向右逐个加字符，累计数量，检查所有需求，保留最短窗口。下面是完整的小输入基线；还没有复用不同起点之间的工作。

from collections import Counter

def baseline(s, t):
    need = Counter(t)
    best = None
    for left in range(len(s)):
        have = Counter()
        for right in range(left, len(s)):
            have[s[right]] += 1
            if all(have[c] >= need[c] for c in need):
                width = right - left + 1
                if best is None or width < best[1] - best[0]:
                    best = (left, right + 1)
    return "" if best is None else s[best[0]:best[1]]

若 k 是 t 中不同字符的数量，每个窗口检查 k 项，代价 O(n + m²k)，额外计数空间 O(52)。m = 100000 时约有 50 亿个窗口。瓶颈是反复计数和检查；我们希望每个字符只进出一次。

02

从数量变化推导规则

这一步要回答：窗口移动一格时，哪些需求真的改变了？need[c] 是 t 对字符 c 的需求数；have[c] 是当前窗口内 c 的数量。覆盖意味着每项 have[c] ≥ need[c]。只存 t 需要的字符；B 等无关字符仍占窗口长度，但不改变需求。

还是 AAC 的需求：need[A]=2，need[C]=1。加入第一个 A：A 从 0→1，欠缺总数 3→2；加入第二个 A：1→2，欠缺 2→1；加入第三个 A：2→3，只是多余副本，欠缺仍为 1。加入 C 后欠缺为 0。反过来，A 从 3→2 不失去覆盖；从 2→1 才欠一个 A。

missing = Σ max(need[c] − have[c], 0)；求和只遍历 t 中的字符种类。missing 是尚欠的副本数，不是尚欠的种类数。

因此加入 c 时，先看旧 have[c] < need[c]，才将 missing 减 1，再加计数。移除 c 时，先减计数，再看新 have[c] < need[c]，才将 missing 加 1。这使上面的等式在每次操作后成立；missing=0 恰好等于覆盖。

先预测：多一个 A 会怎样？
移除一个 A 后还覆盖吗？新例子：s=AABBC，t=ABC。当前覆盖窗口 [0,4] 有 A:2、B:2、C:1，missing（欠缺副本数）=0。先记录这个候选，再移除位置 0 的 A。下一步应该做什么？
停止收缩，因为移除了需求字符 A。
停止并返回 BBC；只看最后三个字符即可。
仍覆盖：记录 ABBC，再尝试移除它最左边的 A。
检查预测并揭晓

再看看数量门槛。 移除后 A:1、B:2、C:1，全部达到需求，所以 missing 仍为 0。ABBC 长 4，应记录后再移除 A；这次 A 从 1→0 才使 missing=1。选项一忽略了多余副本；选项二的 BBC 缺 A，根本不覆盖。最短答案是 ABBC。

05

证明、代码与边界

这一步要回答：只向前移动两端，为何不会漏掉更短答案？have 始终等于当前窗口内的需求字符计数；missing 始终等于各项正欠缺之和。由加入和移除的门槛规则，这两个不变量（每次操作后仍成立的事实）从空窗口开始一直保持。

每次右端加入字符后，先固定右端。只要覆盖，就先检查候选再移除左端，直到覆盖失败。移除不可能补回欠缺，所以更靠右的起点也不可能覆盖这个右端。已丢弃的起点在丢弃前已有覆盖窗口被检查；日后右端变大，以这些旧起点开头的窗口只会更长，不会改进已有答案。因此左端不必回头，检查过的最短记录就是全局最短。

把图里的操作对上 Python
加入：for right,c 遍历 s；只对 c in need 更新 have 和 missing。图中加入帧对应这个分支完成后。
检查：while missing == 0 内先算 width，严格更短时保存 best_start 和 best_len。图中检查帧对应保存候选后。
移除：c=s[left]，更新计数与 missing，最后 left+=1。图中移除帧可能已经不覆盖，best 仍保留。

成本：令 m=len(s)、n=len(t)、k 为 t 中字符种类数、L 为答案长度。建立 need 花 O(n)，right 共移动 m 次，left 最多 m 次，字典操作在固定 52 字母表下为常数。总时间 O(m+n)，含最终一次长度 L 的切片（L≤m）。额外计数空间 O(k)，k≤52；返回字符串另占 O(L)。只保存最短位置，若每次改进都复制窗口，可能退化到平方时间。

边界：t 比 s 长或需要的副本不足时永远不覆盖，返回空串；s=t 时保留整个字符串；大小写分别计数；多余字符不能让 missing 为负。官方不含空输入，代码额外防御空 s 或空 t。非官方并列最短情形保留最先遇到的一段。
