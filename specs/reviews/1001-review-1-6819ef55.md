The huge-grid first query shares the lamp's sum diagonal but is too distant to remove it. The second reads its own light and removes it; the third is dark. This checks that illumination and shutdown use different geometry.

Invariant independently reconstructed: each dictionary counts exactly the members of `active` with its corresponding line key. Deduplication precedes counting. Reads do not change membership. Each successful membership test removes one coordinate and then subtracts its four contributions; testing absent neighboring positions makes no change. Invariant is restored after the complete four-counter update, not necessarily between individual decrement statements. Zero-key deletion is safe because the removed coordinate supplied a positive contribution. Counter lookups do not insert absent keys. Every query completes nine finite candidate visits, so the algorithm terminates in input order.

The visible first shutdown maps to `active.remove((x,y))` with x=y=0, then keys `(rows,0),(cols,0),(down,0),(up,0)` decrement. Row 0 retains one contribution from (0,3), while the other zero keys disappear. Visual and code agree about the instant before versus after shutdown. Separate history snapshots preserve the earlier read counts, not current values masquerading as earlier ones.

Cost is justified by actual loops: expected O(L) set construction/initialization and O(Q) four-lookups-plus-nine-candidates; auxiliary storage has O(U) set/map entries, with O(Q) output. No n² allocation. The direct baseline shown in HTML scans all U active lamps and rebuilds the surviving set, bounded by O(L+Q(U+1)), including Q visits when U=0. Teaching snapshots have separate storage and are explicitly excluded from submission cost.
