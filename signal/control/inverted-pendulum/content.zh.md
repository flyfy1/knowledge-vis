## 推它，它不倒 {#step0 h2=s0t}

::: strings
nav0: 0 钩子
:::

第 0 步 · 先看奇迹 {#s0k .step-kicker i18n=text}

这辆双轮车没有支架，脚下也没有秘密机关。它就这么站着——你**推它一把**，它晃两下自己站回来。再把「控制」关掉推一次：同一辆车，立刻倒。差别只在一个看不见的圈里：传感器每秒几百次量角度，控制器算出该使多大劲，电机马上执行。这一页就把这个圈拆开看。先把读数的一个口径说清：下面「电机出力」的百分数，是此刻推力占电机**最大推力（推力上限）**的比例——100% 就是已经使满了劲。 {#s0e .explain}

## 先让它倒，再亲手救它 {#step1 h2=s1t}

::: strings
nav1: 1 没有反馈
:::

第 1 步 · 没有反馈的世界 {#s1k .step-kicker i18n=text}

左边是控制关掉的双轮车。拖动起始角度、放手——它不会「慢慢倒」，而是**越倒越快**：倾角像滚雪球一样指数长大，计时器告诉你它活了多久。右边是秋千（悬挂摆）：同一条摆的方程，只是平衡点一个在山顶、一个在谷底。谷底的那个你随便推，它只是晃；山顶的这个，呼吸都是扰动。 {#s1e .explain}

::: html step1-1
s1ang: 起始角度
s1inv: 倒立摆（控制关）
s1hang: 悬挂摆（秋千）
s1hangNote: 悬挂摆：等幅摆动，不发散、不衰减（模型里没有摩擦）。
s1release: 放手！
:::

轮到你当控制器 {#s1mt .sub-h tag=h3 i18n=text}

现在换你来闭环：用 **◀ ▶** 方向键（或按住下面的按钮）给轮子加减速，在它倒下前把车身推回竖直。目标：**活过 10 秒**。先说结论：你大概率撑不过几秒——不是手慢，是人的反馈环只有约 5–10 Hz（看清、判断、按下要一两百毫秒），而这根杆的倾角**每约 0.16 秒就翻一倍**。机器的圈每秒转 480 次，这才是它站得住的真正原因。 {#s1me .explain}

## 传感器 → 控制器 → 电机 → 再回到传感器 {#step2 h2=s2t}

::: strings
nav2: 2 闭环
:::

第 2 步 · 把圈闭上 {#s2k .step-kicker i18n=text}

看上面的回路图：信号沿着圈跑——传感器量到角度，控制器算出该出多大的力，电机驱动轮子，车身角度改变，又被传感器量到……周而复始。下面这辆车装的正是这个圈，只是控制器里只有一条最朴素的规则：**往哪边倾，就往哪边开；倾得越狠，开得越猛。**拖动增益，让它先站住再说（晃，是意料之中的）。 <a class="fourier-link" href="../../systems/lti-systems/#step2">回路里每个盒子都有自己的 h：先看系统对一记冲激的回答 →</a> {#s2e .explain}

::: html step2-1
s2gain: 规则增益 K
s2reveal: 点破一下：这条「出力与倾斜程度成比例」的规则有个名字——**比例控制，P**。写成公式是 u = Kp·e，其中 e = 目标角度 − 当前角度（目标是竖直，0°）。车往右倾时 e 为负，u 为负，轮子就按这个符号向右加速去追倾倒的方向——方向由误差的符号自动搞定，你拖的 Kp 决定追得有多凶。后面三步，我们给它陆续加上 D 和 I。
:::

cCtrl: 控制器
cMotor: 电机
cPlant: 车身 · 倾角 θ

## P：太软倒、太硬晃 {#step3 h2=s3t}

::: strings
nav3: 3 只有 P
:::

第 3 步 · 只留 P {#s3k .step-kicker i18n=text}

现在只准用 P。把 Kp 从小往大扫一遍：**太小**——电机追不上重力，车慢慢倒给你看；**适中**——站是站住了，却来回摆个不停，看下方的 θ(t) 曲线，等幅的摆动不会自己停；**太大**——纠正快得发疯，高频狂抖。P 的毛病一句话：它只看「现在差多少」，不看「正在往哪儿倒、倒得有多快」，所以永远在过冲的两岸横跳。 {#s3e .explain}

::: html step3-1
s3kp: Kp
s3mSoft: 太软 Kp=8
s3mMid: 适中 Kp=20
s3mHard: 过硬 Kp=70
:::

本页模型没有摩擦，所以纯 P 的摆动是真的等幅、不衰减——不是画错了。真实小车上那点摩擦会让摆动慢慢收掉，但收得有多慢，取决于运气。 {#s3note .hint i18n=text}

::: strings
s3peak: 峰值倾角（近 3 秒）
:::

## D：提前刹车 {#step4 h2=s4t}

::: strings
nav4: 4 加上 D
:::

第 4 步 · 加上 D {#s4k .step-kicker i18n=text}

给控制器再装一只看趋势的眼睛：**D 项正比于倾角的变化率**——倒得越快，刹得越狠。下方曲线里，灰色虚线是只有 P 的老样子，青色实线是同一辆车、同一组 Kp、加上 Kd 之后。点「扰动一下」同时踢两辆车一脚，再拖动 Kd，看青线怎样在几秒内躺平。 {#s4e .explain}

::: html step4-1
s4kp: Kp（两辆车共用）
s4kd: Kd
s4disturb: 扰动一下（同时踢两辆车）
:::

Kd 也不是越大越好：它对「变化」太敏感，传感器稍微有点噪声就会被放大成抽搐——第 6 步会兑现这个伏笔。在这里先把 Kd 拉满试试：车身会变得神经质地僵硬，一有风吹草动就猛踩刹车。 {#s4note .hint i18n=text}

:::

## 站得稳，还要站得直 {#step5 h2=s5t}

::: strings
nav5: 5 I 与扰动
:::

第 5 步 · 加上 I 与扰动 {#s5k .step-kicker i18n=text}

把车开上斜坡：PD 能站住，却会永远**歪着一个固定的角度**——这叫稳态误差：P 的出力要靠「留一点误差」来维持，就像弹簧总得压着一点才有力。打开 **Ki**：它把误差一笔一笔记账，攒够了就把车多推一把，直到误差被吃光、车回到真正的竖直。但 Ki 太大（试着拉过 250）会矫枉过正：积分攒过了头，车身陷入慢悠悠的大幅摆动，停不下来。 {#s5e .explain}

::: html step5-1
s5slope: 坡度
s5kp: Kp
s5ki: Ki
s5kd: Kd
:::

实测预设（坡度 3° + 踢一脚的实测指标） {#s5presetT .stage-title i18n=text}

pBalanced: 均衡
pBalancedM: 峰值 5.2° · 约 2.6 s 收敛 · 误差 −0.1°

pSportM: 峰值 5.9° · 约 0.7 s 收敛 · 误差 −0.3°

三个预设不是拍脑袋写的：开发时用与本页完全相同的仿真逐个跑出来的，指标就写在按钮下面。随便改任意一个参数，预设的保证就作废——这正是调参的日常。 {#s5note .hint i18n=text}

::: html step5-3
s5formulaNote: 完整公式：u = Kp·e + Ki·∫e dt + Kd·de/dt，e = 目标角度 − 当前角度。积分项带防饱和钳制：电机顶到上限时，积分不会继续无脑累积。
:::

## 真实世界，专治调好的参数 {#step6 h2=s6t}

::: strings
nav6: 6 真实世界
:::

第 6 步 · 终章 {#s6k .step-kicker i18n=text}

第 5 步的参数已经调得很好了。现在把真实世界的三个坑一个一个打开——每一个，都专治「实验室里调好的参数」。 {#s6e .explain}

当前参数：均衡预设 {30, 6, 6}（平地） {#s6base .readout i18n=text}

::: html step6-1
s6delay: ① 传感器延迟
s6noise: ② 测量噪声
s6sat: ③ 电机推力上限
:::

信号晚到，控制器就永远在纠正「过去的姿势」：100 ms 出头开始自激振荡，150 ms 直接倒。这里的毫秒数是实打实的：延迟步数 × 仿真步长（1/480 秒）。工程解法：用模型做预测、给相位留裕度。 {#s6delayNote .hint}

角度读数毛毛糙糙，D 项第一个遭殃——它专盯变化，而噪声全是假变化：电机出力长满毛刺，车身高频细抖。工程解法：滤波，或者让 D 只看模型估计的变化率。 {#s6noiseNote .hint}

把推力上限拉到 4 附近再踢一脚：不是控制器算不出来，是电机给不出来——再聪明的算法也变不出力气。工程解法：留裕度；接近饱和时先停积分（防饱和）。 {#s6satNote .hint}

s6demo: 一键演示：随机推力下活 30 秒
:::

演示会先关掉三个坑，用均衡预设硬扛随机方向的推搡。 {#s6demoNote .hint i18n=text}
