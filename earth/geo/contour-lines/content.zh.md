## 纸是平的，山是立体的，一圈圈的线是怎么来的？ {#step0 h2=s0t}

::: strings
nav0: 0 切开的山
:::

第 0 步 · 切开的山 {#s0k .step-kicker i18n=text}

这一步要回答：地图上的等高线是怎样得到的？想象用一个水平的平面把山切开：切在海拔 H 的位置，切面和山表面相交的那一圈曲线上，每个点的海拔都正好是 H，这条线就是 **等高线**。每隔相同的高度切一刀，再从正上方往下看，就得到一圈圈的线。拖「切到多高」，上图是山的侧面，下图是正上方看到的地图，已经切过的等高线会留在图上。 {#s0e .explain}

::: html step0-1
s0stage: 上：山的剖面（侧面）和水平切面；下：从正上方看的地图，每隔 10 m 一条等高线；亮线是当前这一刀
s0canvas: 山的侧面剖面和对应的等高线地图：切面升高，一圈圈等高线依次出现
s0h: 切到多高
s0reset: 切面放回地面
:::

结论：同一条等高线上所有点的海拔相同；相邻两条线相差一个固定的「等高距」（这里 10 m）。条件：这是虚构的地形；真实地图的等高距按比例尺和地形选取（如 5、10、20 m）。 {#s0result .readout i18n=text}

::: strings
s0ro: 切面高度 {h} m：已经切出 {n} 条等高线（每隔 {iv} m 一条）；当前最高的一条在海拔 {top} m。
:::

## 等高线挤在一起的地方，为什么说坡陡？ {#step1 h2=s1t}

::: strings
nav1: 1 疏密看陡缓
:::

第 1 步 · 疏密看陡缓 {#s1k .step-kicker i18n=text}

这一步要回答：怎么从等高线的疏密看出坡有多陡？相邻两条等高线的海拔差固定（等高距 10 m），如果水平距离很短，说明在很短的水平距离里升了 10 m，坡就陡；水平距离很长，坡就缓。**坡度**是坡面与水平面的夹角。拖两个滑杆移动探测点，看箭头（上坡方向）、相邻两线的水平距离和坡度。 {#s1e .explain}

::: html step1-1
s1stage: 地图：橙点是探测点，箭头指向最陡的上坡方向，青色线段量出这里相邻两条等高线的水平距离
s1canvas: 一座山丘的等高线地图：探测点所在位置的上坡方向和相邻等高线间距
s1x: 探测点左右位置
s1y: 探测点上下位置
:::

结论：等高线越密，水平距离越短，坡越陡；等高线越疏，坡越缓。条件：用有限差分算坡度；地图宽 1000 m，高度是虚构的；等高线间距只在局部近似平行时成立。 {#s1result .readout i18n=text}

::: strings
s1ro: 探测点海拔 {z} m；相邻等高线（间隔 {iv} m）的水平距离约 {d} m，坡度约 {a}°（{kind}）。
s1gentle: 缓坡
s1mid: 中等坡
s1steep: 陡坡
s1flat: 几乎是平地，等高线间距极大
:::

## 等高距取大还是取小？小山包会不会被漏掉？ {#step2 h2=s2t}

::: strings
nav2: 2 间距与细节
:::

第 2 步 · 间距与细节 {#s2k .step-kicker i18n=text}

这一步要回答：等高距选得越大，地图上会丢掉什么？**等高距**是相邻两条等高线的海拔差。选一种地形，拖等高距：等高距小，线多，细节多，但图更密；等高距大，线少，图清爽，但低于一个等高距的起伏（比如小山包）就画不出来。 {#s2e .explain}

::: html step2-1
s2stage: 同一块地形用不同等高距画出：数字是整条线的海拔（米），每 5 条标一次
s2canvas: 所选地形的等高线图：等高距越大，等高线越少，小起伏消失
s2ter: 地形
s2iv: 等高距
:::

结论：等高距决定图能表达的最小起伏；越大越概括，越小越详细。条件：本页地形是虚构函数，用等距栅格近似画线，线条略有锯齿。 {#s2result .readout i18n=text}

::: strings
s2ro: {ter}：最高点约 {top} m，等高距 {iv} m，共画出 {n} 条等高线。{note}
s2lost: 提示：有一些小起伏（如小山包）低于一个等高距，可能已经从图上消失了。
s2ok: 提示：这个等高距下，主要地形都画得出来。
:::

## 把一滴水放在山坡上，它会沿什么方向流？ {#step3 h2=s3t}

::: strings
nav3: 3 水往哪流
:::

第 3 步 · 水往哪流 {#s3k .step-kicker i18n=text}

这一步要回答：水在地形上往哪个方向流，和等高线有什么几何关系？水总是沿**最陡的下坡方向**流，这个方向和等高线垂直。选一块地形，设好水滴的位置，按「放水」，看水滴走出来的路径怎样一路垂直穿过等高线，最后流到哪里。 {#s3e .explain}

::: html step3-1
s3stage: 地图：蓝点是水滴起点，蓝线是水流经过的路径（越走越长）；路径每一步都垂直于所在位置的等高线
s3canvas: 地图上的水流路径：垂直穿过等高线，从高处流向低处
s3ter: 地形
s3x: 水滴左右位置
s3y: 水滴上下位置
s3go: 放水
s3reset: 清除水流
:::

结论：水沿垂直于等高线的最陡下坡方向流，所以山脊线分开水流，山谷线汇集水流，盆地里水无处可去。条件：只看地形，不含土壤渗透和水量；用固定步长沿梯度下降的方向走。 {#s3result .readout i18n=text}

::: strings
s3ro0: 设好位置后按「放水」。
s3roEdge: 水流从海拔 {z0} m 一路下降到 {z1} m，流出了地图边界，路径总长约 {len} m。
s3roPit: 水流从海拔 {z0} m 下降到 {z1} m，停在一个低洼处（四周都更高），路径总长约 {len} m。
:::

## 沿着一条直线路线走，一共要爬多高？ {#step4 h2=s4t}

::: strings
nav4: 4 走一条路线
:::

第 4 步 · 走一条路线 {#s4k .step-kicker i18n=text}

这一步要回答：沿一条路线走，海拔怎么变化，累计要上坡多少米？起点固定在地图左侧中间，调方向和长度确定路线，剖面图把路线穿过每条等高线的位置依次点出来。拖「走到哪里」，看已走过的路程累计上坡和下坡。 {#s4e .explain}

::: html step4-1
s4stage: 上：地图和路线（橙线），圆点是目前走到的位置；下：路线的海拔剖面，黄点是每次穿过等高线的位置
s4canvas: 地图上的路线和对应的海拔剖面：每穿过一条等高线，剖面上就多一个点
s4th: 路线方向（0° 为向右，正为向下）
s4len: 路线长度
s4p: 走到哪里
:::

结论：剖面由路线与各条等高线的交点决定；累计上坡不等于终点和起点的海拔差，因为中间可能先上后下。条件：路线取直线并受地图边界截断；剖面用高密度采样近似。 {#s4result .readout i18n=text}

::: strings
s4ro: 路线长约 {len} m；已走 {p}%：海拔 {z} m；累计上坡 {up} m、下坡 {down} m；整条路线最高 {max} m、穿过 {n} 条等高线。
:::

## 把等高线说给别人听 {#step5 h2=s5t h2part=1}

::: strings
nav5: 5 收束
:::

::: html step5-1
s5k: 第 5 步 · 收束
s5e: 等高线是同一海拔的点连成的线：疏密看陡缓，数字看高低，垂直于它的方向是水流的方向。
f1t: 怎么来的
f1b: 水平面切山，切口俯视就是等高线，相邻两条差一个等高距（第 0 步）。
f2t: 怎么读
f2b: 密 = 陡，疏 = 缓；等高距决定能看到多小的起伏（第 1–2 步）。
f3t: 怎么用
f3b: 水垂直于等高线往低处流；路线穿过等高线的位置画出剖面（第 3–4 步）。
modelT: 模型实话
model1: 地形是虚构的光滑函数，不是真实山体；真实地图靠测量得到，有悬崖、陡坎等不连续的地方。
model2: 等高线用栅格线性插值画出，略有锯齿；水流用固定步长梯度下降近似。
model3: 地图宽度取 1000 m，高度取米；坡度分档（缓 < 5°、中 5–12°、陡 > 12°）是本页的教学约定。
nextT: 继续看（站内）
l1: 导数 · 第 0 步：坡度其实就是变化率，等高线越密变化越快
l2: 梯度下降 · 第 0 步：水沿最陡下坡方向走，和算法「沿梯度往下」是一回事
l3: 坐标系与点的位置 · 第 0 步：地图上用 (x, y) 定位，再加一个海拔就是三维位置
:::
